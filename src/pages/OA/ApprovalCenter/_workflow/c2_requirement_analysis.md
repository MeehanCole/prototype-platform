# OA 审批中心 V2 改造 — 新需求分析

> 阶段：Mode C C2 = A1 需求输入 + A2 需求分析
> 基线：V1 个人视角审批中心（已固化到 _versions/v1.tsx）
> 新需求：管理者视角——团队审批进度与效率监控

---

## Users（新增）

- **部门经理**：只看自己部门下所有成员的审批
- **公司管理员 / 运营**：可切换部门看全公司审批
- **HR / 财务**：按类型（请假 / 报销）看自己业务线相关的审批瓶颈

## Core Goal

当前 V1 是**纯个人视角**（我待办 / 我已办 / 抄送我 / 我发起），只能看到"自己的事"。管理者需要**团队视角**：看到部门成员一共提交了多少、哪些卡在哪个节点超时了、哪些成员待办堆积、平均处理效率是多少——让管理者能**主动干预超时/堆积**，而不是被动等问题升级。

## Constraints

- 复用 V1 的全部数据结构与 Element Plus 设计系统
- V1 个人视角 **必须保留**（通过版本切换 A/B 对比）
- 新增"团队视角"不要破坏 V1 已有信息架构——Tab 顺序、看板/列表双视图的基本结构尽量不变
- 新增数据来自部门维度聚合接口，前端不做复杂计算
- 权限：普通员工看不到"团队视角"Tab（原型为演示方便全显示，生产按权限隐藏）

## User Stories

- 作为**部门经理**，我想一进页面就看到本部门待办总数、超时数、平均处理时长，快速判断团队是否健康
- 作为**部门经理**，我想按成员查看每个人的待办堆积，知道谁压力大
- 作为**部门经理**，我想看到当前哪些审批在部门经理审批节点已经超时了，可以直接催办或转交给别人
- 作为**部门经理**，我想对某条下属的待办发起"催办"（给当前审批人发消息），推进进度
- 作为**部门经理**，我想在详情里看到该审批"已经在当前节点卡了 N 小时/天"的剩余时效可视化
- 作为**管理员**，我想切换部门，查看不同团队的审批效率对比

## Implicit Requirements（AI 补充）

- 个人视角和团队视角使用独立 Tab 切换，**不能让普通员工误看到他人的敏感金额信息**（权限强依赖）
- 团队视角下列表行增加"当前节点停留时长"字段，管理者一眼识别瓶颈
- 团队视角下"效率类"统计卡片使用同比/环比（本周 vs 上周）而不是简单绝对值
- 催办操作有冷却时间，防止滥用（1 条审批 1 小时内只能催办 1 次）
- 部门切换只对管理员可见；部门经理默认进入自己部门

## 用户路径

### 部门经理日常巡检
1. 打开审批中心 → 默认团队视角的"总览"统计
2. 一眼看到：本部门待办 18 / 超时 3 / 平均处理时长 1.2 天 / 本周通过 42
3. 超时卡片红色高亮，点进去 → 自动筛选到超时列表
4. 针对最紧急的 3 条，点击"催办"按钮 → Toast 提示"已通知当前审批人"
5. 切到"成员分布"卡片，发现成员 A 待办 9 条远超其他，点击成员筛选只看 A 的审批 → 决定把 2 条转交给 B 临时处理

### 管理员跨部门对比
1. 打开审批中心 → 切换到"团队视角"
2. 顶部部门下拉：默认 "全公司"
3. 切 "产品部" → 超时 2，平均 1.1 天
4. 切 "销售部" → 超时 6，平均 1.9 天
5. 打开销售部超时列表 → 发现 6 条中超 4 条都卡在同一节点（大区经理审批）→ 标记后联系大区经理

## MoSCoW 优先级

| 需求 | 优先级 | 理由 |
|---|---|---|
| 个人/团队 视角切换 Tab | **Must** | Mode C 的主轴，不加就没区分 |
| 团队总览统计卡片（待办/超时/平均时长/本周通过） | **Must** | 管理者"一眼健康度" |
| 团队视角下 审批列表（增加：当前审批人、节点停留时长） | **Must** | 识别瓶颈的核心数据 |
| 超时筛选 + 催办操作 | **Must** | 主动干预闭环 |
| 部门切换下拉（管理员） | **Should** | 多部门管理才需要，部门经理场景可省 |
| 成员维度分布卡片 | **Should** | 辅助发现"谁压了一堆"，列表排序也能看 |
| 转交操作 | **Should** | 转交涉及流程引擎，MVP 可先只催办 |
| 当前节点剩余时效可视化（时效进度条） | **Could** | 视觉增强，文字时长也能表达 |
| 部门对比效率排名表 | **Could** | 报表级，可独立看板页 |
| 审批 SLA 配置 | **Won't** | 本期 |

## Technical Feasibility

- **数据聚合**：团队视角统计需要部门维度聚合接口（待办/超时/平均时长/通过数）。接口未就绪前前端用 mock，和 V1 一样写死。风险：中
- **权限边界**：普通员工 vs 经理 vs 管理员的可见范围控制，纯前端做隐藏不够，后端必须按角色过滤。风险：中（生产环境必做）
- **催办接口**：催办需要调用消息通知（OA 站内信 + IM）。前端原型只做 Toast 反馈，真实接口后续对接。风险：低
- **转交能力**：转交涉及流程引擎"审批人变更"操作，需后端接口。MVP 先不做，列表里放占位按钮。风险：低
- **Element Plus 组件复用**：新增成员 Tag、时效进度条、部门下拉全是 EP 原生，无定制成本。风险：低

### 工时估算
- Must 项：2-3 人日
- Should 项：1-2 人日
- Could 项：1-2 人日
- 合计：4-7 人日（含联调）
