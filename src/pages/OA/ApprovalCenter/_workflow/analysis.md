# OA 审批中心 需求分析报告

> 阶段：A2 需求分析
> 输入：requirement.md

## Competitive Analysis

选取 5 款含审批中心 / 待办中心模块的同类产品对比核心功能差异。

| 产品 | 核心功能 | 差异点 | 可借鉴点 |
|------|---------|--------|---------|
| **钉钉** | 统一待办中心,按应用聚合,支持批量处理 | 待办以"应用来源"分组,顶部统计卡片 | 顶部统计卡片(待办数/超时数)、应用来源筛选 |
| **飞书** | 审批中心独立应用,Tab 切换待办/已办/抄送/发起 | 详情页内嵌审批流时间线,支持加签转交 | Tab + Badge、审批流时间线可视化 |
| **企业微信** | 审批入口在应用栏,列表 + 详情两级 | 列表行内快捷操作(同意/驳回下拉) | 行内快捷操作,减少跳转 |
| **泛微 e-cology** | 传统 OA 审批,流程引擎强,界面偏重 | 支持复杂条件路由、多分支并行审批 | 状态字段丰富(挂起/撤回/加签) |
| **致远 OA** | 表单驱动审批,强流程配置 | 待办支持按"紧急程度"排序 | 紧急标记 + 排序、超时高亮 |

**关键洞察**：
- 主流产品均采用 **Tab 分类（待办/已办/抄送/发起）** 作为信息架构主轴，验证了 requirement.md 中的用户故事
- 钉钉/飞书的 **顶部统计卡片** 能让用户快速感知待办压力，值得借鉴
- 行内快捷操作是高频审批场景的效率关键，企业微信做法最轻量

## User Journey

### 普通员工处理抄送审批（仅需知晓）
1. 进入审批中心 → 默认落在"待办"Tab
2. 切换到"抄送我"Tab → 看到抄送列表
3. 点击某条 → 查看详情与流转轨迹
4. 关闭详情,继续其他工作

### 审批人批量处理待办（高频）
1. 进入审批中心 → "待办"Tab 默认展示
2. 看到顶部统计:待办 12 / 超时 2 / 今日已处理 8
3. 用"审批类型"筛选 → 聚焦到"请假"类
4. 勾选多条同类待办 → 点击"批量同意"
5. 弹窗确认 → 输入审批意见 → 确认
6. Toast 成功 → 列表刷新,已处理项移出待办

### 员工查询发起的审批进度
1. 切换到"我发起的"Tab
2. 看到申请列表 + 当前节点 + 审批人
3. 对长时间未推进的,点击"催办"

## Requirement Priority (MoSCoW)

| 需求 | 优先级 | 理由 |
|------|--------|------|
| Tab 分类(待办/已办/抄送/发起) | **Must** | 信息架构主轴,所有竞品标配 |
| 审批列表展示(标题/类型/发起人/时间/状态) | **Must** | 核心数据呈现 |
| 待办 Tab Badge 数量 | **Must** | 用户感知待办压力的入口 |
| 审批详情 + 流转时间线 | **Must** | 决策前必须看完整轨迹 |
| 待办同意/驳回操作 | **Must** | 核心动作 |
| 顶部统计卡片(待办/超时/今日已处理) | **Should** | 钉钉式增强体验,非阻塞 |
| 审批类型/状态/时间筛选 | **Should** | 数据量大时必需,小量可缓 |
| 行内快捷同意/驳回 | **Should** | 提升高频效率,但需防误操作 |
| 紧急标记 + 置顶 | **Should** | 致远 OA 经验,提升时效 |
| 批量处理 | **Could** | 高峰期提效,非日常必需 |
| 超时高亮提醒 | **Could** | 视觉增强,可二期 |
| 催办功能 | **Could** | 依赖后端推送能力,可缓 |
| 转交/加签 | **Won't**(本期) | 流程引擎复杂度高,独立迭代 |
| 审批流模板配置 | **Won't**(本期) | 已在 Out of Scope |

## Technical Feasibility

### 技术风险
- **多业务系统数据聚合**：审批数据来自报销/请假/采购等不同系统,字段结构不一。需后端提供统一聚合接口,前端不直接对接多源。**风险:中** —— 取决于后端接口就绪时间
- **批量操作幂等性**：批量同意可能因网络抖动部分成功。需前端处理"部分成功"反馈。**风险:低**
- **流转时间线渲染**：复杂分支并行审批的轨迹可视化较复杂。本期按线性时间线展示即可。**风险:低**

### 依赖项
- 后端审批聚合接口(待提供 OpenAPI)
- 用户身份与权限上下文(沿用现有 OA 登录态)
- Element Plus 组件库(Table / Tabs / Tag / Dialog / Badge)

### 技术选型确认
- 列表:ElTable(默认 stripe + border,headerBg #fafafa,符合 Element Plus preset)
- 分类:ElTabs + ElBadge
- 状态:ElTag(success/warning/danger/info 配色)
- 详情:ElDialog + 自定义 Timeline
- 筛选:ElSelect + ElDatePicker
- 批量:ElTable selection + ElButton

### 工时估算(参考)
- Must 项:3-4 人日
- Should 项:2-3 人日
- Could 项:2 人日
- 合计:7-9 人日(含联调)
