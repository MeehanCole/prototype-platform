# OA 审批中心 需求清单

> 阶段：A1 需求输入
> 场景假设：企业内部 OA 系统新增"审批中心"模块，统一聚合各业务线审批事项

## Users

- **普通员工**：发起审批申请，查看自己提交的申请进度，处理抄送给自己的审批
- **审批人**（部门经理 / 财务 / HR 等）：处理待审批事项，同意 / 驳回 / 转交
- **管理员**：查看全部审批流水，配置审批流模板，处理异常挂起

## Core Goal

为企业员工提供统一的审批事项处理入口，将分散在报销、请假、采购、用印等各业务系统中的审批任务聚合到一个中心化工作台，让用户在一个页面内完成"待办处理 + 进度查询 + 历史追溯"，降低跨系统切换成本，提升审批时效。

## Constraints

- 技术栈：Vue3 + Element Plus（目标产品已有技术栈）
- 设计系统：Element Plus 预设
- 须对接现有 OA 后端，审批数据来自多业务系统聚合
- 移动端适配优先级低（主要在 PC 端使用）
- 单页数据量大，需考虑分页与虚拟滚动

## User Stories

- 作为**普通员工**，我想在一个页面看到我所有待处理的审批事项，这样我就不用逐个业务系统去找
- 作为**普通员工**，我想按"待办 / 已办 / 抄送我 / 我发起的"切换查看，这样能区分需要我处理和仅需知晓的事项
- 作为**审批人**，我想在列表里直接同意 / 驳回简单事项，这样不用每个都点进详情
- 作为**审批人**，我想批量处理同类审批，这样能提升高峰期处理效率
- 作为**普通员工**，我想看到每个审批的当前流转节点和审批人，这样我能预判进度
- 作为**管理员**，我想按审批类型 / 状态 / 时间筛选，这样能快速定位异常挂起的流程

## Implicit Requirements（AI 补充的隐性需求）

- 待办数量需在 Tab 上以 Badge 形式展示，让用户一眼看到待处理量
- 审批列表需支持"紧急"标记，高优先级事项置顶或高亮
- 长时间未处理的待办需有超时提醒机制（列表视觉提示）
- 审批详情需展示完整审批流转轨迹（时间线形式）
- 操作后需即时反馈（成功 Toast + 列表状态刷新）

## Out of Scope

- 审批流模板的可视化配置（后续独立页面）
- 移动端审批处理（本期仅 PC）
- 审批数据的统计分析报表（后续独立看板）
