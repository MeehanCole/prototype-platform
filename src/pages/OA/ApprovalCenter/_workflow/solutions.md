# OA 审批中心 方案设计

> 阶段：A3 方案设计
> 输入：analysis.md
> ⚠️ 本阶段为人工决策点,AI 生成 3 个候选方案,最终方案需由用户确认

## 背景

企业 OA 系统新增审批中心,需将多业务系统审批事项聚合到统一工作台。需求 Must 项为 Tab 分类 + 列表 + 详情 + 同意/驳回操作,Should 项含统计卡片、筛选、行内快捷操作、紧急标记。目标技术栈 Vue3 + Element Plus。

三个候选方案在**详情承载方式**与**信息架构密度**上做出不同取舍。

---

## 方案 1: 经典列表 + 弹窗详情（企业微信式）

**核心思路**：
Tab 分类 + 表格列表为主,点击行弹出 Dialog 展示详情与流转时间线。最传统稳健,Element Plus 原生组件全覆盖,学习成本最低。

**交互流程**：
1. 进入页面 → 默认"待办"Tab,顶部统计卡片(待办/超时/今日已处理)
2. 表格展示:标题 / 审批类型 / 发起人 / 提交时间 / 当前节点 / 状态 / 操作
3. 点击行 → ElDialog 弹出详情(申请表单 + 流转时间线 + 审批意见输入)
4. 待办 Tab 行内"操作"列含快捷【同意】【驳回】按钮,点击弹小确认框
5. 勾选多行 + 顶部【批量同意】按钮
6. 操作后 Toast + 列表刷新

**优点**：
- Element Plus 组件 100% 原生,无定制成本
- 详情弹窗信息承载量大,适合复杂表单
- 列表全宽,信息密度高,适合大量数据
- 学习成本最低,用户对表格+弹窗模式零认知负担

**缺点**：
- 每次看详情都弹窗,高频审批时反复开关体验略重
- 弹窗遮挡列表,无法边看详情边操作其他项
- 行内快捷操作需防误触(同意/驳回紧邻)

**开发成本**：低,预估 5-6 人日
**风险**：低

---

## 方案 2: 列表 + 右侧抽屉详情（飞书式）

**核心思路**：
Tab 分类 + 表格列表为主,点击行从右侧滑出 Drawer 展示详情。详情不遮挡列表,可边看详情边切换其他审批项,适合高频连续审批。

**交互流程**：
1. 进入页面 → 默认"待办"Tab,顶部统计卡片
2. 表格展示同方案 1
3. 点击行 → 右侧 ElDrawer(宽度 480px)滑出详情
4. 详情内含审批意见输入 + 【同意】【驳回】【转交】操作
5. 抽屉打开时列表仍可见,可点击其他行切换详情内容(抽屉内容替换)
6. 勾选多行 + 顶部【批量同意】
7. 操作后 Toast + 列表刷新 + 抽屉内容同步更新

**优点**：
- 详情不遮挡列表,连续审批效率最高
- 视觉上"主从"结构清晰,符合工作台心智
- 抽屉可容纳较丰富的详情(含时间线)
- 飞书验证过的成熟交互模式

**缺点**：
- 抽屉占 480px,列表可视宽度收窄,小屏体验下降
- 抽屉内表单复杂度受限(超长表单仍需弹窗)
- 需处理"抽屉打开时列表点击"的切换逻辑
- 批量操作时抽屉与列表选中态需协调

**开发成本**：中,预估 6-7 人日
**风险**：低-中(交互细节较多)

---

## 方案 3: 统计看板 + 列表双视图（钉钉式）

**核心思路**：
顶部强化统计看板(待办/超时/今日已处理/本周完成,含趋势小图),下方列表支持"看板视图/列表视图"切换。看板视图按审批类型分列(类似看板),列表视图回归传统表格。信息架构最丰富。

**交互流程**：
1. 进入页面 → 顶部 4 个统计卡片(含数字 + 小趋势图)
2. 卡片下方视图切换器【看板】【列表】
3. 看板视图:按审批类型(请假/报销/采购)分列,每列卡片堆叠,拖动可跨列(模拟流转)
4. 列表视图:传统表格,同方案 1
5. 点击卡片/行 → 弹窗或抽屉详情
6. 操作后对应卡片/行状态更新,统计卡片数字联动

**优点**：
- 统计看板让管理者一眼掌握全局,符合"中心"定位
- 看板视图直观展示各类型待办分布
- 双视图满足不同角色(执行者用列表,管理者用看板)
- 视觉冲击力最强,演示效果好

**缺点**：
- 开发成本最高,看板视图需额外实现拖拽与列管理
- 看板视图对大量数据(单列 50+)体验差
- 双视图维护两套交互,测试成本翻倍
- 统计卡片趋势图依赖后端聚合接口,接口未就绪则降级
- 偏离 Element Plus 原生模式,定制组件多

**开发成本**：高,预估 9-11 人日
**风险**：中(看板拖拽 + 统计接口依赖)

## 对比矩阵

| 维度 | 方案 1 列表+弹窗 | 方案 2 列表+抽屉 | 方案 3 看板+列表 |
|------|------------------|------------------|------------------|
| 用户体验(高频审批) | 中(反复弹窗) | **高(不遮挡列表)** | 中-高(双视图灵活) |
| 用户体验(管理全局) | 低 | 低 | **高(统计看板)** |
| 开发成本 | **低(5-6 人日)** | 中(6-7 人日) | 高(9-11 人日) |
| 技术风险 | **低** | 低-中 | 中 |
| Element Plus 贴合度 | **高(全原生)** | 高(Drawer 原生) | 中(看板需定制) |
| 扩展性 | 中 | 中 | **高(看板可演进)** |
| 用户学习成本 | **低** | 低 | 中(双视图) |
| 信息密度 | **高** | 中(列表收窄) | 中 |
| 演示/汇报效果 | 中 | 中 | **高** |

## AI 建议（仅供参考,最终决策由人完成）

基于对比矩阵分析:

- 若**优先效率与稳健**,选**方案 1**:开发成本最低,Element Plus 原生全覆盖,1 期内可交付 Must+Should 全量。适合"先跑起来再优化"的节奏。
- 若**优先高频审批体验**,选**方案 2**:抽屉不遮挡列表,审批人连续处理效率最高。开发成本仅比方案 1 多 1 人日,性价比高。
- 若**优先管理视角与演示效果**,选**方案 3**:统计看板 + 双视图视觉冲击强,但开发成本与风险显著上升,且看板视图对大数据量不友好。

**综合建议**:倾向**方案 2**。理由:审批中心的核心高频场景是"审批人连续处理待办",抽屉模式在此场景体验最优,而开发成本与方案 1 接近,Element Plus 原生 Drawer 即可实现。方案 3 的统计看板可作为后续迭代增强,不必本期承担。
