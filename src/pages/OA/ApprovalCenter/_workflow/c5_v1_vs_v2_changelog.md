# V1 → V2 功能变更清单 Changelog（测试验收专用）

> 文件位置：`_workflow/c5_v1_vs_v2_changelog.md`
> 关联版本：V1 = 个人视角纯审批中心（_versions/v1.tsx）/ V2 = 个人 + 团队双视角（_versions/v2.tsx）
> 对应原型标注系统：**左上角版本下拉切 V1/V2 对比；右上角「显示新增功能点」开关（V2 才出现）打开后所有改动点均有编号角标，与本表编号一一对应，hover 角标可看该功能点说明**

## 1. Restructure（信息架构重构，紫色角标 A）

### A.01 顶层 Tab：单层 → 双层视角架构
- **V1 行为**：顶部 4 个 Tab（待办 / 已办 / 抄送我 / 我发起的），纯个人视角
- **V2 行为**：顶层改为「**视角（个人 / 团队）** → 子 Tab（个人 4 个保持不变；团队新增 4 个子 Tab：总览 / 团队待办 / 成员分布 / 效率排行）」
- **验收点**：
  - [x] 顶部出现双视角切换 Tab，团队视角 Tab 旁有 NEW 角标
  - [x] 个人视角下 V1 所有功能（4 子 Tab + 看板 / 列表 + 批量同意 + 详情弹窗 同意/驳回）**完全保持 V1 行为，无回归**
  - [x] 切到团队视角后出现团队专属筛选项 + 4 个新子 Tab
- **关联编号**：本清单所有 B.* 新增仅在团队视角可见

## 2. Add（新增功能，绿色角标 B）

### B.01 团队视角 · 顶部统计 4 张卡（替换个人版卡片）
**仅团队视角显示**，可点击跳转对应子 Tab。
| 卡片 | 说明 | 验收点 |
|---|---|---|
| 部门待办总数 | 统计该筛选条件下 pending/processing 的审批数，有较昨日趋势 | 筛选条件变化时数字实时变 |
| 超时未处理（⚠ 点了催办） | **点击直接催办当前所有超时项**；显示数量 | 点卡片 → Toast「已催办当前审批人」弹出；**B.04 右栏有同样入口** |
| 平均处理时长 | 该筛选条件下所有审批的平均停留时长，同比上周 -6h | |
| 本周通过 | 部门本周处理通过总数，周进度条 72% | |
- **验收点**：[x] 4 张卡全部有虚线框高亮标注 + NEW 角标（开开关时）

### B.02 团队视角子 Tab 4 个
| Tab 名 | 对应功能 | 编号 |
|---|---|---|
| 总览 | 成员待办分布 + TOP6 + 类型进度条 + 快捷操作 | B.03 / B.04 |
| 团队待办 | 核心干预视图：列表 3 列新增 + 行操作改催办/转交，看板分组改节点 | B.05 / M.03 |
| 成员分布 | 每人一列看板：待办+超时数 + 卡片堆叠 | B.06 |
| 效率排行 | 金银铜牌排名、处理数、SLA 平均时长、超时数、对比条 | B.07 |

### B.03 总览 · 成员待办分布条（点成员跳对应看板）
- 每个成员一行：姓名 + 进度条（占比）+ 待办数字 + 超时红 tag
- **点击任意成员行 → 联动效果**：顶部「成员」筛选 = 该成员 + 自动切到 **成员分布** 子 Tab（方便管理者盯着一个人处理）
- 验收点：[x] 点击后地址/状态正确联动；[x] 进度条比例按 Math.max 正常计算不超 100%

### B.04 总览 · 右侧类型分布 + 管理者快捷操作 3 个
| 快捷操作按钮 | 验收点 |
|---|---|
| 处理超时审批 (N 项) | 点 → 切团队待办 Tab + 自动打勾「仅看超时」筛选（= **M.02** 打开） |
| 查看成员效率排行 | 点 → 切效率排行 Tab |
| 按成员查看分布看板 | 点 → 切成员分布 Tab |

### B.05 团队待办列表视图（核心验收项，和 V1 差异最大）
**对比 V1 列表：新增 3 列 + 行操作换按钮 + 批量入口占位**
| 差异项 | V1 列表 | V2 团队待办列表 | 验收 |
|---|---|---|---|
| 复选框 | 每列有，用于批量同意 | **无复选框列**（管理者不做决策操作，不支持批量通过/驳回） | 团队视角确实没有左边 check 列 |
| 新增列 1 — | 不存在 | **发起人 / 部门** | Table header 有 B.05 NEW tag，每条有对应数据 |
| 新增列 2 — | 不存在 | **当前审批人** | 同上 |
| 新增列 3 — | 不存在 | **节点停留**（≥24h 红色 + 加粗） | 同上 |
| 行操作 | 同意 / 驳回 / 详情 | **催办（可用，主按钮，蓝）+ 转交（disabled，灰「即将上线」）+ 详情** | 点催办 → 弹详情弹窗有催办按钮 |
| 批量入口（底栏选中态） | 「已选 N 项」+「批量同意」 | **底栏提示「新增 · B.05 批量催办/转交入口(待接入)」**（开开关时才显示，避免干扰演示） | 选中团队待办里任意 N 条（因没 check，需要代码侧手动验证？）；底栏确实出现占位提示 |

### B.06 成员分布看板
- 按成员分列（支持最多 6 列：陈晨/林芳/赵磊/孙悦/周凯/吴敏），每列头部：姓名 + 待办/超时
- 每张 KanbanCard 显示「停留 Xh Ym」extraInfo（B.05 列表的停留信息一致）
- 验收点：[x] 顶部筛选「成员 = 全公司」时 6 列全出；筛选某个成员 → 只有该成员一列；[x] 每列卡片数 + 头部数字一致

### B.07 效率排行表
6 条记录（6 个成员），金银铜牌排名前 3：
| 列 | 验收 |
|---|---|
| 排名 1-3 | 金=黄 / 银=灰 / 铜=橙 背景圆徽章 |
| 本周处理 | 最多者进度条满 100% |
| 平均时长 | ＞ 24h 的字段变红（例如：陈晨 14h / 周凯 36h 红 / 吴敏 48h 红） |
| 超时数 | 0 → 绿色「0」；非 0 → 红 tag 显示具体数字（周凯 2，吴敏 5） |
| 对比条 | 按本周处理 / 最大值 = 百分比宽度，第一名满 |

### B.08 右上角「显示新增功能点」开关（本交付物本身）
- **V2 才出现，V1 页面不显示**
- 状态存在 `localStorage` 的 `ac_v2_showfeat`（on / off），刷新保留
- 验收点：
  - [x] 默认勾选，所有编号角标 / 高亮外框 / 底栏提示 均显示
  - [x] 取消勾选 → **所有角标/高亮/底栏提示瞬间消失**，原型纯净适合客户演示，刷新仍然保持关闭
  - [x] 切 V1 → 开关消失（V1 没新增功能所以没必要）

## 3. Modify（修改/增强，橙色角标 M）

### M.01 团队顶部筛选：新增「部门」下拉
- **仅团队视角显示**，个人视角不显示
- 可选值：全公司 / 研发部 / 产品部 / 市场部 / 运营部 / 财务部 / 人事部
- 联动：筛选变化 → 团队统计卡 B.01 + 所有 4 个子 Tab 数字一起变

### M.02 团队顶部筛选：新增「仅看超时」checkbox
- 仅团队视角
- **联动 B.04 第一个快捷操作「处理超时审批」**：点按钮 = 自动勾上这个 + 切团队待办 Tab
- 验收点：两种路径打开结果一致（直接勾 vs 通过快捷入口点）

### M.03 团队待办看板：分组维度从「按类型」→「按当前节点」
- V1 看板 4 列按类型（请假/报销/采购/用印）分组 —— 对个人处理人合理
- V2 **团队视角看板** 改成按当前节点分列（例如：部门主管审批、部门经理审批、财务复核、总经理审批）—— 对管理者合理，一眼看哪个环节堆积
- 验收点：团队视角看板列头是「部门主管审批/部门经理审批/财务复核/总经理审批/归档」节点名，**不是类型名**
- 关联：个人视角看板仍然保持「按类型」V1 行为（不回归）

### M.04 详情弹窗 · 团队模式信息增强 + SLA 警告条
**仅 teamMode=true 时生效，个人模式保持 V1 完全一致（不回归）。**
| 改动点 | 验收 |
|---|---|
| 新增字段 1：当前审批人（申请信息 section） | 团队模式有「当前审批人:xxx」字段；个人模式没有 |
| 新增字段 2：节点停留（申请信息 section） | 团队模式有；≥24h 红色加粗；**M.05 催办操作的判断依据** |
| SLA 警告条（停留≥24h 才显示） | **顶部橙色 WARNING 条**，带虚线 M.04 外框（开关开时）：「⚠ 当前节点【xxx】已停留 Xh Ym，超过 SLA(24h)，建议催办」 |
| 顶部 header tag：发起人/部门 | 团队模式标题旁出现 tag（V1 无） |

### M.05 详情弹窗 · 底部操作按钮：决策按钮 → 推进按钮
| 模式 | 按钮组（从左到右） |
|---|---|
| V1 个人模式（保持不变） | 取消 / 驳回（红）/ 同意（蓝主按钮） |
| V2 团队模式（**新增**） | 取消 / 转交（灰，disabled，hover 显示「转交能力即将上线，敬请期待」tooltip）/ **催办（蓝主按钮）** |

- 验收点：
  - [x] 团队模式下「同意/驳回」按钮消失（管理者不直接做决策）
  - [x] 转交按钮是 disabled，cursor:not-allowed，有 tooltip「转交即将上线」或「转交能力即将上线，敬请期待」
  - [x] 点**催办** → 关闭弹窗 + Toast「已催办当前审批人」
  - [x] 个人模式仍然是「同意 / 驳回」，完全无回归

## 4. Remove / Restructure 的「不回归项」（必测，勿漏）

虽然编号在 A.01 已经提过，这里再列一遍测试员容易漏的「不要回归」：

| 功能 | V1 行为 | 验收人确认 |
|---|---|---|
| 个人视角 4 个子 Tab 计数徽标 | 待办 5 / 已办 23 / 抄送 8 / 我的 12 | ☐ 数字正确 |
| 个人视角列表批量同意 | 选 N 条 → 底栏「批量同意」按钮 | ☐ 按钮 + 弹 Toast |
| 个人看板类型 4 列 | 请假/报销/采购/用印 | ☐ 不是节点 |
| 详情弹窗个人模式底部 | 同意/驳回，不是催办 | ☐ 按钮正确 |
| 全局 Toast 机制 | 任意操作后消失 < 3s | ☐ 不常驻 |
| 版本下拉 V1 / V2 切换 | 切 V1 完全没有双视角 Tab、没有团队筛选、没有开关 | ☐ 版本隔离干净 |
| 筛选 → 数字联动（全局） | 类型筛选、状态筛选在 V1/V2、个人/团队下都生效 | ☐ 不出现筛选了数据不变 |
