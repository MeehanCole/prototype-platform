# 审批中心 PRD

## Business Context

**Target product**: 企业 OA 系统
**Target tech stack**: Vue3 + Element Plus
**Design system**: Element Plus(蓝色 #409eff,4px 圆角,stripe 表格,headerBg #fafafa)
**Entry point**: OA 系统 > 工作台 > 审批中心
**Related existing pages**: 工作台首页、各业务系统申请页(报销/请假/采购/用印)、通知中心
**Navigation context**: 现有 OA 左侧导航含"工作台""通讯录""应用中心",审批中心作为"工作台"下二级入口新增

## Feature Overview

审批中心是企业 OA 系统的统一审批工作台,将分散在报销、请假、采购、用印等各业务系统中的审批任务聚合到一个中心化页面。采用"统计看板 + 双视图(看板/列表)"钉钉式信息架构,让员工在一个页面内完成待办处理、进度查询、历史追溯,管理者可全局掌握审批压力与时效。

## Functional Requirements

### 顶部统计看板

| 指标 | 数据来源 | 说明 |
|------|---------|------|
| 待办事项数 | 审批聚合接口(待我审批) | 当前用户待处理审批总数,含趋势小图(近 7 天) |
| 超时未处理数 | 审批聚合接口(超时标记) | 超过 SLA 时效的待办数,需尽快处理 |
| 今日已处理数 | 审批聚合接口(今日已办) | 当日 0 点至今已审批数,含趋势小图 |
| 本周已完成数 | 审批聚合接口(本周已办) | 本周一至今已完成数 + 本周进度百分比 |

### Tab 分类(信息架构主轴)

| Tab | 数据范围 | Badge |
|-----|---------|-------|
| 待办 | 当前用户作为审批人且状态为待审批/审批中 | 显示数量,主色 |
| 已办 | 当前用户已处理的审批记录 | 显示数量,灰色 |
| 抄送我 | 抄送给当前用户的审批(仅知晓,无需操作) | 显示数量,灰色 |
| 我发起的 | 当前用户发起的审批申请及进度 | 显示数量,灰色 |

### 视图切换

| 视图 | 适用场景 | 呈现方式 |
|------|---------|---------|
| 看板视图(默认) | 管理全局、按类型分布概览 | 按审批类型(请假/报销/采购/用印)分 4 列,卡片堆叠 |
| 列表视图 | 高效逐条处理、批量操作 | 表格(标题/类型/发起人/提交时间/当前节点/状态/操作),支持勾选+分页 |

### 看板视图

| 区域 | 功能 | 数据来源 | 说明 |
|------|------|---------|------|

| 卡片 | 审批摘要 | 单条审批数据 | 标题+事由+发起人+时间,紧急标记,超时提示 |
| 卡片交互 | 点击打开详情 | - | 弹出详情弹窗 |
| 滚动 | 单列超过 N 张 | - | 列内纵向滚动,不撑高页面 |

### 列表视图

| 列 | 数据 | 说明 |
|----|------|------|
| 勾选 | - | 支持全选/单选,用于批量操作 |
| 标题 | 审批标题 | 紧急项前置红点,点击可打开详情 |
| 类型 | 审批类型 | 色标 Tag(请假蓝/报销绿/采购橙/用印紫) |
| 发起人 | 申请人姓名 | - |
| 提交时间 | 申请提交时间 | tabular-nums 等宽 |
| 当前节点 | 流转当前位置 | 主色文本 |

### 详情弹窗

| 区域 | 内容 | 说明 |
|------|------|------|
| 头部 | 标题 + 状态 + 紧急标记 | - |

| 审批轨迹 | 时间线:发起→各节点→当前→后续 | 已完成(绿点)/当前(主色+环)/待处理(灰点),含审批人与意见 |
| 审批意见 | 文本输入框 | 可选,驳回时建议必填 |
| 操作 | 取消/驳回/同意 | 同意主色按钮,驳回警示色按钮 |

### 筛选

| 筛选项 | 选项 | 联动 |
|--------|------|------|
| 审批类型 | 全部/请假/报销/采购/用印 | 作用于看板+列表 |
| 审批状态 | 全部/待审批/审批中/已通过/已驳回 | 作用于列表(看板按类型分组) |

| 操作 | 触发条件 | 行为 |

## Interaction Flow

### 审批人批量处理待办(高频主流程)
1. 进入审批中心,默认"待办"Tab,顶部统计看板显示待办 5 / 超时 2
2. 切换到"列表视图",用"审批类型"筛选聚焦到"请假"
3. 勾选多条请假待办,顶部出现"已选 N 项"+【批量同意】按钮
4. 点击【批量同意】,Toast 提示"已批量同意 N 项审批"
5. 列表刷新,已处理项移出待办,统计卡片数字联动更新

### 审批人查看详情并处理单条
1. 在看板视图点击某张卡片 → 弹出详情弹窗
2. 查看申请信息 + 审批轨迹(已到部门经理节点)
3. 输入审批意见(可选)
4. 点击【同意】→ Toast 成功 → 弹窗关闭 → 列表移除该项

### 员工查询发起的审批进度
1. 切换到"我发起的"Tab
2. 看板/列表查看各申请当前节点与审批人
3. 点击卡片/行打开详情,查看完整审批轨迹预判进度

## Edge Cases

- **空状态**:某 Tab 或筛选下无数据时,展示圆形图标 + "暂无审批事项" + 辅助说明文案
- **加载状态**:首次进入或切换 Tab 时,列表区展示 4 行骨架屏(animate-pulse 灰色色块)
- **错误状态**:接口失败时 Toast 提示"加载失败,请重试",保留上次数据(原型层面用静态数据演示)
- **超时项**:卡片底部展示橙色提示条;列表状态列附加"超时"文字标记
- **紧急项**:卡片标题区红色"紧急"标;列表标题前红色圆点
- **超长文本**:卡片事由 line-clamp-1 截断;列表标题不换行
- **批量部分成功**:Toast 明确提示"已批量同意 N 项"(原型简化,生产环境需区分部分失败)
- **详情弹窗滚动**:内容超过 85vh 时弹窗内部滚动,头部/底部固定
- **误触防护**:列表行内同意/驳回直接打开详情弹窗,在弹窗内二次确认操作,避免误触

## Design Intent

- **为什么顶部统计看板**:审批中心定位为"统一工作台",管理者需一眼掌握全局审批压力(待办/超时/今日已处理/本周完成),看板比纯列表更符合"中心"定位。借鉴钉钉经验。
- **为什么默认看板视图**:审批类型固定为 4 类(请假/报销/采购/用印),看板按类型分列能直观展示分布,管理视角友好;执行者可一键切列表视图高效处理。
- **为什么保留列表视图**:看板视图对大数据量(单列 50+)体验差,批量操作也需勾选,列表视图是高频处理与批量的必要补充,双视图覆盖管理与执行两类角色。
- **为什么详情用弹窗而非抽屉**:方案 3 已含双视图,信息密度高,弹窗承载量更大,适合含时间线的复杂详情;抽屉会挤压看板/列表可视宽度。这是方案决策(见 _workflow/decision.md)的取舍结果。
- **为什么 Tab 用 Badge**:用户进入页面第一眼即可感知待办压力,主色 Badge 视觉锚点强,降低漏处理风险。

## Data Flow

- **待办列表**:前端请求审批聚合接口(待我审批,按状态) → 后端聚合多业务系统数据 → 返回统一结构 JSON → 前端按 Tab/筛选渲染
- **统计卡片**:前端请求审批统计接口(按时间维度) → 后端返回 4 项指标 + 趋势序列 → 前端渲染数字 + sparkline
- **审批操作**:前端 POST 审批接口(action: approve/reject, opinion) → 后端推进流程引擎 → 返回成功 → 前端 Toast + 刷新列表 + 更新统计
- **批量操作**:前端 POST 批量审批接口(ids: [], action: approve) → 后端逐条处理 → 返回成功数/失败数 → 前端 Toast 反馈
- **审批轨迹**:前端请求单条审批的流转记录 → 后端返回节点列表 → 前端渲染时间线
