# PRD V2 — OA 审批中心(个人视角 + 团队视角双轨制)

> 版本: V2
> 前置版本: V1(纯个人视角审批中心,保留为 A/B 对比基线,见 [prd_v1.md](./prd_v1.md))
> 工作流: Mode C 混合设计 — 在 V1 成熟产品基础上,增量叠加团队管理者新需求
> 产物目录: `_workflow/` 下 C1-C5 完整记录

## 1. 业务上下文

### 1.1 背景
V1 版本审批中心上线后,覆盖了**普通员工**(处理自己的待办/已办/抄送/发起)**和个人视角的使用场景。产品收到的高频反馈来自部门经理和管理员:
- "我想看整个**部门**一共有多少审批卡在哪了,但现在只能一件一件查,效率太低"
- "我想知道哪些成员手上**积压了一堆,需要我帮忙协调?"
- "某条审批卡住好几天了,有没有办法**主动催办**而不是等它自己走完流程?"

### 1.2 问题 V1 无法解决
1. **不可见**:管理者看不到部门审批的**整体健康度**,只能在"我发起的"里看自己提交的
2. **不可干预**:发现卡住也无法从管理者侧**催办或转交**,只能私下打电话
3. **不可衡量**:团队审批效率**没有任何度量**(平均处理时长、超时率、成员排名),无法做资源分配
4. **不可切换**:多部门管理场景,管理员**看不到部门间的对比**

### 1.3 商业目标(V2 → 增量价值)
| 指标 | 目标 | 度量方式 |
|---|---|---|
| 部门审批平均处理时长 | 缩短 30% | 节点停留时长统计 vs V1 基线 |
| 超时审批数 | 周环比下降 50% | SLA 未达标数量 |
| 管理者催办使用率 | 每周 >= 10 次 | 催办接口调用次数 |
| 管理员月活 | 提升 2x | 管理员角色登录并访问团队视角 PV |

### 1.4 用户角色
- **普通员工** — V1 个人视角,无变化,V2 个人 Tab 保持 1:1 一致
- **部门经理** — 新增使用者,核心操作:总览巡检、超时催办、成员积压识别
- **公司管理员 / 运营** — 部门切换、跨部门对比、效率排行做资源分配
- **HR / 财务 / 法务 职能线** — 按类型(请假/报销)看本线相关审批瓶颈

## 2. 需求范围(V2 增量改动)

### 2.1 V1 现有功能 **(无变更,简版,完整见 prd_v1.md)**
1. 顶部筛选:审批类型 / 状态下拉
2. 统计卡:待办 / 超时 / 今日已处理 / 本周完成 4 张卡
3. 个人 4 Tab:待办 / 已办 / 抄送我 / 我发起的
4. 双视图切换:看板视图(按审批类型分列) / 列表视图(表格)
5. 批量操作:列表视图待办 Tab 支持批量同意
6. 详情弹窗:申请信息 + 审批时间线 + 意见输入 + 同意/驳回
7. Toast 反馈、空状态、分页

### 2.2 V2 新增功能 **(详)**
按 C3 改造方案分类:
- Restructure: 1 项(顶层 Tab 重构成视角+子 Tab 两层)
- Modify: 6 项(筛选、统计卡、分组、操作按钮、弹窗、meta 版本)
- Add: 5 项(团队 4 子 Tab + 催办/转交)
- Remove: 0 项(最小改动原则,不删任何功能)

### 2.3 功能需求详单

**FR-1 视角切换(Restructure,顶层 Tab 必做)**
| 项目 | 说明 |
|---|---|
| 描述 | 页面最顶部显示「个人视角」/「团队视角」切换 Tab,默认进入用户上一次访问的视角(首次登录按角色:普通员工→个人,经理→团队) |
| 业务规则 | 1) 普通员工登录 = 只显示「个人视角」,团队 Tab 不可见。2) 经理/管理员 = 两个 Tab 都可见。3) 个人视角子 Tab 行为与 V1 1:1 一致,零学习成本 |
| 权限控制 | 前后端双校验。前端按角色条件渲染,后端按登录人角色过滤接口数据 |
| 交互 | 切换视角时,保留各自视角内的子 Tab、筛选状态(不串) |
| 状态持久化 | 每个视角的最后访问 Tab + 筛选条件存 localStorage |
| 验收 | 切回 V1 A/B 对比时,个人 Tab 的筛选体验与 V1 完全一致 |

**FR-2 团队视角:部门/成员筛选(Modify,顶部筛选区)**
| 项目 | 说明 |
|---|---|
| 描述 | 团队视角可见时,顶部筛选新增「部门下拉」+「成员下拉」。其他筛选(类型/状态/仅超时)双视角共用 |
| 业务规则 | 1) 部门经理 = 部门下拉默认自己部门、灰掉不可切换。2) 管理员 = 默认「全公司」,可切任部门。3) 成员下拉联动:选了部门后,成员只列该部门员工 |
| 数据联动 | 切部门 → 统计卡、4 子 Tab 全量 re-render 过滤 |
| 验收 | 部门经理角色访问时,部门下拉 disabled 属性为 true |

**FR-3 团队视角统计卡(Add,替换个人版 4 张)**
| 项目 | 说明 |
|---|---|
| 描述 | 团队视角加载一套新的聚合统计:①部门待办总数 ②超时未处理 ③平均处理时长 ④本周通过数。每张卡带同比趋势 sparkline |
| 业务规则 | ①超时卡背景高亮。②点击「超时」卡 = 一键跳到「团队待办」Tab + 自动勾选「仅超时」筛选。③平均时长 < 24h 绿色,>= 24h 红色 |
| Mock 字段 | 接口:GET `/api/approval/stats/team?dept=&member=` 返回 {pending, timeout, avgHours, doneThisWeek, trend: {pendingTrend:[], timeoutTrend:[], ...}} |
| 验收 | 切到团队视图后 4 张卡数值随部门筛选变化;点超时卡 Tab 切换 + 筛选联动 |

**FR-4 团队视角 · 子 Tab 1 总览(Add)**
- **左主区上 · 成员待办分布卡片**:横条进度条形图,一行一个成员,标注待办数 + 超时红点。点击成员 = 自动跳到「成员分布」Tab + 该成员筛选用,帮助管理者快速识别"谁手上事最多"
- **左主区下 · 最近待办 TOP 6**:审批卡片形式 2 列展示,卡片底部额外信息"审批人:XX"
- **右区上 · 类型分布进度条**:请假/报销/采购/用印各类型占比条形图
- **右区下 · 管理者快捷操作**:红色醒目"处理超时审批 (N 项)"跳团队待办+勾超时、查看效率排行、查看成员分布三个快捷按钮

**FR-5 团队视角 · 子 Tab 2 团队待办(Add,核心干预页)**
| 项目 | 说明 |
|---|---|
| 视图 | 双视图:看板视图(按当前节点分列) / 列表视图(表格) |
| 看板分组变化 | V1 个人视角 = 按审批类型分列。V2 团队视角 = 按「当前节点」分列(部门经理审批 / 财务复核 / 法务审核 / 总经理审批 等)。**帮助管理者识别哪个环节成瓶颈** |
| 列表新列 | 新增「发起人/部门」「当前审批人」「节点停留时长」三列。停留时长 >= 24h 标红加粗 |
| 操作变化 | 行操作列改为「催办」「转交(禁用占位)」「详情」。**管理者不能代替审批人同意/驳回**,只能推进流程,防止越权 |
| 催办逻辑 | 催办 = 调用接口 + Toast 成功 + 冷却时间(1h 内同一条审批只能催 1 次) |
| 转交占位 | MVP 禁用 + hover tooltip "转交能力即将上线,敬请期待" |

**FR-6 团队视角 · 子 Tab 3 成员分布(Add)**
- 看板视图(默认):按人分列,每列顶部成员名 + 待办/超时统计,下方堆叠该成员的审批卡片
- 列表视图:标准列表,显示「发起人」列
- 无待办成员 = 中间置灰"无待办 ✓"占位 + 鼓励 emoji,避免空栏

**FR-7 团队视角 · 子 Tab 4 效率排行(Add,Should 项 MVP 简化)**
| 项目 | 说明 |
|---|---|
| 列 | 排名(金银铜配色 1/2/3 名) / 成员 / 本周处理数 / 平均时长 / 超时数 / 处理数对比条形图 |
| 排名规则 | 默认按本周处理数 DESC 排序 |
| 颜色 | 超时数 >= 2 加 ⚠ 警告 Tag。平均时长 > 24h 红色 |
| MVP 简化 | 不做多维度切换,固定本周处理数 |

**FR-8 详情弹窗增强(Modify,团队视角时)**
| 项目 | 说明 |
|---|---|
| SLA 提示条 | 停留时长 >= 24h 弹窗顶部出现红色警告条:"⚠ 当前节点【XXX】已停留 N 小时,超过 SLA(24 小时),建议催办" |
| 申请信息扩展 | 团队视角下,新增「当前审批人」「节点停留」两个字段行 |
| 底部操作 | 个人视角:【取消】【驳回】【同意】不变。团队视角:【取消】【转交(即将上线·disabled)】【催办】。管理者不做决策,只推进 |
| 意见框文字 | 团队视角 placeholder 变:"催办备注(可选,将发送给当前审批人)"。行数由 3 行缩至 2 行 |

### 2.4 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 团队视角数据量可能大于个人,列表 100 条 / 看板 200 卡以内 FPS >= 50。超长分页加载 |
| 权限 | 前端按角色做 UI 隐藏 + 后端接口强制校验(个人接口只返回自己的,团队接口按部门+角色过滤),防止越权 |
| 隐私 | 金额敏感字段,管理者查看报销类审批按角色分级显示(经理看本部门,管理员按配置) |
| 兼容性 | 切回 V1 A/B 对比时,个人路径功能完全一致。V1 bug 修复同步合入 V2 个人路径 |
| 可访问 | Tab 切换符合键盘可达,颜色对比度满足 AA(红警告色需 4.5:1 对比白背景) |

## 3. 数据与接口(新增 / 变更)

V1 个人接口完全保留不动。V2 增量团队接口:

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/approval/team/list` | 团队待办列表,支持 dept/member/type/status/timeout 过滤 |
| GET | `/api/approval/team/stats` | 团队 4 张统计卡 + 7 天趋势数据 |
| GET | `/api/approval/team/rank` | 成员效率排行数据 |
| POST | `/api/approval/:id/urge` | 催办,传 {reason: 催办备注(可选)},1h 幂等 |
| POST | `/api/approval/:id/transfer` | 转交,V2 MVP 先不开放接口,V2.1 再上 |

## 4. 与 V1 对比 / 影响分析

### 4.1 V1 → V2 个人视角兼容性
| 项 | 影响 | 说明 |
|---|---|---|
| 4 个个人 Tab | ✅ 1:1 保留 | 作为"个人视角"下的子 Tab,功能 / 样式 / 顺序全不变 |
| 顶部筛选 | ✅ 保留 | 类型 / 状态两个下拉双视角共用 |
| 看板 / 列表视图 | ✅ 保留 | 个人视角分组逻辑 = 按审批类型分列,完全 V1 一致 |
| 统计卡 4 张 | ✅ 保留 | 个人视角专属 V1 卡样式 |
| 批量同意 | ✅ 保留 | 个人待办 Tab 列表视图 |
| 详情弹窗 | ✅ 保留 | 个人视角弹窗 + 底部按钮完全不变 |
| Toast / 空状态 | ✅ 保留 | 组件完全复用 |

### 4.2 数据兼容
- 团队接口 = 纯新增,不碰 V1 的任何接口
- 列表和详情核心数据结构 V1 <-> V2 **一致**(title, type, applicant, status, timeline 等),仅在团队视角追加显示字段(currentApprover, stayHours, applicantDept)
- 前后端约定:同一条审批详情接口,通过 query `?mode=personal|team` 返回不同程度的附加字段,避免信息冗余

### 4.3 回滚方案
- 版本切换:侧边栏版本选择器 2 个版本可选 — V1(改造前)/ V2(改造后)。用户投诉可一键切回 V1
- 目录快照: `_versions/v1.tsx` = 原始 V1 基线,随时可作为热修复基线
- 分模块回滚:如顶层双 Tab 架构有争议,可单独回滚该部分(只需把 4 个个人 Tab 提回顶层,团队 4 Tab 暂存至 B 路由)

## 5. 边界情况与异常处理

| 场景 | 处理 |
|---|---|
| 团队 0 待办 | 空状态插画"团队当前无待办,太棒了 🎉" |
| 某节点看板列为空 | 该列内显示小字"暂无,无需处理" |
| 部门没成员(极端) | 成员 Tab 全列"无待办 ✓" |
| 催办冷却期内重复点击 | Toast 提示"本条审批已于 N 分钟前催办过,请稍后再试" |
| 转交按钮点击(disabled) | 原生 disabled + tooltip "转交能力即将上线,敬请期待" |
| SLA > 72h 严重超时 | 除红色停留字外,列表行加淡红背景闪烁 |
| 管理员跨部门切换 | 切部门时数据为空需要 loading 骨架,避免"闪一下白屏" |
| 权限降级 | 临时被撤经理角色的用户,仍在团队视角页面 = 顶部通知"你已切换为普通员工视角"并自动切 Tab |

## 6. 组件映射(Element Plus 设计系统)

本页面组件与 Element Plus 预设 1:1 对齐:
- 顶部 Tab → ElTabs(type=default + underline)
- 视角 Tab → ElTabs(type=card)
- 筛选下拉 → ElSelect / ElCheckbox(仅超时)
- 统计卡 → ElCard + sparkline(ECharts 迷你折线)
- 看板列 / 卡片 → ElCard bordered + ElTag 类型标签
- 团队待办表格 → ElTable stripe + ElPagination
- 效率排名表 → ElTable 行斑马纹 + ElProgress 水平条
- 催办 / 转交按钮 → ElButton(type=primary) / disabled
- 详情弹窗 → ElDialog(width 680px) + ElDivider + ElTimeline + ElInput(type=textarea)
- Toast 反馈 → ElMessage
- SLA 警告条 → ElAlert(type=warning, effect=light)
- 排名金银铜 → ElTag custom-class 背景色

## 7. 设计决策与取舍(Why not)

| 决策 | 取舍理由 |
|---|---|
| 顶层 Tab 做两层不做第 5 Tab | 团队视角下还有 4 个平级子视图,塞不下。两层结构=管理端页面共识(飞书审批/钉钉工作台类似) |
| 管理者不能代替同意/驳回 | 权责分离红线。管理者=推进人不是决策人,防止审批责任纠纷 |
| 转交 MVP 先占位不做 | 转交涉及流程引擎"审批人变更"接口复杂,风险高。催办=足够解决 80% 主动干预场景 |
| 效率排行 MVP 只做本周处理数排序 | 多维度切换=后端接口复杂。Should 项 MVP 原则:先上线再迭代 |
| 看板团队视角分组从「类型」变「节点」 | 团队看板核心是"哪一步卡住了"而不是"什么类型的卡"。类型分布总览已独立条形图覆盖 |
