## 1. 页面定位

「在线服务」列表点击「详情」或行内「服务名称」后的详情页。v2 版本统一了「服务名称」「调用模型名」「后端推理类型」「后端推理实例」命名，确保详情页与列表页、创建/编辑页口径完全一致。

**布局优化（2026-11-05）**：将原有的「服务配置」Tab 下的基础配置信息上移至页面顶部常驻的**概览 + 基础信息卡**，使基础信息在切换任意 Tab（服务配置 / 用量统计 / API 文档）时均可见；「服务配置」Tab 此后仅承载策略项，与创建/编辑页结构严格对齐。

## 2. 顶部概览 + 基础信息卡

面包屑标题固定为「在线服务详情」（不再展示具体服务名称）。

卡片自上而下分三部分：

1. **标题行**：展示服务名称（加粗 18px）+ 发布状态标签（`已发布` 绿色 / `未发布` 灰色），右侧不再放置操作按钮。
2. **基础属性网格**：3 列网格（key-value 形式），常驻展示以下字段，并与创建/编辑页基本信息字段对齐：
   - 调用模型名
   - 发布类型（蓝色标签=公开发布 / 绿色标签=私有发布）
   - 后端推理类型（标签：内部推理实例 / 外部推理实例）
   - 后端推理实例：每个实例前以圆点标识运行状态（绿色 `#67C23A`=正常 / 红色 `#F56C6C`=异常），实例名在右侧展示，去掉「正常 / 异常」文字标签
   - 创建时间
   - 关联模型（仅当「公开发布 + 内部推理实例」时展示，值为关联模型或回退到调用模型名）
   - **说明**：服务名称已在标题行展示，故网格内不再重复「服务名称」一行。
3. **操作按钮区**：位于卡片左下角，左对齐排列 `发布 / 停止发布`、`编辑`（跳转创建页并带 `&v=v2`）、`删除`、`刷新` 图标按钮。

## 3. 功能需求

**FR-1 服务名称统一**（Must）：面包屑固定为「在线服务详情」；服务名称作为顶部概览卡标题行展示，同时【服务配置】Tab 不再保留冗余的「服务名称」key-value 行。

**FR-2 调用模型名统一**（Must）：顶部概览卡以「调用模型名」字段展示当前模型；并动态联动【API 文档】Tab 示例代码中 `"model"` 字段，同步展示当前服务的调用模型名。

**FR-3 后端推理类型统一与模型Fallback联动**（Must）：顶部概览卡展示「后端推理类型」（枚举值统一为「内部推理实例」/「外部推理实例」）；【服务配置】Tab 中「模型Fallback」仅在常规路由策略或未开启流量分发时展示（是否开启 + 兜底推理实例），灰度发布策略下不展示；【全局限流】开启时展示「请求频次上限」，【请求超时时间】命名与创建页一致。

**FR-4 后端推理实例统一**（Must）：顶部概览卡展示「后端推理实例」及各实例运行状态，以绿/红圆点标识（正常=绿色、异常=红色），与列表页和创建页对齐。

**FR-5 路由策略灰度发布（金丝雀 / 蓝绿）**（Must）：【服务配置】Tab 中模块命名统一为【流量分发策略】，排在【缓存加速】之后，内部展示「是否开启」「策略类型」「分发方式」与「权重配置」；按权重分发与金丝雀发布展示各实例权重百分比，蓝绿发布以「当前生效 (100%) / 待命 (0%)」状态徽章只读呈现，与创建/编辑页及列表页保持一致。

## 4. 服务配置 Tab 结构（纯策略项）

基础信息上移后，【服务配置】Tab 严格按创建/编辑页顺序，仅承载以下策略项：

1. **缓存加速**：是否开启、缓存时间（开启时展示）
2. **流量分发策略**：是否开启、策略类型（常规路由策略 / 灰度发布策略）、分发方式（按权重分发 / 金丝雀发布 / 蓝绿发布）、权重配置
3. **模型Fallback**：是否开启、兜底推理实例（常规路由或未开启流量分发时展示；含后端推理类型与实例列表）
4. **全局限流**：是否开启、请求频次上限（开启时展示 `xxx 次 / 分钟`）
5. **请求超时时间**：超时时长
