## 1. 业务背景与目标

算力加速平台通过 vLLM 部署「推理实例」（负责 GPU 资源调度与进程生命周期），通过 Higress 网关将推理实例包装发布为对外暴露 API 的「在线服务」。现有版本（v1）中存在「策略名称」「模型名称」「后端服务类型」「后端服务实例」等概念混用问题。v2 版本统一全链路业务术语，降低用户理解成本。

## 2. 功能需求

**FR-1 服务名称统一**（Must）：将筛选区标签与表格首列由「策略名称」统一改为「服务名称」，筛选输入框占位文案改为「请输入服务名称」，与模块名称「在线服务」及「创建在线服务」保持一致。

**FR-2 调用模型名统一**（Must）：将筛选区标签与表格第 2 列由「模型名称」统一改为「调用模型名」，筛选下拉占位文案改为「请选择调用模型名」，明确其代表客户端 API 请求体中的 `"model"` 字段。

**FR-3 后端推理类型优化**（Must）：将表格第 7 列由「后端服务类型」改为「后端推理类型」，枚举值由「内部推理服务 / 外部推理服务」统一改为「内部推理实例 / 外部推理实例」，与左侧导航「推理实例」对齐。

**FR-4 后端推理实例统一**（Must）：将表格第 8 列由「后端服务实例」改为「后端推理实例」，与创建页、详情页字段命名保持一致。

**FR-5 创建与行操作**（Must）：左上角「创建在线服务」跳转创建页；点击「服务名称」跳转详情页；行操作支持「编辑」「发布」「停止发布」「删除」。

**FR-6 路由策略升级与灰度发布**（Must）：路由策略支持「按权重分发」「金丝雀发布」「蓝绿发布」三种模式。列表与卡片视图支持直观展示策略类型，以及实例的「基线 / 金丝雀 / 主 / 备」角色与流量权重；同时下线冗余且概念冲突的「模型Fallback」兜底。

## 3. 数据要求

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 服务名称 | string | 在线服务唯一名称，点击进入服务详情 |
| 调用模型名 | string | API 请求体中传入的 `model` 参数名 |
| 状态 | enum | 「已发布」/「未发布」 |
| 发布类型 | enum | 「私有发布」/「公开发布」 |
| 路由策略 | string | 如「按权重分发」或「–」 |
| 缓存加速 | enum | 「未开启」/「已开启」 |
| 后端推理类型 | enum | 「内部推理实例」/「外部推理实例」 |
| 后端推理实例 | list | 关联的推理实例列表，含健康状态圆点与实例名 |
| 限流策略 | string | 限流信息或「–」 |
| 创建时间 | datetime | 创建时间 |
