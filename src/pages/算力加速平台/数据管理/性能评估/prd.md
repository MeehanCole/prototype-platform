## 1. 业务背景

推理服务上线前需要确认模型在目标硬件与并发策略下的真实表现。当前性能评估任务分散在脚本与人工记录中，缺少统一的任务列表，导致：

- 同一个服务在不同并发策略下的评估结果无法横向对比；
- 历史评估报告难以追溯，重复评估成本高；
- 评估任务占用的算力规格（GPU 型号 / CPU 内存 / 显存）不可见，无法评估资源成本。

性能评估挂在侧栏算力评测分组下，为推理服务提供评估任务的登记、检索与结果查看入口。

## 2. 功能概览

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| F-1 | 评估任务列表 | 表格展示「名称/ID」「评估规格」「评估类型」「评估对象」「评估模式」「评估状态」「创建人」「创建时间」「操作」 |
| F-2 | 创建评估任务 | 点击「创建评估任务」发起新的评估任务（本原型仅入口，不含表单） |
| F-3 | 名称检索 | 前置下拉固定为「名称」，输入框占位「请输入」，点击放大镜或回车后生效 |
| F-4 | 刷新 | 点击「刷新」按钮清空检索条件、状态筛选并回到第 1 页 |
| F-5 | 状态筛选 | 点击漏斗按钮展开筛选浮层，按「评估状态」过滤，仅看未完成任务时按钮高亮 |
| F-6 | 查看结果 | 状态为「已完成」的任务提供「查看结果」入口 |
| F-7 | 克隆任务 | 行内「克隆」复制参数重新发起评估 |
| F-8 | 删除任务 | 行内「删除」移除单条评估任务 |
| F-9 | 批量删除 | 勾选多行后启用「批量删除」，未选中时置灰禁用 |
| F-10 | 分页 | 展示任务总数（Mock 总数 34 条），支持 10 / 20 / 50 条每页与页码跳转 |
| F-11 | 跳至页码 | 分页右侧「跳至」输入框 + 「页」，输入页码定位 |

页面不包含评估任务创建表单、报告详情与数据集选择，属后续迭代范围。

## 3. 用户故事

- 作为算法工程师，我希望在一张表里看到所有历史评估任务及其规格与状态，以便快速找到可复用的评估结果。
- 作为算法工程师，我希望按名称检索并只看未完成的任务，以便跟踪正在运行的评估。
- 作为平台管理员，我希望批量清理失效的评估任务，减少无效记录。

## 4. 功能需求详单

### 4.1 标题区

- 页面标题为「性能评估」，下方一行灰色说明文案，描述支持文本性能评估与并发/负载策略覆盖。

### 4.2 工具条

| 元素 | 类型 | 行为 |
| --- | --- | --- |
| 「创建评估任务」 | 主按钮（蓝底白字） | 预留入口，暂无表单 |
| 检索前置下拉 | 只读下拉 | 固定展示「名称」 |
| 检索输入框 | 文本输入 | 占位「请输入」，回车或点击放大镜触发检索 |
| 放大镜 | 图标按钮 | 触发检索，重置到第 1 页 |
| 「刷新」 | 图标按钮 | 清空关键词、筛选与分页 |
| 筛选漏斗 | 图标按钮 | 展开「评估状态」浮层；仅看未完成时按钮描边高亮 |

### 4.3 列表字段

| 列 | 内容 | 说明 |
| --- | --- | --- |
| 复选框 | 单选 / 全选当前页 | 全选只作用于当前页数据 |
| 名称/ID | 名称（可点击）+ 任务 ID | 名称后带铅笔编辑图标，ID 为 `msp-xxxxxxxx`，右侧复制图标 |
| 评估规格 | GPU 型号 × 数量 + 资源明细 | 第二行为 CPU / 内存 / 显存，灰色小字 |
| 评估类型 | 文本推理 | 单行文本 |
| 评估对象 | 对象名 + 对象类型 | 第二行为灰字，如内部推理服务 |
| 评估模式 | 模式名 + 模式细节 | 第二行为灰字说明 |
| 评估状态 | 彩色圆点 + 状态文案 | 已完成为绿色，下方附「查看结果」链接 |
| 创建人 | 账号名 | 单行文本 |
| 创建时间 | 相对时间 | 如 16 天前 |
| 操作 | 克隆 / 删除 | 文字链接 |

### 4.4 底部操作区

- 左侧展示已选数量（初始为 0）与「批量删除」按钮；未选中时按钮禁用并显示浅蓝色。
- 右侧为分页区：任务总数、每页条数下拉、页码翻页，以及「跳至」输入框 + 「页」。
- 空结果显示「暂无评估任务」。

- 视觉沿用平台规范：主色 `#166eff`，卡片边框 `#e5e6eb`，表头底色 `#f7f8fa`。
