## 1. 背景与目标

### 1.1 背景

推理服务部署后，扩容与缩容的**依据**目前只依赖ray serve autoscaler基于请求排队数进行弹性扩缩容，缺少基于显卡指标的扩缩容机制。


### 1.2 目标

让**GPU 指标直接参与扩缩容决策**，把扩缩容依据从「请求数」扩展到「GPU 利用率 / 显存占用 / 算力活跃度」等指标，并允许用户自行配置判定条件。

| 目标 | 说明 |
|---|---|
| 依据更贴合业务 | 按 GPU 指标扩缩，而不是按间接指标猜 |
| 配置可控 | 指标、阈值、副本范围、观察时长均由用户配置 |
| 多厂商可用 | 英伟达、昇腾、Metax、寒武纪、海光、天数等机型都能配 |
| 能解释 | 用户能看到「当前按什么条件扩缩」，而不是黑盒 |

### 1.3 用户与场景

| 角色 | 关注点 |
|---|---|
| 算法工程师 | 服务在高峰时能不能顶住、低谷时会不会浪费卡 |
| 平台运维 | 资源利用率、异常扩缩排查 |

**典型场景**

1. **在线推理服务**：白天请求高峰 GPU 利用率到 85%，需自动扩到 4 个副本；夜间回落到 30% 以下，收回副本释放显卡
2. **多厂商混合集群**：同一套配置方式适配英伟达与国产卡，运维不用记两套用法
3. **特殊业务判定**：默认指标不满足时，允许用户写一条自定义表达式（如「显存占用超 85% 才扩」）作为兜底

---

## 2. 需求范围

- 三种弹性模式：常规、Serverless（按请求）、指标（按 GPU 指标）
- 指标模式支持两种来源：内置指标（多条件组合）、自定义表达式
- 指标、阈值、副本范围、观察时长可配置、可编辑、可在详情回显
- 多家算力厂商的机型与指标支持

---

## 3. 方案概述

在现有弹性能力之上，新增一种**「按指标扩缩容」**的模式：系统持续观察用户配置的指标条件，**条件满足时放开副本上限，让服务能扩上去；条件长时间不满足时收回上限，把副本降回最小值**。

三种模式面向不同负载特征：

| 模式 | 适合谁 | 判定依据 | 用户要配什么 |
|---|---|---|---|
| **常规模式** | 负载稳定、不想自动伸缩 | 无 | 副本数 |
| **Serverless 模式** | 请求量波动大、关心排队 | 每副本处理中的请求数 | 副本区间 + 观察时长 + 目标 / 最大请求数 |
| **指标模式** | 关心 GPU 真实压力 | GPU 指标（内置或自定义） | 伸缩条件 + 副本区间 + 观察时长 |

> 指标模式的判定依赖平台已有的指标采集与弹性调度能力，本次不改变采集与调度链路，只新增**配置入口与判定条件**。

### 4.2 创建内部推理服务

#### 4.2.1 弹性伸缩

分区说明：**弹性伸缩最小单元是一个模型副本，通过调整模型副本数实现扩缩容。**

**指标模式**

按算力指标判断是否需要扩容，表单与 Serverless 同构。

**指标来源：内置指标**

| 字段 | 规则 |
|---|---|
| 算力型号 | 只读，取自「算力规格」选中行 |
| 伸缩条件 | 条件列表，默认 1 条、最多 3 条，每条为「指标 + ≥ + 阈值」；可逐条删除 |
| 条件关系 | 2 条及以上时出现，必填，选「且」（同时满足）或「或」（满足任一） |
| 聚合方式 | 必填，平均值 / 最大值 / 求和 |
| 最小模型副本数 | 必填，至少 1 个（算力资源冷启动需要时间，不能缩到 0） |
| 最大模型副本数 | 必填，必须 ≥ 最小副本数；两者相等时视为固定副本 |
| 缩容检测窗口 | 必填，秒。指标回落后观察这么久，确认不是短暂波动再缩容 |

条件说明文案（随关系变化）：

- 选「且」：**同时满足上述条件时，允许服务扩展到最大副本数以应对高峰；条件长时间不满足时，回落至最小副本数并释放算力资源**
- 选「或」：**满足任一条上述条件时，允许服务扩展到最大副本数以应对高峰；条件长时间不满足时，回落至最小副本数并释放算力资源**

**指标来源：自定义表达式**

| 字段 | 规则 |
|---|---|
| 指标表达式 | 必填，单行输入，输入时联想可用指标名 |
| 填写要求 | 用户写**完整判断条件（含比较）**，例如「显存占用超过 85% 时扩容」；因此**不再单独填写阈值** |
| 其余字段 | 最小 / 最大模型副本数、缩容检测窗口 |

**模式限制**

推理框架为 KTransformer 时，**仅支持常规模式**，Serverless 与指标模式置灰不可选，并提示「KTransformer 暂不支持 Serverless 与指标模式，仅支持常规模式（固定副本）」。从其他框架切换到 KTransformer 时自动回到常规模式。

## 5. 业务规则与校验

| # | 场景 | 规则 | 提示 |
|---|---|---|---|
| 1 | 最小模型副本数 | ≥ 1 | 「最小模型副本数不能为 0（算力资源冷启动需数分钟，至少保留 1 个副本）」 |
| 2 | 副本区间 | 最小 ≤ 最大（允许相等） | 相等时提示「等同于常规模式（无弹性）」；倒置时提示「最大模型副本数不能小于最小模型副本数」 |
| 3 | 伸缩条件 | 1 ~ 3 条 | 达到 3 条后不再展示「添加条件」 |
| 4 | 条件关系 | 2 条及以上必填 | 默认「且」 |
| 5 | 聚合方式 | 必填 | 默认「平均值」 |
| 6 | 自定义表达式 | 必须能返回单个数值 | 保存时校验，提示具体原因（如「返回多个序列，请使用聚合」） |
| 7 | 框架限制 | KTransformer 仅常规模式 | 置灰 + 悬停提示 |

| 算力厂商 | 可选指标 |

## 7. 状态流转

```
创建（填表 → 校验 → 提交）
   ↓
列表卡片（运行中 · 副本 1/1 · 弹性模式 · 模型副本区间）
   ↓ 查看
详情（弹性伸缩配置完整回显）
   ↓ 编辑
编辑（预填，部分字段锁定）→ 保存 → 回到来源页，数据已更新
   ↑
启停 / 删除 → 列表与详情同步
```

| 流转 | 变化 |
|---|---|
| 创建提交 | 新增卡片，状态运行中，副本为最小副本数 |
| 编辑提交 | 服务信息与弹性配置更新，列表与详情同步 |
| 停止 | 状态变已关机，副本 0/0 |
| 启动 | 状态变运行中，副本回到最小值 |
| 删除 | 服务与配置一并移除 |

## 8. 异常与边界

| 场景 | 处理 |
|---|---|
| 未选算力规格就选指标模式 | 指标下拉显示「暂无内置指标」，提交被拦截 |
| 编辑时模型不在下拉列表中 | 保留原值，不因保存被改写 |
| 历史数据框架与弹性模式不匹配 | 编辑时按框架约束纠正为常规模式 |
| 指标服务不可用 | 联想降级为纯手写；扩缩容按兜底副本数运行 |
| 列表为空 | 展示「暂无数据」 |
