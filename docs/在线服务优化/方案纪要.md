# 在线服务优化 · 方案纪要

## 2026-11-04 · 方案 v2：在线服务术语与表单联动优化（v1 / v2 多版本对比）

- **问题**：现有产品「在线服务」模块存在多处概念与命名混用（如把在线服务本身叫做“策略名称”、把接口请求体的 `"model"` 参数叫做“模型名称”且需手敲、把后端关联对象在“推理服务”与“推理实例”之间来回切换），导致用户心智负担高、领导体验认为不好用。
- **结论（v2 五项改动，覆盖列表页 / 创建与编辑页 / 详情页）**：
  1. **「策略名称」→「服务名称」**：列表筛选栏、表头、创建/编辑页表单项及详情页基本信息统一改名，与模块名「在线服务」对齐。
  2. **「模型名称」→「调用模型名」**：列表筛选栏、表头、创建/编辑页表单项及详情页基本信息统一改名，明确其为 API 调用时传入的 `"model"` 参数名，与公开发布下的「关联模型」区分。
  3. **「后端服务类型」→「后端推理类型」，选项改为「内部推理实例 / 外部推理实例」**：列表表头与单元格、创建/编辑页单选、Fallback 类型下拉及详情页统一收敛为“推理实例”口径，与左侧导航「推理实例」及下一行「后端推理实例」保持一致。
  4. **「后端服务实例」→「后端推理实例」**：列表表头、创建/编辑页标签与占位文案、详情页基本信息统一使用「后端推理实例」。
  5. **关联推理实例后自动填充「调用模型名」**：创建/编辑页选择「后端推理实例」后，若用户未手动修改过「调用模型名」，自动填入所选**第一个**推理实例部署的模型名称（清空实例时同步清空），同时保留手动修改能力。
- **多版本管理**：
  - `方案 v1`：保留现有产品 1:1 逆向还原基线（含公开发布下仅内部推理服务展示关联模型、初次切换默认未选）。
  - `方案 v2`（默认展示）：落地上述 5 项优化并挂载功能点批注（`NewTag`），支持在页面顶栏随时切换 `方案 v1 / 方案 v2` 进行前后对比。
