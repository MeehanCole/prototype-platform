# 开发态素材库（DEV ONLY）

> 决策留痕：2026-11-16，项目负责人明确要求「设计的时候能看到有哪些素材，正式运行给别人看时不体现素材」。
> 涉及 `src/App.tsx`、`src/host/layout/Sidebar.tsx`，属于 R1 外壳红线，**经项目负责人明确授权执行**。

---

## 1. 解决什么问题

素材（平台外壳、九宫格、功能点批注、图标、设计系统 token）沉淀在 `src/lib/` 和 `docs/` 后，
时间一长就忘了：

- 到底有哪些素材；
- 每个素材长什么样；
- 现在哪个页面在用；
- 接入代码怎么写；
- 对应说明书在哪。

所以增加一个**只在开发环境出现的素材库页面**，把这些信息集中可浏览。正式构建时整页消失，
不进入给外部查看的产物。

## 2. 怎么访问

```bash
npm run dev
```

左侧导航「平台总览」下方 →「素材库」（带 `DEV` 徽标）→ `/__assets`。

页面内可：

- 看实时预览（真实组件 + 现有 preset，不是截图）；
- 点图标复制 `<ShellIcon />` / `<NavIcon />` 用法；
- 复制每个素材的最小接入代码；
- 直接阅读 `docs/` 与 `.skills/reusable-assets.md`；
- 通过 `?a=<id>` 深链，例如 `/__assets?a=product-nav`。

> `npm run build` / `npm run preview` 看不到素材库，是预期行为。

## 3. 生产隔离机制

```tsx
// src/App.tsx
const DevAssetLibrary = import.meta.env.DEV
  ? lazy(() => import('@/dev/assets/AssetLibrary'))
  : null

{DevAssetLibrary && <Route path="__assets" element={<DevAssetsRoute />} />}
```

- `import.meta.env.DEV` 在 `vite build` 时被静态替换为 `false`，`lazy()` 分支整体被 DCE；
- 素材库模块只通过动态 `import()` 进入，`App.tsx` / `Sidebar.tsx` 不静态引用 `src/dev/`；
- 文档通过 `?raw` 内嵌在素材库模块内，模块被 DCE 后文档文本也不会进入产物；
- 不注册进 `pageRegistry`，因此不进入侧栏产品树、平台总览、`Cmd+K` 搜索。

### 验收命令

```bash
npm run build
grep -rl "素材库\|__assets\|DEV ONLY" dist     # 无输出
ls dist/assets | grep -i -E "AssetLibrary|Demos" # 无输出
```

## 4. 目录结构

| 文件 | 作用 |
| --- | --- |
| `src/dev/assets/AssetLibrary.tsx` | 页面骨架：左侧清单 + 右侧详情 + 文档阅读 |
| `src/dev/assets/registry.ts` | 素材 / 文档登记表（名称、说明、引入路径、使用方、标签、代码片段、关联文档） |
| `src/dev/assets/Demos.tsx` | 各素材的实时预览；按 `id` 与 registry 对应 |
| `src/dev/assets/DocsView.tsx` | Markdown 渲染（复用 `react-markdown` + `remark-gfm`，跟随工作台深浅色） |
| `src/dev/assets/ui.tsx` | 代码块、复制按钮、区块标题等小组件 |
| `src/dev/assets/clipboard.ts` | 剪贴板（含非安全上下文回退） |

## 5. 新增一个素材

1. 先在 `src/lib/<name>/` 落实现（见 [可复用素材规范](../../.skills/reusable-assets.md)）；
2. 在 `src/dev/assets/registry.ts` 的 `ASSETS` 里加一条：

   ```ts
   {
     id: 'your-asset',
     kind: '组件素材',
     name: '素材名',
     summary: '一句话说明',
     status: 'stable',
     importPath: '@/lib/your-asset',
     usage: ['使用方页面'],
     tags: ['标签'],
     docs: [{ id: 'doc-platform-shell' }],
     snippet: `import { X } from '@/lib/your-asset'`,
   }
   ```

3. 需要专属预览时，在 `Demos.tsx` 加一个 `XxxDemo`，并在 `AssetLibrary.tsx` 的 `AssetDemo` 里按 `id` 挂上；
4. 有新说明书时，在 `DOCS` 里登记，文件放 `docs/<主题>/<名称>.md` 即可被 `import.meta.glob` 自动内嵌；
5. 跑一遍第 3 节的验收命令。

> 只是登记、不做 demo 也可以：详情页仍会展示说明、引入路径、使用方、代码片段与文档。

## 6. 边界

- ❌ 不要把素材库放进 `src/pages/`：会被 `pageRegistry` 当成业务页面，污染产品树 / 总览 / 搜索；
- ❌ 不要在素材库内复制素材的视觉实现：预览必须直接 `import` `src/lib/` 组件，避免「预览和真实页面两套样式」；
- ❌ 不要改素材库来「修」素材视觉：视觉改动仍在 `src/lib/`，并同步 `docs/`；
- ✅ demo 使用现有 preset（如 `CALSPEED_SHELL`）作为示例数据，不引入其它项目的页面代码；
- ✅ 新增页面 / 素材仍遵守 R2 项目隔离与 R1 外壳边界。
