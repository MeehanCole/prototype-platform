# 智能中心 · 导航结构与权限（补充评审稿）

> 状态：**待评审**（未动页面代码，只更新了导航预设数据）
> 关联：[产品导航面板素材](./产品导航面板.md) · [智能知识库方案设计](../KnowledgeBase/方案设计.md)
> 结论一句话：`智能运维` 改为 `智能中心`，下分 **智能应用**（前台，人人可见）和 **系统设置**（后台，仅管理员可见）两块；`知识库配置` 收进后者的 `参数配置`（与 `运行与存储` 同页、页内双 Tab 切换），知识库页面只留"库内可调项"。

---

## 1. 为什么这样改

| 现在的问题 | 影响 |
| --- | --- |
| 一级名 `智能运维` | "运维"只装得下监控告警，装不下知识库/对话/Agent 配置，名字先自相矛盾 |
| `智能应用` 下面挂 6 个页面（含模型/工具/技能管理） | 前台业务（知识库、对话）和后台配置（模型、配额）混在一层，普通用户点进去全是看不懂的配置项 |
| `智能管控` 这个名字 | "管控"带强制意味，客户侧听着像权限收紧；且与页内的 `参数配置` 语义重叠 |
| 缺少知识库的全局配置 | 解析器、OCR、切分默认值、Embedding、配额这些**全平台一份**的设置无处安放，只能硬塞进每个库的"设置"里，导致用户能改到不该他改的东西 |
| 没有角色概念 | 平台走 OIDC 登录，导航却对所有人长一样，普通用户看到 4 个管理入口，点了要么空白要么报错 |

## 2. 目标结构

```
智能中心
├─ 智能应用            ← 前台，所有登录用户可见
│  ├─ 控制台            历史会话 + 对话交互（业界流程类 xxxBot 形态，交互本期未做）
│  └─ 知识库            用户自己上传文档、解析、切分、检索验证
└─ 系统设置            ← 后台，仅平台管理员可见
   ├─ 模型管理          对话/Embedding/重排模型的注册与默认值
   ├─ 工具管理          MCP Server 接入
   ├─ 技能管理          SKILL.md 能力包
   └─ 参数配置   ★新增   面板只有这一项，页内双 Tab 再分：
      ├─ 运行与存储      运行资源、数据库/对象存储用量、会话清理与审计保留
      └─ 知识库配置      默认分块策略与调整权限、单库/单文件/单用户配额
```

导航面板落位：**第 5 列**，一个产品、两个分组（沿用现有 `section → group → item` 三层，不改结构）。

| 层级 | 值 | 视觉 |
| --- | --- | --- |
| 产品标题 | `智能中心`（icon `Atom`） | 28px 图标 + 16px 半粗，只有一行 |
| 分组 1 | `智能应用` | 9px 蓝点 + 14px 灰字 |
| 分组 1 服务 | 控制台 `MessagesSquare` / 知识库 `Library` | 30px 行，缩进 15px |
| 分组 2 | `系统设置` | 同上 |
| 分组 2 服务 | 模型管理 `BrainCircuit` / 工具管理 `Wrench` / 技能管理 `Puzzle` / 参数配置 `SlidersHorizontal` | 同上 |

> 为什么不再多加一个"智能中心"分组：产品标题已经叫智能中心，再加同名分组是废话；两块直接用 `智能应用` / `系统设置` 命名，语义对齐"前台/后台"。
>
> 为什么把 `知识库配置` 和 `运行与存储` 合成一个 `参数配置`：两者都是"管理员一次性设定、之后长期生效"的参数，拆成两个面板项会让管理员在面板上做二次选择；合起来后，**面板只回答"去哪"，页内 Tab 再回答"改哪一类"**。面板保持 4 项，一屏读完。
>
> 为什么不拆成两个子导航项：`运行与存储` 是运维视角（资源够不够、数据留多久），`知识库配置` 是业务策略（新库怎么切、给多少额度）。两者操作人相同、变更频率都低，拆开后每个页面只有 2–4 个区块，导航收益低于多一次点击的成本。
>
> 页面内的 Tab 放在标题下方、内容区顶部，而不是再加一条左侧二级导航：内容区本身已有卡片分栏，左侧再来一列会形成"三栏夹心"，压缩表单宽度。

## 3. 命名结论（`智能管控` → `系统设置`）

| 候选 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| **系统设置** | 客户看到就知道"这是管理员改东西的地方"；与左侧业务产品（统一运营平台/算力加速平台）不撞名，不会被读成"管整个平台" | 范围略窄：模型注册、工具接入、技能上传是"管理资产"，不完全是"设置"；与内层 `参数配置` 近义 | **采用** |
| 平台管理 | 与"智能应用"对仗 | "平台"指代不明，容易被当成管整个平台；和左侧平台产品撞名 | 弃用 |
| 管理后台 | 范围最准，天然前台/后台对仗 | 偏 IT 语感，客户演示时略硬 | 备选 |
| 管理中心 | 中性 | 与四个"××管理"叠字，信息量为零 | 备选 |
| 智能管控 | —— | 语义偏强制；与"参数配置"语义重叠 | 不采用 |

> 关于"系统设置 > 参数配置 > 知识库配置"三层近义：这是**分组 / 页面 / 页内页签**三种不同粒度，读起来是"设置区里的参数页 → 知识库那一组参数"，不拗口。内层已由 `配置管理` 定为 `参数配置`，与 `运行与存储` 合为一页，也避开了"管理 → 配置 → 配置"的叠字。

配套命名：`参数配置` 作为**面板唯一的配置入口**保留；它内部的两个 Tab 分别叫 **`运行与存储`**（运行资源、数据库/对象存储、数据保留）和 **`知识库配置`**（分块默认值、库配额）。原先"把配置管理改名为运行配置"的方案作废——那样会把两个同类项拆到面板上，反而多一层选择。

## 4. 每个入口的职责边界

| 入口 | 谁用 | 管什么 | 明确不管 |
| --- | --- | --- | --- |
| 控制台 | 所有人 | 历史会话、新建对话、挂流程/任务 | 文档、模型、配额 |
| 知识库 | 所有人（可见范围由库成员决定） | 建库、传文档、触发解析、调库级分块、检索测试、看解析任务 | 解析器选型、Embedding、配额、谁能建库 |
| 模型管理 | 管理员 | 模型注册、连通性测试、设默认对话/Embedding/重排模型 | 单个库绑定哪个模型 |
| 工具管理 | 管理员 | MCP Server 地址、鉴权、工具白名单 | 库 |
| 技能管理 | 管理员 | SKILL.md 上传、启停、可见范围 | 库 |
| **参数配置** | 管理员 | 平台级参数总入口，页内双 Tab（见 §5） | 具体文档内容、库级参数 |
| ├ 运行与存储 | 管理员 | 运行资源用量、数据库与对象存储占用、会话自动清理与审计保留 | 库级参数、模型选择 |
| └ 知识库配置 | 管理员 | 默认分块策略/块大小/重叠、库创建人调整权限、单库文档/存储、单文件大小、单用户建库数 | 单个库的覆盖值、模型与向量引擎 |

边界一句话：**普通用户只决定"这个库里放什么、怎么切"，管理员决定"平台允许怎么切、用哪个模型、给多少额度"。**

## 5. 参数配置（新增页）内容

**页面骨架**：页面标题「配置管理」+ 一句说明，标题下方是页内双 Tab：`运行与存储` / `知识库配置`，默认落在 `运行与存储`。Tab 用文字 + 底部 2px 蓝色下划线，内容区整宽，不新增路由，也不再加左侧二级导航。

> 导航结论：**一个面板项 + 页内两个 Tab**，不拆成两个子导航项。原因见 §2 的三条说明；拆分的代价是面板变长、两页都偏薄，而收益只是少一次点击。

### 5.1 运行与存储

面向运维，回答"资源够不够、数据放哪儿、留多久"。三个区块，均为平台级只读或轻量编辑。

| 区块 | 字段 | 说明 |
| --- | --- | --- |
| 运行资源 | 执行环境申请量（CPU/内存，只读）、环境数量上限、子智能体并发、闲置回收时长、用户响应时限 | 上限类字段可就地编辑，保存后对后续任务生效；不改写正在运行的任务 |
| 存储管理 | 数据库占用、对象存储占用、各库容量明细 | 展示用量与占比，不提供删除入口；清理动作走独立运维流程 |
| 数据保留 | 会话自动清理天数（默认 90）、审计日志保留天数 | 到期自动清理；缩短保留期不追溯删除已归档数据 |

### 5.2 知识库配置

面向业务策略，回答"新库默认怎么切、给多少额度"。两块，保存后对**新建库/后续上传**生效，不回溯覆盖已建库。

| 区块 | 字段 | 说明 |
| --- | --- | --- |
| 默认分块与调整权限 | 默认策略四选一（自动 512/80、标题 768/80、语义 768/120、固定 1024/150）、块大小（128–2048）、重叠（≤ 块大小一半）、允许库创建人调整 | 建库弹窗按当时策略初始化；关闭调整权限后建库与库设置只读，已有自定义值保留 |
| 容量与配额 | 单库文档数（默认 5000）、单库存储（默认 50 GB）、单文件大小（默认 100 MB）、单用户建库数（默认 20） | 四字段均为正整数并做上下界校验；调低配额不删除已有数据，仅阻止后续写入 |

页内形态：蓝色说明条解释"只影响新建库"；每个区块是一张白卡，卡内表单行 + 底部「还原 / 保存」，保存后就地出现"已保存"提示。

> **不做**：解析器/OCR/向量库/Embedding/重排模型不在此页重复出现，统一由 `模型管理` 维护；检索 TopK、相似度阈值、重排开关属于库内成员行为，不下沉为平台默认。配额目前只做前端校验与提示，尚未接入上传链路强制拦截。

> **可见性定稿**：`知识库配置` 里的分块默认值与配额**只属于管理员**；知识库前台（建库向导、库设置、概览、检索测试）不出现模型名、向量库、维度、距离算法，也不放"当前使用：xxx（由管理员配置）"这类只读提示。前台只继承结果值（如"自动 · 512 / 80 tokens"）。

## 6. 权限（OIDC）

### 6.1 角色

平台侧只认两个角色，其余细分放到"库成员"里，避免角色爆炸：

| 角色 | 来源 | 判定 |
| --- | --- | --- |
| 平台管理员 `admin` | OIDC `roles` 包含 `aiops-admin`（名字待定） | 见全部入口 |
| 普通用户 `user` | 其他已登录用户 | 只见 `智能应用` 分组 |

库内角色（`owner` / `editor` / `viewer`）是**库的成员属性**，不是平台角色，不参与导航。

### 6.2 可见性矩阵

| 入口 | admin | user |
| --- | --- | --- |
| 控制台 | ✅ | ✅ |
| 知识库 | ✅ | ✅ |
| 模型管理 | ✅ | ❌ |
| 工具管理 | ✅ | ❌ |
| 技能管理 | ✅ | ❌ |
| 参数配置（含两个 Tab） | ✅ | ❌ |

整页 `admin` 校验即可，两个二级页不再单独分角色（都是管理员才能进）。普通用户的第 5 列只剩"智能应用"一个分组，高度约 130px，不会出现"半列空白"的观感——分组本身随权限消失，不留占位。

**模型对普通用户完全不可见**：矩阵里"模型管理 / 参数配置"整页不可见只是第一层；知识库页面内部同样不得出现模型、向量引擎、Embedding、重排模型字段或只读值（见 §7 与《方案设计》§3.3）。普通用户回答的是"传什么文档、怎么切、怎么搜"，不是"用哪个模型"。

### 6.3 落地要点（四处都要做，只做导航等于没做）

1. **导航面板**：`ProductNav` 增加 `role` 入参，按 `visibleTo: 'admin'` 过滤 item / group；过滤后 group 为空则整组不渲染，section 为空则整段不渲染（搜索过滤已有这套逻辑，复用）。
2. **左侧栏**：`pageRegistry` 按 `meta.access` 过滤产品/需求/页面，否则用户从侧栏照样点进管理页。这是**下一期改动**，本期先记录。
3. **路由守卫**：直接粘贴 URL 访问时给 403 占位页（"该功能仅平台管理员可用，请联系管理员开通"），不要白屏。
4. **演示开关**：原型要给客户演示两种视角，建议顶栏账号菜单加"切换为普通用户（演示）"，或支持 `?role=user`；默认 `admin`，保证现有截图/演示不变。

本期实现范围：仅第 1 项 + 预设数据；2/3/4 记录为待办。

## 7. 对《智能知识库方案设计》的三处修订

| 位置 | 原设计 | 修订后 |
| --- | --- | --- |
| §5.1 建库向导 | 3 步（基础信息 → 引擎与 Embedding → 分块） | **2 步**（基础信息 → 分块）。向导内**完全不出现**引擎/模型字段，也不提示"将使用某模型"；全局默认静默继承 |

| §4.1 概览 | 切分参数直接展示 | 加"继承全局默认"角标，覆盖过的显示"已自定义"并可一键恢复默认 |
