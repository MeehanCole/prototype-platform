# 智能知识库 · 默认模型配置 方案设计

> 状态：**待评审**
> 日期：2026-11-15
> 上游依据：[调研-WeKnora.md](./调研-WeKnora.md)（v0.9.0）、[方案设计.md](./方案设计.md)
> 范围：模型管理中的「默认模型」配置、缺失提示、知识库创建前置校验
> 不含：真实模型连通性探测、密钥托管、按知识库覆盖模型（本期仍由平台统一继承）

---

## 1. 结论先行

知识库的入库与检索依赖对话、向量与重排三类模型，图片与扫描件场景由支持图片理解的对话模型承担，且选择权必须收口到管理员，因此「默认模型」应作为**平台级、全局唯一**的配置存在，而不是散落在每个知识库的创建表单里。

建议按以下方式落地：

1. **模型增加能力类型**：`对话（chat）`、`向量（embedding）`、`重排（rerank）`。同一模型只属于一种能力，列表与默认配置都按能力识别；对话模型可额外勾选「支持图片理解（多模态）」，不作为独立能力。
2. **默认配置独立于模型注册**：模型管理页顶部增加「默认模型」状态区，固定展示三个槽位（对话、向量为必选，重排为可选）；未配置的槽位显示「未配置」。点击「设置默认模型」在弹窗中集中选择，不要求用户逐张卡片设置。
3. **进入模型管理时给出持久提示，而不是每次弹窗**：只要必选槽位（对话、向量）有任意一个缺失，页面顶部保留一条警示条，说明缺什么、会影响什么，并提供「立即设置」。配置完整后警示条消失，状态区转为绿色「已就绪」。自动弹窗会打断管理员做其他模型维护，不建议。
4. **知识库创建做前置拦截**：缺少对话模型或向量模型时，点击「创建知识库」不进入创建弹窗，而是给出阻断说明，列出缺失项，并提供「前往设置默认模型」。业务用户看到的是「请联系管理员」，不暴露模型细节。重排模型不参与建库校验。
5. **默认模型受保护**：正在作为默认模型的模型不可停用、不可删除；如需更换，先在「设置默认模型」中切换，再操作原模型。
6. **变更影响分级**：更换对话模型、重排模型只影响后续问答/检索排序，可直接保存；更换向量模型会使既有向量索引失效，必须二次确认并提示需要重建索引。

> 为什么对话模型和向量模型都算「创建前置」：向量模型决定文档如何写入索引，对话模型决定问答能否生成回答，缺少任意一个，知识库都无法完成完整链路。重排模型只影响检索结果的排序质量，不配置时仍可正常检索与问答，因此作为可选项，不阻断建库。图片理解依附于对话模型：所选对话模型具备多模态能力时，图片与扫描件链路自动生效，不额外占用默认槽位。

## 2. 现状与问题

### 2.1 现状

- `模型管理` 只有名称、协议、请求地址、启停，没有能力类型；无法判断某个模型能否用于向量化或重排。
- 模型列表是页面内局部状态，刷新即回到 Mock；知识库列表无法读取同一份模型配置。
- 知识库创建弹窗刻意不暴露模型、向量引擎、Embedding 等字段，这是正确的业务边界；但缺少「平台默认值是否就绪」的前置判断。
- PRD 仍把默认 Embedding / 重排模型放在「参数配置 · 模型与索引」，与当前「模型管理」页面职责重叠，且默认模型只覆盖对话模型。

### 2.2 问题

| 问题 | 后果 |
|------|------|
| 没有能力类型 | 管理员可能把对话模型选成向量模型，直到入库失败才暴露 |
| 默认值分散 | 模型管理与参数配置各存一份，无法判断哪份生效 |
| 无缺失提示 | 管理员不知道配置不完整，业务用户建库时才遇到失败 |
| 无引用保护 | 删除/停用默认模型会让知识库链路静默失效 |
| 无变更影响提示 | 更换向量模型后旧索引不可用，但界面没有告知 |

## 3. 与 WeKnora 的对应关系

WeKnora 在空间（租户）级提供默认模型，建库时选择 Embedding 模型，检索链路再使用重排模型；配置采用「单次上传 > 知识库 > 空间默认」的三级覆盖。

本期原型只取其中两层含义：

| WeKnora | 本期方案 | 说明 |
|---------|---------|------|
| 空间级默认模型 | 平台级默认模型（对话 / 向量 / 重排） | 全局唯一，由管理员维护 |
| 建库时选择 Embedding | 建库时**不选择**，继承平台默认 | 保持业务用户对模型透明 |
| 知识库级模型覆盖 | 不做 | 避免同一平台内索引口径不一致 |
| 更换 Embedding 需重建 | 保留为保存前二次确认 | 原型展示影响面，不执行真实重建 |
| 模型管理含 LLM / Embedding / Rerank / VLM / ASR | 收敛为对话 / 向量 / 重排；VLM 并入对话模型的「支持图片理解」标记 | 保留图文链路，不额外增加默认槽位；ASR 本期不做 |

> 与 WeKnora 的有意差异：WeKnora 把模型选择放在建库向导里；本产品坚持「模型对业务用户完全透明」，因此把选择前移到管理员的默认配置，建库只做前置校验。

## 4. 信息架构与页面落点

```
系统设置
├── 模型管理
│   ├── 默认模型状态区（对话 / 向量 / 重排）
│   ├── 缺失警示条（有缺失时出现）
│   ├── 工具栏（添加模型居左，搜索居右）
│   └── 模型卡片（能力标签、默认标识、启停、编辑、删除）
├── 工具管理
├── 技能管理
└── 参数配置
```

知识库侧：

```
智能知识库
├── 库列表
│   ├── 默认模型未就绪提示（只读，不暴露具体模型）
│   └── 创建知识库 → 前置校验 → 通过则打开创建弹窗 / 不通过则阻断说明
└── 文档工作台
```

**职责边界**：

- `模型管理` 负责模型注册与默认模型选择，是唯一配置入口。
- `参数配置` 不再承载默认模型，避免双入口；后续应清理 PRD 中的旧描述。
- `知识库` 只消费默认配置，不展示、不允许修改。

## 5. 对象模型

### 5.1 模型

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识 |
| `name` | string | 模型名称，必填 |
| `capability` | `chat \| embedding \| rerank` | 能力类型，必填，创建后允许修改但需重新校验默认引用 |
| `supportsVision` | boolean | 仅 `chat` 能力有效；标记该对话模型是否支持图片输入（多模态），随对话默认槽位生效 |
| `protocol` | enum | 接口协议，沿用现有三种 |
| `baseUrl` | string | 请求地址，必填 |
| `enabled` | boolean | 是否启用 |

### 5.2 默认配置

```ts
type ModelCapability = 'chat' | 'embedding' | 'rerank'

interface DefaultModels {
  chat: string | null
  embedding: string | null
  rerank: string | null
}
```

约束：

1. 每个槽位只能引用一个**同能力且已启用**的模型。
2. 同一模型不能被两个槽位引用（能力类型本身已保证唯一）。
3. 默认配置与模型列表一起持久化，刷新后保留。
4. 删除模型时同步清理其默认引用；但 UI 上默认模型不可直接删除，正常流程不会产生悬空引用。

### 5.3 就绪判定

```ts
const REQUIRED_CAPABILITIES = ['chat', 'embedding'] as const

const missing = REQUIRED_CAPABILITIES.filter(
  (key) => !defaults[key],
)
const ready = missing.length === 0
```

- `missing.length > 0`：模型管理显示警示条；知识库创建被阻断。
- `missing.length === 0`：显示「默认模型已就绪」。

> 本期将对话、向量两类设为必选，重排设为可选：`REQUIRED_CAPABILITIES = ['chat', 'embedding']`。就绪判定只检查这两类，重排未配置时状态区仍显示「未配置（可选）」，但不会出现警示条，也不阻断知识库创建。

## 6. 交互设计

### 6.1 模型管理 · 默认模型状态区

位置：页面标题与工具栏之间，白底，与列表区分隔。

```
默认模型                                    2/2 必选已配置   [设置默认模型]
对话模型 · 必选   Qwen3.8-Flash-Next
向量模型 · 必选   BGE-M3
重排模型 · 可选   未配置（可选）
```

- 三个槽位横向排列（窄屏自动折为两列），每个槽位包含：能力名称、必选/可选标识、当前模型名或「未配置」、状态点。
- 必选槽位未配置时使用橙色文字与浅橙底；可选槽位未配置时保持中性灰，文案为「未配置（可选）」，不使用警示色。
- 已配置槽位使用常规文字与绿色对勾。
- 右侧「设置默认模型」为描边按钮，始终可点。
- 状态区不占满整屏，高度约 84–96px。

### 6.2 缺失警示条

位于状态区下方、工具栏上方，橙色浅底：

```
⚠ 必选默认模型尚未配置完整（缺少：向量模型）
  未完成配置前，将无法创建知识库；重排模型为可选项，不影响创建。   [立即设置]
```

规则：

1. 只在 `missing.length > 0` 时出现，不自动弹窗。
2. 文案动态列出缺失项；两类必选均缺时显示「对话、向量模型均未配置」。重排缺失不触发警示条。
3. 点击「立即设置」打开默认模型弹窗。
4. 配置完整后警示条立即消失，状态区显示「已就绪」。
5. 同一会话内不重复弹出打扰；提示以页面内常驻条呈现。

### 6.3 设置默认模型弹窗

标题：`设置默认模型`
说明：`默认模型对全部知识库生效。更换向量模型后，已有知识库需要重建索引。`

三个表单项，其中对话、向量为必选，重排为可选：

| 字段 | 必选性 | 控件 | 选项 |
|------|--------|------|------|
| 对话模型 | 必选 | 下拉 | 已启用的 `chat` 模型 |
| 向量模型（Embedding） | 必选 | 下拉 | 已启用的 `embedding` 模型 |
| 重排模型（Rerank） | 可选 | 下拉 | 已启用的 `rerank` 模型；首项为「不启用重排模型（可选）」 |

- 对话、向量下拉首项为「请选择」，重排下拉首项为「不启用…（可选）」；允许暂时留空保存，便于分步配置，状态区会继续显示必选缺失。
- 对话模型下拉中，具备图片理解能力的模型在名称后追加「（多模态）」，与普通对话模型区分；该项只影响图片输入能力，不新增默认槽位。
- 必选能力下没有可用模型时，下拉禁用并提示「暂无可用模型，请先添加」；可选能力显示「暂不启用（可选）」。
- 底部：`取消` / `保存`。保存后关闭弹窗，状态区与警示条同步更新。
- 保存时若向量模型发生变化且原值非空，弹出二次确认：

```
更换向量模型将影响 3 个知识库、128 篇文档的索引。
已有索引不会自动迁移，需要重建后才能按新模型检索。
[取消] [保存并稍后重建]
```

原型中确认后仅保存配置并提示「已保存，请在参数配置中重建索引」，不执行真实重建。

### 6.4 模型卡片

在现有卡片上增加两类信息：

1. 能力标签：`对话` / `向量` / `重排`，位于模型名旁，使用中性浅灰底。
2. 默认标识：被引用为默认时显示蓝色 `默认` 标签，并附 `对话默认` 等 title。

操作约束：

| 操作 | 默认模型 | 非默认模型 |
|------|---------|-----------|
| 启停 | 禁用，title「默认模型不可停用，请先更换默认模型」 | 可切换 |
| 删除 | 禁用，title「默认模型不可删除，请先更换默认模型」 | 可删除 |
| 编辑 | 允许，但修改能力类型时需校验其默认引用 | 允许 |

### 6.5 添加 / 编辑模型

在现有表单中增加「模型能力」下拉，位于模型名称之后：

- 对话模型：用于知识库问答与内容生成。
- 向量模型（Embedding）：用于文档向量化与语义召回。
- 重排模型（Rerank）：用于检索结果重排序。
- 能力选择「对话」时，可勾选 `支持图片理解`，用于图片、扫描件解析与图表问答；该标记随对话模型生效，不单独形成能力类型。

校验：

1. 能力必选。
2. 编辑时若模型正被设为默认，能力类型不可修改（下拉禁用），避免默认引用失效。
3. 其余校验沿用现有规则。

### 6.6 知识库列表 · 前置校验

1. 页面顶部在缺失时显示一条只读提示：

```
必选默认模型尚未配置完成，暂时无法创建知识库，请联系平台管理员。
```

2. 点击「创建知识库」：
   - 已就绪：打开现有创建弹窗，流程不变。
   - 未就绪：不打开创建弹窗，弹出「无法创建知识库」说明弹窗。

阻断弹窗内容：

```
无法创建知识库

知识库需要对话模型与向量模型完成问答与索引，
以下必选默认配置尚未完成：

· 向量模型（Embedding）

请联系平台管理员在「系统设置 → 模型管理」中完成配置。
[知道了] [前往设置默认模型]
```

- 「前往设置默认模型」仅对管理员展示，跳转模型管理并自动打开设置弹窗；普通用户只看到「知道了」。
- 原型默认以管理员视角演示，保留跳转按钮。
- 阻断弹窗不出现具体模型候选，避免业务用户感知技术选型。

### 6.7 知识库创建成功后的继承

创建成功后，知识库记录不需要保存模型快照；运行时始终读取平台默认配置。这样管理员更换默认模型后，所有知识库统一生效（向量模型更换仍需重建索引）。

## 7. 状态与异常

| 场景 | 表现 |
|------|------|
| 对话、向量均缺 | 警示条「对话、向量模型均未配置」；状态区 0/2 必选已配置；建库阻断 |
| 缺少对话或向量 | 警示条列出具体缺失项；状态区 1/2；建库阻断 |
| 必选齐全、重排未配置 | 状态区绿色「2/2 必选已配置」；重排槽位显示「未配置（可选）」；无警示条；建库正常 |
| 某能力无模型 | 弹窗对应下拉禁用，提示先添加模型 |
| 默认模型被停用 | 不允许，按钮禁用并说明原因 |
| 默认模型被删除 | 不允许；若通过数据导入产生悬空引用，状态区按「未配置」处理 |
| 更换向量模型 | 保存前二次确认，说明影响面与重建要求 |
| 刷新页面 | 模型与默认配置从 localStorage 恢复，状态一致 |
| 普通用户访问 | 不展示模型管理入口；知识库侧只显示「请联系管理员」 |

## 9. 数据与持久化

原型使用 localStorage 保存一份注册表：

```ts
const STORAGE_KEY = 'ikb-model-registry-v1'
const REGISTRY_VERSION = 3

interface ModelRegistry {
  version: number
  models: ModelItem[]
  defaults: DefaultModels
}
```

- 存储键沿用 `ikb-model-registry-v1`，通过 `version` 字段做结构演进，避免换键导致旧数据丢失。
- v3 迁移规则：历史数据中 `capability: 'vision'` 的模型统一转为 `capability: 'chat'` 且 `supportsVision: true`；同时移除历史 `defaults.vision`，多模态能力随对话模型默认值生效。
- 仅 v1 升级到 v2 时补入缺失的内置视觉示例模型；v2 及之后的升级只做字段迁移，不会重新加入用户已删除的模型。
- 读取失败、`version` 缺失或结构不合法时回退到内置 Mock；部分字段缺失时按空值兜底，不阻断页面渲染。
- 模型管理与知识库列表通过同一个 hook 订阅，任一处修改后另一处即时同步。
- 真实实现应改为后端接口：`GET/PUT /api/models`、`GET/PUT /api/models/defaults`，并做服务端唯一性校验。

## 10. 验收标准

1. 进入模型管理且对话/向量任一必选模型缺失时，页面顶部出现警示条，列出缺失项，且不自动弹窗。
2. 默认模型状态区固定展示对话、向量、重排三个槽位；对话、向量标记为必选，重排标记为可选。
3. 点击「设置默认模型」可选择三类模型并保存；保存后状态区、警示条即时更新。
4. 必选模型齐全时，状态显示「2/2 必选已配置」且为绿色；重排未配置显示「未配置（可选）」，不出现警示条。
5. 模型卡片展示能力标签；对话模型支持图片理解时追加 `多模态` 标识，默认模型展示 `默认` 标识，且启停、删除入口被禁用并有原因提示。
6. 添加/编辑模型必须选择能力类型；编辑默认模型时能力类型不可改。对话模型可勾选「支持图片理解」，切换为其他能力时该标记自动清除。
7. 仅必选模型（对话、向量）齐全时，知识库列表无阻断提示，创建流程正常；重排缺失不阻断。
8. 对话/向量缺失时，点击「创建知识库」出现阻断弹窗，仅列出缺失的必选模型，不打开创建弹窗。
9. 阻断弹窗的「前往设置默认模型」可跳转模型管理并打开设置弹窗。
10. 更换向量模型时出现索引重建确认；更换对话或重排模型不出现。
11. 刷新页面后模型列表与默认配置保持一致。
12. 内置技能数量仍为 42，工具管理空态与现有工具栏布局不被破坏。
