## 1. 设计结论先行

1. **列表 + 一个文档工作台**：默认进入库列表，点卡片进入当前库的文档工作台。进入后固定当前库，不切库，也不设概览 / 分块 / 检索测试 / 设置，只展示文档卡片与列表。平台不允许面包屑，库内层级用「标准顶部导航（返回 + 知识库详情）+ 固定库名」表达。
2. **主体不是文件列表，是"入库流水线"**：建库 → 上传 → 解析 → 切分 → 索引 → 检索验证，每一步都要在界面上有可观测的状态和可回退的动作。
3. **切分是核心资产**：库级默认 → 文档级覆盖 → 分块级人工修正，三级对象 + 继承关系，而不是一个参数表单。
4. **参数改动必须显示影响面**："将影响 128 篇文档，需重新解析"+ 一键重解析；否则参数页是危险的。
5. **不暴露算法**：策略只给四档中文名（自动 / 按标题 / 按语义段落 / 固定长度），`separators`、token 换算、校验器降级全部收进「高级」。
6. **不暴露模型**：模型、向量引擎、Embedding、重排模型、配额对普通用户完全不可见。用户只回答"传什么文档、怎么切、怎么搜"，不回答"用哪个模型"；所有模型选择是平台管理员的运维决策。

### 1.1 与调研文档的偏差（有意为之）

| 调研建议 | 本次方案 | 原因 |
|---------|---------|------|
| 8 个 Tab（含问答/FAQ/Wiki） | 5 个 Tab | 已确认不做 FAQ/Wiki/问答，页面量与叙事聚焦 |
| 建库 6 步向导 | 单步（可选高级设置） | 模型/向量引擎/Embedding 属平台配置，由管理员在「模型管理」统一设定；配额在「参数配置 · 容量与配额」维护；建库只需基础信息，分块默认使用内置推荐预设，可展开「高级设置」调整 |
| 知识图谱、评估、多租户 | 不做 | B 端后台不可见，且无对应消费场景 |
| 概览含"被引用应用" | 不做 | 已确认纯知识管理 |

- **页面顶部导航**：40px 高，左侧返回图标回到库列表，标题为「知识库详情」；不使用 `A / B` 面包屑。

- **URL / 状态**：单入口应用内部状态切换（沿用现有 `activePage` 模式），不改路由层级。

## 3. 对象模型与配置继承

### 3.1 四级对象

| 层级 | 对象 | 关键字段 | 说明 |
|------|------|---------|------|
| L1 | 知识库 Library | 名称、描述、类型、默认切分配置、索引开关、文档数/分块数 | 库创建人可维护分块与解析富化；向量引擎、Embedding、配额**不出现在用户界面**，由平台统一下发 |
| L2 | 文档 Document | 文件名、类型、大小、来源、解析器、解析状态、覆盖配置、标签、块数、更新时间 | 可覆盖库级切分配置 |
| L3 | 分块 Chunk | 序号、内容、字符数、章节路径、来源页/段落、状态（启用/停用）、版本 | 可人工修正 |
| L4 | 任务 Task | 类型（解析/切分/索引/重解析）、进度、耗时、失败原因 | 文档列表与概览共用 |

### 3.2 配置继承规则

```
库级默认  ──继承──>  文档级覆盖（可选）  ──产出──>  分块
```

| 配置项 | 库级 | 文档级可覆盖 | 改动后影响 |
|-------|------|-------------|-----------|
| 切分策略（四档） | ✅ | ✅ | 该库/该文档需重解析 |
| 块大小 / 重叠 / 分隔符 | ✅ | ✅ | 同上 |
| 父子块增强、token 上限、语言 | ✅ 高级 | ❌ | 全库需重解析 |
| 解析器（自动/OCR/纯文本） | ✅ 默认 | ✅ | 仅该文档 |
| 摘要生成 | ✅ 默认开 | ✅ | 仅该文档，不触发重切分 |
| 索引开关（向量/关键词） | ✅ | ❌ | 全库需重建索引 |
| 向量引擎、Embedding、重排模型 | 全局（管理员） | ❌ | 普通用户不可见、不可选；在「系统设置 → 模型管理」配置，变更后由平台侧重建索引并公告 |
| 容量与配额（单库文档数 / 存储 / 单文件大小 / 人均库数） | 全局（管理员） | ❌ | 普通用户不可见；在「系统设置 → 参数配置 · 容量与配额」配置，只影响新建库与新上传文件 |

**继承的可视化**：文档详情里每个可覆盖项后面标注 `继承自库` / `已覆盖`，覆盖后出现「恢复继承」。

### 3.3 模型与引擎的可见性（定稿）

**原则：业务用户的知识库界面里，不出现「模型」「向量引擎」「Embedding」「重排模型」任何一个词，也不出现相关只读字段、链接或提示。**

| 层 | 归属 | 用户可见性 |
|----|------|-----------|
| 平台模型（对话 / Embedding / Rerank 接入、密钥、默认模型） | 平台管理员 | 全部收在「系统设置 → 模型管理」，普通用户无入口 |
| 平台容量与运行（配额、存储、解析并发、保留策略） | 平台管理员 | 全部收在「系统设置 → 参数配置」，普通用户无入口 |
| 库级绑定（某库用哪个 Embedding / 向量库） | 平台管理员 | 不绑定到库、不在库内展示；全局默认即唯一事实 |
| 检索行为（TopK、阈值、向量/关键词开关、重排开关） | 库成员 | 可见可调，属于"怎么搜"，不涉及"用哪个模型" |

配套规则：

- **建库弹窗**只有基础信息，分块默认使用内置推荐预设；可展开「高级设置」自定义，也可稍后在库内「库设置」调整。**设置·基础信息**只有库名、描述、类型、创建时间，不出现模型/引擎行，也不放"查看全局配置"链接（普通用户点了也进不去）。
- **管理员页面分工**：模型只在 `系统设置 → 模型管理` 维护；`系统设置 → 参数配置` 为单页，只维护运行与存储、容量配额与保留策略，**不提供默认分块、解析富化或模型选择**。该页仅 `admin` 可见。
- **变更由平台发起**：Embedding / 向量库变更会导致已有索引失效，属于管理员操作。切换默认模型时先展示影响面（受影响知识库与文档数），由管理员选择「仅切换默认，稍后重建」或「切换并立即重建」；不向业务用户弹出迁移决策。
- **例外只走管理员**：未来若确需"按库差异化模型"，由管理员发布「模型方案」（名称 + 对话/Embedding/重排组合）并授权到部门，配额仍由管理员在参数配置统一维护；用户最多选择一个已授权方案，仍看不到具体模型名；在该需求被正式提出前不实现。

### 3.3.1 参数配置单页边界

**原则：一个侧栏入口、一个滚动页，按「运行与存储」与「容量与配额」两段分组，不把模型、分块或解析富化塞进来。**

| 区块 | 管什么 | 典型字段 | 生效方式 |
|-----|--------|----------|----------|
| 运行与存储 | 平台运行资源与存储运维 | 运行资源（CPU / 内存）、数据库与对象存储用量、会话清理、审计保留 | 管理员保存后对平台生效；清理与保留策略作用于后续任务 |
| 容量与配额 | 知识库容量边界 | 单库文档数、单库存储、单文件大小、单用户建库数 | 保存后立即生效；配额约束新建库与新上传，不追溯已建库、不删除已有文件 |

补充边界：

- **仅管理员可见**：页首说明「管理运行资源、审批策略与审计留存等平台配置」；不设 Tab，不使用「知识库配置」分组。
- **不提供默认分块与调整权限**：分块是库级内容策略，由库创建人在创建弹窗与库内「库设置」维护；平台只保留内置推荐预设（自动 512 / 80），不提供可编辑默认值，也不设「允许库创建人调整」开关。
- **不提供解析与富化默认值**：AI 问题生成的开关、数量与要求同样由库创建人在「库设置」维护，保存后仅对后续上传与重新解析生效。
- **模型不在此页**：对话、Embedding、Rerank 的默认模型与接入信息只在「模型管理」维护；缺少必填默认模型时由模型管理页统一提示。
- **不做检索参数**：TopK、相似度阈值、重排开关属于库成员的检索行为，不上升为平台配置，避免一个库的检索策略被全局覆盖。
- **配额不追溯**：下调配额只影响后续新建与上传；已有库和文件保留，由库创建人自行清理。

### 3.3.2 默认向量模型切换的迁移与重建

**原则：默认模型只影响新建库与新上传；已有索引必须显式迁移，不允许静默混用两套向量。**

| 环节 | 行为 |
|------|------|
| 影响预判 | 保存默认模型前，若目标 Embedding 与当前默认不同，计算受影响库与文档数；空库不计入影响面，直接跟随新模型 |
| 影响确认 | 弹窗列出受影响知识库、文档数、旧/新模型名；提供两个动作：「仅切换默认，稍后重建」与「切换并立即重建」。无受影响库时直接保存，不弹迁移确认 |
| 稍后重建 | 受影响库标记为「待重建」，索引信息保留旧模型名与历史时间；库列表与工作台持续提示旧模型，直到重建完成 |
| 立即重建 | 切换默认后立即把受影响库置为「重建中」，进度从 0 开始，完成后写入新模型名与索引时间 |
| 单库/批量重建 | 库列表卡片提供「重建」，顶部待重建提示条提供「全部重建」；工作台提供「重建索引」。确认弹窗展示 KB 数、文档数与目标模型 |
| 状态与恢复 | 重建中禁用重复发起；完成后清除旧模型提示。空库只更新绑定模型，不进入待重建/重建中状态 |
| 失败与回退 | 重建失败保留旧索引可用性与「待重建」标记，可重试；不支持自动回退默认模型，需管理员再次切换 |

**边界**：迁移只重建索引，不重新解析、不改分块、不删除文档；重建期间检索使用旧索引，结果中标注当前索引模型。配额与计费不在本期实现。

### 3.4 分块与解析富化的权限边界（定稿）

**原则：产品给推荐预设，库创建人管当前库，上传者管单次覆盖。平台不维护可编辑的知识库默认值。**

| 配置 | 谁决定 | 在哪里 | 说明 |
|------|--------|--------|------|
| 推荐分块预设 | 产品内置 | 创建弹窗 / 库设置 | 自动 512 / 80，只读展示，可一键恢复 |
| 当前库分块策略 / 块大小 / 重叠 | 库创建人 | 创建弹窗 · 高级设置、库设置 · 分块 | 受 128–2048 / 重叠 ≤ 块大小一半约束；保存后对后续上传与重新解析生效 |
| 当前库解析与富化 | 库创建人 | 库设置 · 解析与富化 | AI 问题生成开关、每分块 1–10 个、要求 ≤4000 字；默认开启、3 个/块 |
| 单次上传覆盖 | 上传者 | 上传文档第 2 步 | 仅影响本次文档，可恢复继承库级配置 |
| 模型（对话 / Embedding / Rerank） | 平台管理员 | 系统设置 · 模型管理 | 业务用户不看见、不可选、不感知；缺失必填默认模型时阻止建库并引导管理员配置 |
| 容量与配额 | 平台管理员 | 参数配置 · 容量与配额 | 约束新建库与新上传文件；不追溯已有库，不因下调配额删除已有内容 |

补充规则：

- 建库时**不强制**用户做切分决策：高级设置默认收起，摘要展示「自动 · 512 / 80 tokens」。
- 库设置里明确区分「已自定义」与「使用推荐配置」；点「恢复推荐值」清空库级覆盖，回到内置预设。
- 分块与富化是**库级内容策略**，不是用户个人偏好：同一库的所有成员看到同一套配置，避免检索结果不一致。
- 产品调整推荐预设不回溯已建库；已建库保持原值，由库创建人手动恢复推荐值。

### 3.5 状态机

**文档状态**（原型收敛为 6 个 UI 状态）：

| 状态 | 进入条件 | 是否可检索 | 退出 |
|------|----------|------------|------|
| 排队中 | 文件已入库，等待解析 worker | 否 | 开始解析 → 解析中 |
| 解析中 | 解析管线执行中（读取 / 分块 / 向量化） | 否；重解析时保留旧版本可检索 | 主解析完成 → 优化中；异常 → 解析失败 |
| 优化中 | 主解析与向量索引已完成，摘要 / AI 推荐问题仍在生成 | **是** | 富化完成 → 已解析；富化失败不回退解析状态 |
| 已解析 | 解析与富化全部完成 | 是 | 库级分块或富化配置变更 → 需重新解析 |
| 解析失败 | 任一解析阶段失败 | 有上一次成功结果时可检索旧版本 | 重新解析 → 排队中 |
| 需重新解析 | 库级分块 / 富化配置已变更，当前分块与配置不一致 | 是，继续使用旧分块与旧索引 | 重新解析 → 排队中 → 已解析 |

补充规则：

- **「优化中」必须独立存在**：AI 问题生成默认开启，若把富化并入「解析中」，会出现"文档明明已经能搜到，却显示还在解析"的误导。状态标签用「优化中」，详情提示「已完成解析并可检索，正在生成摘要与推荐问题」。
- **失败要带阶段**：记录 `docreader / chunking / embedding / multimodal / postprocess` 中失败的一步与原因，详情浮层展示「解析失败（分块阶段）：原因」，操作仍只保留「重新解析」。
- **「需重新解析」是产品态，不是解析引擎态**：只由库级配置变更触发；重新解析完成前不删除旧分块、不中断检索，完成后原子切换。
- **裁剪项**：`疑似卡住`、`取消解析`、`删除中`、`草稿`、文档级启停不进入本期原型。排队超过阈值只在详情里提示"处理时间较长"，不新增第 7 个状态。

**索引状态**（独立于文档状态，展示在库维度）：`未索引 → 索引中 → 已索引`，失败为 `索引失败`；默认向量模型变更后追加 `待重建（stale，保留旧模型）` 与 `重建中（rebuilding(targetModel)）`，完成后回到 `已索引` 并写入新模型。索引的 `待重建` 与文档的 `需重新解析` 是两件事：前者换向量模型，后者改分块 / 富化配置，文案和入口不得混用。

**分块状态**：`启用 / 停用`（停用的块不参与检索，但保留在列表，可恢复）。

## 4. 页面设计

### 4.1 文档工作台（库内唯一页面）

**目标**：进入库后直接管理文档，不经过概览或设置页。

**布局**（自上而下）：

1. 标准顶部导航：返回 + `知识库详情`。
2. 库标题区：固定库名 + `N 篇文档` + 知识库描述，不提供切库。
3. 工具条：左侧为「上传文档」分裂按钮——主按钮直接打开文件选择器，右侧箭头展开「上传文件夹」与上传限制说明；右侧状态筛选（全部 / 排队中 / 解析中 / 优化中 / 已解析 / 需重新解析 / 失败）与名称搜索合并为一个控件，再接卡片/列表切换。
4. 文档卡片：类型图标、文件名、格式与大小、分块数、解析状态、更新时间、右上角复选框；分块数只在已生成后展示，排队中 / 解析中 / 失败不显示该段，避免把尚未生成的分块误报为 0（列表对应列显示 `—`）。
5. 文档列表：复选框、文件名、大小、状态、分块数、更新时间、操作；文件名与更新时间支持点击列头排序，失败与需重新解析的行在操作列直接露出「重新解析」，更多菜单保留下载、重新解析、删除文档（删除需二次确认，并同步移除分块）。
6. 卡片与列表底部均有分页：总数、每页条数（6 / 12 / 24）、上一页/下一页、当前页/总页数；切换筛选、搜索、排序或每页条数后回到第 1 页。
7. 选中后底部浮出批量操作条：已选数量、全选本页、取消选择、批量下载、重新解析、批量删除。
8. 点击文档卡片或列表行：打开文档详情浮层，展示基本信息（上传时间 / 类型 / 大小 / 解析状态 / 分块数 / 所属库）、可编辑摘要和文件内容；文件内容默认原文预览，可切换「查看分块」，片段支持编辑正文、恢复原文、启用/关闭，关闭的片段标注「未启用」且不参与检索。
9. 空库：居中空态 + 「上传文档 / 上传文件夹」+ 支持格式与大小说明；筛选无结果：清空筛选。
10. 拖拽文件到工作台任意位置即可上传，拖入时显示整页投放遮罩；遮罩只做投放提示，不阻塞任务中心与列表操作。

**不做**：概览、独立分块页、切分参数调整、检索测试、库设置、库切换；分块能力只保留在文档详情内，用于查看、编辑和启停片段。

### 4.2 文档

**目标**：管理入库对象，看清每篇文档卡在哪一步。

**布局**：

1. 工具条：状态筛选（全部 / 排队中 / 解析中 / 优化中 / 已解析 / 需重新解析 / 失败）+ 搜索 + 「上传文档」分裂按钮。
2. 表格列：

| 列 | 内容 | 交互 |
|----|------|------|
| 文件名 | 图标（按类型）+ 名称 | 点击打开文档详情浮层；列头可排序 |
| 大小 | 人类可读 | — |
| 解析状态 | 状态标签；失败附阶段与原因 tooltip；优化中标注「可检索」 | 失败 / 需重新解析可「重新解析」 |
| 分块数 | 已生成分块数；排队中 / 解析中 / 失败显示 `—` | — |
| 更新时间 | `YYYY-MM-DD HH:mm` | 列头可排序，默认倒序 |
| 操作 | 行内「重新解析」（仅失败 / 需重新解析）+ 更多：重解析、下载原文、删除 | 删除二次确认（级联删除分块） |

3. 排序：文件名按中文拼音升序 / 降序，更新时间按时间升序 / 降序；再次点击同一列头切换方向，切换排序后回到第 1 页。
4. 批量操作（选中后浮出）：批量重解析、批量删除、批量打标签。
5. **上传任务中心**：右下角浮层，聚合展示当前会话的上传与处理任务；支持收起为标题栏；关闭后整个浮层消失，不再出现可恢复的浮标，任务继续在后台执行，进度可在文档列表查看。

**可检索性口径**：排队中、解析中不可检索；优化中开始即可检索，列表与详情都要明确提示，避免用户重复上传。重解析与配置变更期间保留旧版本可检索，新结果就绪后切换，不出现"整库暂时搜不到"的空窗。

**文档详情（居中浮层，最大宽 1120）**：

- 头部：文件类型图标 + 文件名 + 下载 / 重新解析 / 关闭。
- 基本信息：上传时间、类型、大小、解析状态、分块数、所属知识库。
- 摘要：只读展示，支持编辑保存与重新生成。
- 文件内容：标题旁展示总片段数，默认「预览」原文，可切换「查看分块」。
- 片段卡片：头部为 `片段 N`，操作含编辑、恢复原文、启用/关闭；正文只读展示，编辑时切换为文本域；关闭后卡片降透明度并标注「未启用」，提示不参与检索。
- 不提供解析时间线、切分配置、独立分块 Tab、原文-分块对照。

**空态**：无文档 → 「上传文档」+ 支持格式说明；筛选无结果 → 清空筛选。

### 4.3 分块（二期能力，本期不单独提供）

> 一期只在文档详情内提供「查看分块」与片段编辑、启停；以下独立分块页为二期设计，不在一期导航和页面中出现。

**目标**：看切分质量，并能在不重新解析的前提下修好个别块。

**布局**：

1. 顶部筛选：文档（下拉，含"全部文档"）、块状态（启用/停用）、长度区间（过短 <100 / 正常 / 超长 >2×块大小）、搜索块内容。
2. 质量条（全库或当前筛选范围）：块总数、平均长度、过短占比、超长块数；超阈值给出建议文案 +「去调参数」。
3. 块列表（虚拟滚动，卡片式而非表格，便于读长文本）：

| 区域 | 内容 |
|------|------|
| 块头 | `#序号` · 所属文档 · 字符数 · 状态标签 · 操作（编辑 / 停用 / 拆分 / 合并下一块 / 历史） |
| 上下文头 | 章节路径（如 `3.2 配置分层 › 3.2.1 继承规则`），灰色小字，说明"不参与检索计分" |
| 正文 | 最多 6 行，超出「展开」；等宽字体可选 |
| 脚注 | 来源位置（第 3 页 / 段落 12）、版本号 |

4. 右侧滑出「切分预览」面板（复用同一块卡片组件，只读 + 统计）：修改参数后实时显示预估块数、平均长度、告警；底部「应用并重解析」。

**编辑交互**：

- 编辑：行内展开 textarea，保存后版本 +1，块头显示「已人工修改」标记。
- 拆分：光标位置拆分，两块都保留上下文头。
- 合并：与下一块合并，上下文头取父级公共部分。
- 停用：灰显 + 删除线，不参与检索；可恢复。
- 历史：抽屉列出该块版本（时间、操作人、差异高亮），可回滚。

**空态**：无分块 → 引导"先去解析文档"；筛选无结果 → 清空筛选。

### 4.4 检索测试（库内最小闭环）

**目标**：让库成员在不离开工作台的情况下验证"当前索引能不能召回、召回得准不准"，并可直接回到原文。

**入口与布局**：工作台头部「召回测试」按钮，打开 900px 居中弹层。弹层自上而下为：

1. 顶部信息：知识库名、当前索引模型、文档数；索引待重建/重建中时给出状态提示，不阻塞测试。
2. 查询区：多行输入框，默认示例 `容器云集群扩容失败怎么排查`，`⌘/Ctrl + Enter` 执行；下方 4 条示例 query 快捷填充。
3. 参数条：TopK（1/3/5/10/20，默认 5）、相似度阈值（默认 0.3）、重排开关（无默认重排模型时禁用并说明）。
4. 结果区：按得分降序的命中分块卡片，展示排名、文档名/标题、得分、三行高亮正文、命中策略、token 数与 AI 问题标记；「查看原文」关闭弹层并打开对应文档详情。
5. 底部：`命中 N 个分块 · 候选 M · 耗时 Xms · 已重排/未重排`，附"结果为演示数据"说明。

**与早期方案的取舍**：本期不拆向量/关键词两路结果，不展示 RRF 融合分与重排分构成，不做"保存为默认""标记不相关""查看上下文块"；统一以一个混合得分呈现，重排只体现为开启后的分数与排序变化。TopK 默认 5 而非 8，降低演示时的信息密度。

**Mock 规则**：基于 12 条固定分块与确定性打分函数（中文二元组 + 英文词命中密度，标题权重 0.35、正文 0.65，精确 query 加分，重排叠加标题密度），保证同一 query 稳定复现；加载态固定 320ms。

**边界**：检索参数只在本次测试生效，不写回库设置，也不上升为平台配置；未实现检索评估集与历史查询。

### 4.5 库设置（单弹窗，两段式）

> **一期范围**：工作台内不设设置子页，统一用「库设置」弹窗承载，仅两段——`分块` 与 `解析与富化`。基础信息、成员与权限、活动日志沿用现有入口，不在本期改造范围。

「库设置」由库创建人打开，宽 640px；顶部展示库名，两段各自带状态徽标，底部「取消 / 保存」。所有改动**保存后对后续上传与重新解析生效**，不改写已入库内容。

| 段落 | 字段 / 内容 | 关键交互 |
|------|------------|---------|
| 分块 | 四档策略卡片（自动 / 按标题层级 / 按语义段落 / 固定长度）、块大小（数字输入，128–2048）、重叠（数字输入，0–块大小一半） | 徽标区分「使用推荐配置 / 已自定义」；「恢复推荐值」清空库级覆盖回到内置预设；选策略自动带出该档默认值，仍可微调；越界就地报错，不关闭弹窗 |
| 解析与富化 | AI 问题生成开关、每分块问题数（1–10）、生成要求（≤4000 字，带占位示例） | 同样有「使用推荐配置 / 已自定义」与「恢复推荐值」；关闭开关后数量与要求置灰；页内提示「每个分块调用一次模型，数量越多耗时与成本越高」 |

**分块参数的四档文案**：

| 档位 | 文案 | 适用 | 推荐参数 |
|------|------|------|---------|
| 自动（推荐） | 按文档结构自动选择 | 通用 | 512 / 80 |
| 按标题层级 | 以 Markdown/Word 标题为边界 | 手册、规范、技术文档 | 768 / 80 |
| 按语义段落 | 以分页符、章节标记、空行为边界 | OCR PDF、书籍、扫描件 | 768 / 120 |
| 固定长度 | 按字符数硬切 | 无结构长文、日志导出 | 1024 / 150 |

> 推荐预设是**产品内置常量**，不提供管理员可编辑的默认值，也不存在「继承平台策略 / 恢复继承」；库创建人改的是当前库，点「恢复推荐值」即回到内置预设。产品日后调整预设不回溯已建库。二期若设置项继续增多，再拆为 `基础信息 | 分块 | 索引 | 成员与权限 | 活动日志` 子 Tab；模型/引擎的只读值始终不出现。

## 5. 关键流程

### 5.1 新建知识库（单步弹窗 + 可选高级设置）

**入口**：库列表工具栏「创建知识库」。弹窗宽 560px，点遮罩不关闭；右上角 ×、底部「取消」、Esc 均可退出。**已填写名称或描述时退出需二次确认**，避免误丢输入。

```text
[创建知识库 · 单步]
   ├─ 名称 / 描述 / 类型
   ├─ 分块方式：默认摘要（自动 · 512 / 80）
   │     └─「高级设置」展开四档策略 + 块大小 / 重叠（始终可编辑）
   └─ 创建后进入知识库（默认勾选）
        │
        └─ 创建（校验通过）→ 提交中 → 插入列表首卡 + 轻提示
                                      └─（默认）进入空库文档页
```

**基础信息**

| 字段 | 控件 | 必填 | 规则与默认 |
|------|------|------|-----------|
| 知识库名称 | 单行输入，自动聚焦 | 是 | 去首尾空格后 2–40 字符；库内唯一（忽略大小写）；实时字数 `n/40` |
| 描述 | 多行输入，3 行 | 否 | ≤200 字，实时字数；占位提示写“放什么、给谁用” |
| 类型 | 固定卡片（非下拉） | — | 仅“文档库”，标注“当前仅支持”；支持 PDF / Word / Markdown / TXT，上传后自动解析 |
| 分块方式 | 摘要行 +「高级设置」 | — | 默认展示推荐预设「自动 · 512 / 80 tokens」，高级设置始终可展开调整 |

- 创建人不在表单里选，默认当前登录用户，创建后即为该库负责人；成员邀请在「设置 · 成员与权限」。
- 不提供其它类型的置灰选项：未定能力不提前占位，避免“即将支持”的承诺。
- 名称不合法时不提交，输入框标红并在下方给单行错误；用户修改即清除错误。
- 向导内不出现模型、向量引擎、Embedding 等任何字段，也不提示“将使用某模型”，建库时静默使用管理员设定的默认模型。

**高级设置（可选）**

默认收起，不强制用户做切分决策。展开后四选一，复用 §4.5 的四档：

| 档位 | 卡片说明 | 默认块大小 / 重叠 |
|------|---------|------------------|
| 自动（推荐） | 按文档结构自动选择 | 512 / 80 |
| 按标题层级 | 以 Markdown / Word 标题为边界 | 768 / 80 |
| 按语义段落 | 以分页符、章节标记、空行为边界 | 768 / 120 |
| 固定长度 | 按字符数硬切 | 1024 / 150 |

- 选中策略后自动填入该档默认值，用户仍可改「块大小」与「重叠」：块大小 128–2048 整数，重叠 0–块大小的一半。
- 参数非法时就地报错，不关闭弹窗、不丢已填内容；若在收起状态下提交，参数非法会自动展开高级设置。
- 页内注明：更改仅作用于本库，上传文档时仍可临时覆盖；入库后调整需重新解析。

**校验与边界**

| 场景 | 触发 | 表现 |
|------|------|------|
| 名称为空 / 全空格 | 创建 | 聚焦名称，提示“请输入知识库名称” |
| 名称长度不在 2–40 | 创建 | 提示“名称需为 2–40 个字符” |
| 名称与已有库重复 | 创建 | 提示“该名称已被使用，请换一个名称”；提交时再校验一次，若期间被占用则留在弹窗 |
| 块大小非整数 / 越界 | 创建 | 提示“请输入 128–2048 之间的整数” |
| 重叠为负 / 超过块大小一半 | 创建 | 提示“请输入不小于 0 的整数”/“重叠不能超过块大小的一半” |
| 重复点击“创建” | — | 按钮进入“创建中…”并禁用，防重复提交 |
| 有内容时关闭 | × / 取消 / Esc | 二次确认“放弃创建？已填写的内容不会保留。”，可继续编辑 |
| 创建成功 | — | 新库插到卡片墙首位（0 篇、当前用户、当天日期），轻提示“知识库「X」已创建”；默认进入该库空态概览 |
| 创建成功但未勾选进入 | — | 留在列表，清空搜索词并回到第 1 页，保证新卡片可见 |

**关键文案**

| 位置 | 文案 |
|------|------|
| 标题 / 副标题 | 创建知识库 / 填写基础信息即可创建，分块方式使用推荐预设。 |
| 分块摘要 | 自动 · 512 / 80 tokens |
| 高级入口 | 高级设置 |
| 名称占位 | 例如：产品文档库 |
| 描述占位 | 说明这个库主要放什么内容、给谁用，方便同事搜索。 |
| 主按钮 | 创建 / 创建中… |
| 成功提示 | 知识库「{名称}」已创建 |
| 放弃确认 | 放弃创建？已填写的内容不会保留。 / 继续编辑 / 放弃 |

**原型实现约定**：弹窗校验与重名判断均为前端 Mock；知识库记录、库级分块与富化配置保存在 localStorage，切页不丢、刷新恢复。分块默认「自动 512 / 80」，创建时按弹窗内参数落库；容量配额在「参数配置 · 容量与配额」维护，建库与上传按当时配置校验。

### 5.2 上传与入库（直接上传 + 任务中心）

**交互流程**

1. 点击「上传文档」主按钮 → 直接打开系统文件选择器，选完即开始校验与上传；点击右侧箭头可「上传文件夹」，也可以把文件直接拖拽到工作台任意位置。
2. 先做一次轻量预检：格式、单文件大小、同名冲突。通过的文件立即插入文档列表顶部，初始状态「排队中」；未通过的文件不进入队列，聚合展示在「部分文件未添加」弹层中，逐条说明原因。
3. 若同一批既有通过也有未通过，通过的文件照常开始处理，弹层标题说明「已开始处理 N 个；以下 M 个未添加」，用户关闭后可在任务中心继续查看进度。
4. 右下角弹出**任务中心**，标题显示整体进度（如「正在入库 3/4」），下方一行汇总「可检索 3 · 处理中 1 · 失败 0」。
5. 每行展示文件名、大小、当前状态与右侧指示：排队中为时钟、解析中为转圈、可检索为绿勾、失败为红色感叹号。
6. 解析期间底部提示「文件已全部上传，处理在后台继续，可以放心离开此页面」；全部结束后改为「可在文档列表中查看并检索」。
7. 任务中心可收起为标题栏（只保留标题与状态）；点击关闭则整个浮层消失，右下角不再出现可恢复的浮标，任务继续在后台执行，进度在文档列表可见，再次上传时重新展开。

**状态流转**

`排队中 → 解析中 → 优化中（可检索）→ 已解析`。失败进入「解析失败」，在该行展示红色状态，用户到文档列表重新解析；任务中心不内嵌重试，避免与列表操作重复。

**规则**

- **支持格式**：PDF、Word（`.doc` / `.docx`）、Excel（`.xls` / `.xlsx`）、Markdown（`.md` / `.markdown`）、TXT。一期不接收图片、网页、音视频与压缩包，避免把“能上传”误当成“能解析”。
- **单文件上限 100MB**，实际阈值以「参数配置 · 容量与配额」为准；超限文件不进入队列。
- **单次建议不超过 50 个**，不做硬性批量上限。超过 50 个仍可上传，但提示「数量较多，建议分批查看处理进度」；这样既不阻塞整目录导入，又避免任务中心一次涌入过多行。
- **同名文件默认跳过**，包括与库内已有文档重名、以及同一批次内重名；如需覆盖，先删除旧文档。
- 上传前不做逐文件解析器 / 切分覆盖：库级「参数配置」就是唯一事实来源，个别文件需要不同切分时，先改库设置再重解析。
- 文件夹上传按所选目录内的文件批量加入，当前不保留目录层级，也不在列表里展示来源路径；目录内不支持的文件同样进入预检弹层。
- 目标并发为 3 个文件，超出部分显示「排队中」；原型用错峰定时器模拟状态推进，不实现真实 worker。
- 任务中心最多同时展示 4 行，超出滚动；不自动消失，由用户关闭，确保失败与完成结果可回看。
- 列表按更新时间倒序展示；文件名 / 更新时间支持列头排序，切换排序回到第 1 页。

**竞品取舍（RAGFlow）**

借鉴三点：上传限制前置说明、拖拽投放、批量预检与逐条原因。以下不照搬：

- 不采用「单次 32 个 / 总大小 1GB」的硬上限，否则整目录导入会被直接打断；我们只给 50 个的软提示。
- 不增加「创建时解析」开关，避免引入“已上传未解析”的第七种状态与两段式操作；当前自动解析更符合知识库的默认预期。
- 不做“上传弹窗 + 保存”的二次确认，保留直接上传 + 常驻任务中心的低打断路径。
- 不在列表展示解析器名称（如 RAGFlow 的 `General`），分块策略放在库设置与文档详情，列表只回答“现在能不能用、卡在哪一步”。

**为什么不做上传向导**

WeKnora 的实际做法是选完文件立即入库，把解析进度放到右下角常驻面板。这样上传动作只有一步，用户可以在等待时继续浏览文档，失败也能在列表里定位。三步抽屉适合"上传前必须逐文件确认参数"的场景，但我们的切分与富化已收敛为库级推荐配置，再让用户每次选择只会制造两套配置来源。

### 5.3 调参 → 重解析（二期，危险动作）

库设置·分块 改动 → 底部出现影响条「将影响 128 篇文档，需重新解析」→ 保存时二次确认（选项：仅保存 / 保存并立即重解析 / 保存并在低峰重解析）→ 文档状态批量转「需重新解析」，旧分块继续可检索 → 文档列表顶部出现批量条「128 篇待重新解析 · 全部重解析」。

### 5.4 检索验证闭环（一期最小）

库内「召回测试」输入 query → 查看命中分块与得分 →「查看原文」回到文档详情核对内容 → 调整 query / TopK / 阈值 / 重排后重跑 → 对比命中结果变化。

一期闭环止于"发现结果不理想并回到原文"，不在弹层内做分块级编辑。定位到具体分块、拆分/停用分块、以及"改完分块立即重跑对比"的完整链路，依赖独立分块页与原文-分块对照，统一放到二期。

## 6. 组件映射与素材复用

| 需求 | 来源 | 说明 |
|------|------|------|
| 平台外壳（顶栏 + 侧栏） | `@/lib/platform-shell` `PlatformShell` / `SideNav` | 沿用，不改 |
| 九宫格产品导航 | `@/lib/product-nav` `ProductNav` + `CALSPEED_PRODUCT_NAV` | 沿用，不改 |
| 按钮/输入/下拉 | 页内 Tailwind 原子类 | 项目无 UI 库，保持现有写法 |
| 表格 | 自建 `DataTable`（`_shared.tsx`） | 支持列配置、空态、批量选择条 |
| 状态标签 | 自建 `StatusTag` | 6 种解析状态 + 3 种索引状态，统一色板 |
| 文档详情浮层 | 页面内 `fixed` 浮层 | 居中最大宽 1120，遮罩/ESC 关闭；长文档阅读优先 |

| 进度/时间线 | 自建 `ProgressBar` | 仅上传与索引重建进度；不提供解析时间线 |
| 代码高亮/长文本 | 无 | 分块正文用 `whitespace-pre-wrap` + 折叠 |

**素材沉淀判断**：`DataTable`、`StatusTag` 具备 ≥2 处复用（文档/列表/详情），一期落地后可抽到 `src/lib/kb-kit/`；但**先页面跑通再抽**，避免过早抽象。

## 7. Mock 数据约定

- 单库演示数据：`产品文档库`（128 篇文档、1,664 块），另备 4 个库用于下拉切换演示（`运维知识库` 96 篇 / `故障案例库` 74 篇 / `研发规范库` 41 篇 / `客户交付资料` 0 篇空态）。
- 文档覆盖多状态：已解析 114、优化中 2、排队中 2、解析中 2、需重新解析 6、失败 2（失败原因分别为"文件加密"与"扫描件未识别"，并标注失败阶段）。
- 分块数据：为 3 篇代表文档准备真实可读的中文块（技术文档 heading 型、OCR 型、长文固定长度型），其余按模板生成。
- 检索测试：内置 1 条默认 query 与 4 条示例 query（`容器云集群扩容失败怎么排查`、`如何调整分块大小`、`解析失败怎么重试`、`支持哪些文件格式`），基于 12 条固定分块与确定性打分函数，保证演示可复现。
- 存储 key 前缀：`kb.*`（`kb.activeLibrary`、`kb.libraries`、`kb.chunkOverrides`），索引迁移状态使用 `ikb-kb-index-v1`，与现有 `aiops.*` 隔离；旧的 `aiops.defaultModel` 仅原型兼容保留，正式版不向业务用户暴露模型。
- 数据集中在页面目录下的 `mock.ts`，组件不内联大段常量；上传任务与本次新增文档仅保存在内存，用于演示状态推进，刷新后回到内置 Mock。

## 9. 已确认

1. 文档详情采用居中大浮层，不使用右侧抽屉；长文档阅读优先。
2. 片段允许编辑正文并启停；关闭的片段不参与检索。
3. 独立分块页、切分参数调整（含调参后批量重解析）、原文-分块对照不在一期范围；一期只提供库设置弹层与库内最小召回测试（查看结果并回到原文，不做分块级编辑闭环）。
