这是一份融合了我们所有讨论精华的最终版落地实施方案。它不仅是一个原型展示平台,更是一个**"需研交一体化(需求、研发、交互)"**的团队私有资产库。

> 设计原则:**AI 来源无关,但生成有规范**。当前主要承接 Figma 设计稿转码,后续会接入 v0、Trae、Cursor、Claude、lovable 等任意 AI 从文档/图片/截图生成的代码。平台不绑定任何特定生成源,但**所有 AI 必须通过统一的 Skill 规范来生成代码**,从源头保证接入契约、样式系统、批注锚点的一致性——让"插 U 盘"真正即插即用。

# 🚀 代码驱动的统一原型与需求协作平台 (V3.0)

## 一、 平台定位与核心价值

- **一站式闭环**:彻底取代 Axure 和离线文档。将 AI 生成的真实前端代码与 Markdown 需求文档深度绑定。
- **基座架构 (Host)**:平台基础设施(路由、文档渲染/编辑、注解、搜索)只开发一次。后续新需求只需"像插 U 盘一样"丢入页面组件和文档。
- **同源强绑定**:需求文档与原型代码在同一个 Git 目录下,同生共死,版本永远一致,消除"研发看错文档版本"的痛点。
- **本地优先 (Local-First)**:**摒弃云端部署,评审者 `git clone` + 一行命令启动**。数据完全留在本地,保密性强、零云成本、离线可用。
- **文档可编辑+注解**:PRD 不只渲染,还支持在线所见即所得编辑,保存即写回 .md;支持 Word 式段落注解,讨论沉淀与文档同源。
- **AI 来源解耦**:平台只认"接入契约",不关心代码是 Figma 转的还是 AI 写的。换工具不影响资产沉淀。

## 二、 技术栈全景选型

| 模块 | 技术选型 | 核心作用与优势 |
|---|---|---|
| 基础框架 | Vite + React + Tailwind CSS | 现代前端标配,构建极速,契合 Trae/v0/Cursor 等 AI 工具的默认输出 |
| UI 组件库 | Shadcn UI | 源码级组件(Tabs、Sidebar、Drawer、Command),支持深度定制 |
| **文档渲染** | **react-markdown + remark-gfm + tailwindcss/typography** | **Markdown 零成本渲染为优雅网页(只读模式)** |
| **文档编辑** | **Milkdown (基于 ProseMirror)** | **所见即所得 Markdown 编辑器,体验接近 Notion/Word,保存即写回 .md** |
| **Word 式注解** | **自研轻量 mark + 侧边栏 Drawer** | **选中段落挂评论,锚定文本段(非 DOM 坐标),天然稳定** |
| **本地后端** | **Express + fs(50 行级)** | **提供 `/api/md` 读写本地 .md、`/api/anno` 读写注解 JSON** |
| **一键启动** | **bash 脚本 `prototype.sh`** | **封装 `npm install + 启动前后端 + 自动开浏览器`,用户感知一行命令** |
| **全文搜索** | **fuse.js** | **离线对所有 .md 建索引,Command+K 唤起** |
| 部署与版本 | Git + GitHub(仅作版本管理与分发,不做云部署) | 评审者 `git clone` 即获全部资产 |
| **PDF 导出** | **react-to-print(客户端打印)** | **浏览器原生打印导出 PDF** |

## 三、 AI 代码接入契约 + Skill 规范(核心创新)

### 设计思路:从"事后检查"升级为"生成时强制"

任何 AI(Figma 转码、Trae 从 PRD 生成、Cursor 从截图重构)产出的代码,只要遵守契约就能接入。但"事后人工检查"成本高、易遗漏。因此平台配套一套**统一 Skill 规范**,所有 AI 生成代码时必须加载该 Skill,从源头保证合规——这是让"插 U 盘"真正即插即用的关键。

### 契约 1:目录约定(强约束)
```
src/pages/<业务域>/<页面>/
  ├── index.tsx          # 默认入口(必须 default export 一个 React 组件)
  ├── prd.md             # 专属 PRD 文档(可空但文件必须存在)
  ├── meta.json          # 页面元数据(见契约 3,由 Skill 自动生成)
  └── _versions/         # 可选:多方案目录
      ├── v1.tsx
      └── v2.tsx
```

### 契约 2:组件默认导出(强约束)
入口文件**必须** `export default function XxxPage()`,基座通过 `React.lazy(() => import(...))` 动态加载。
```tsx
// ✅ Skill 规范输出:默认导出
export default function LoginPage() {
  return <div>...</div>;
}
```

> 注:V2.2 的 `data-anno-anchor` 锚点约定**取消**——批注改为锚定 PRD 文档段落(Word 式),不再需要 DOM 锚点。Skill 不再注入锚点,简化生成规则。

### 契约 3:meta.json 元数据(由 Skill 自动生成)
```json
{
  "title": "登录页",
  "module": "CRM",
  "defaultVersion": "v2",
  "versions": ["v1", "v2"],
  "tags": ["登录", "鉴权"]
}
```
- `tags`:供搜索与筛选使用。
- 已移除 V2.2 的 `fixedAspect` 和 `anchorIds`(随锚点约定一起取消)。

### 契约 4:样式系统统一(强约束)
- **必须**使用 Tailwind CSS + Shadcn UI,禁止 antd、inline-style、CSS Modules。
- **必须**使用平台预设的设计 token(颜色、圆角、间距),由 Skill 注入 `tailwind.config` 引用。
- 这条约束解决"不同 AI 工具产出样式割裂"问题,保住"统一平台"的视觉一致性。

### Skill 规范定义(给 AI 的生成规则)

平台提供 `prototype-page-generator.skill`,任何 AI 工具加载后须遵守:

| 规则 | 强制级别 | 说明 |
|---|---|---|
| 输出目录结构符合契约 1 | 强制 | 缺一不可 |
| 入口 `export default` | 强制 | 否则基座无法懒加载 |
| 使用 Tailwind + Shadcn | 强制 | 禁用其他 UI 库与 inline-style |
| 引用平台设计 token | 强制 | 颜色/圆角/间距走 `theme/*` |
| 生成 `meta.json` | 强制 | 含 title/module/versions/tags |
| 生成 `prd.md` | 推荐 | 可从输入文档提炼,也可留空模板 |

### 接入流程(给协作者的 SOP)
1. 在 AI 工具(Trae/Cursor/v0)中加载 `prototype-page-generator.skill`;
2. 喂给 AI 输入(Figma 链接 / PRD 文档 / 截图 / 口头描述);
3. AI 按 Skill 规范产出代码,直接落到 `src/pages/<业务域>/<页面>/`;
4. `git push`,基座自动扫描 `meta.json` 注册路由与导航,批注锚点自动可用。

> 该契约 + Skill 对所有 AI 工具透明——Figma 转 v0、Trae 从 PRD 生成、Cursor 从截图重构,产物都能直接套用,且批注锚点与样式天然统一。

## 四、 核心功能模块设计

### 1. 混合式左侧导航 (Hybrid Sidebar)
- 💻 **业务原型区**:按 `meta.json.module` 自动分组(如 CRM、ERP)。
- 📚 **全局文档区**:存放《全局权限说明》《数据字典》《接口规范》等宏观文档。
- 🔍 **顶部搜索框**:Command+K 唤起,fuse.js 索引所有页面标题与 .md 正文,回车直达。

### 2. 需研一体化双视窗 (Tab View)
右侧主内容区顶部固定 Shadcn Tabs:
- 🎨 **交互原型**:渲染 `index.tsx` 或 `_versions/<v>.tsx`,可直接点击操作。
- 📝 **PRD 需求文档**:渲染同级 `prd.md`,默认只读;点击右上角"编辑"按钮切换为 Milkdown 所见即所得编辑模式,**保存即通过 `/api/md` 写回本地 .md 文件**,git 可追踪沉淀。

**多方案版本绑定规则**:
- 若 `meta.json.versions` 仅 1 项 → PRD 单一版本,直接渲染 `prd.md`;
- 若有多版本 → **强制拆分** `prd_v1.md` / `prd_v2.md`,由 `meta.json.prdFiles` 显式声明映射(放弃 V2.1 的 `## @v1` 标题分区法,易遗漏且编辑器难处理)。

### 3. Word 式文档注解系统(取代页面坐标批注)
> 设计转向:不再做"在原型 UI 上打点"的页面批注(坐标漂移是死结),改为**在 PRD 文档段落上挂评论**,锚定文本段,天然稳定。

**交互形态(对标 Word/Notion)**:
- 在 PRD 文档(只读或编辑模式均可)中**选中一段文字** → 浮出"添加注解"按钮 → 右侧侧边栏 Drawer 弹出输入框。
- 提交后:被选中的文字在文档中**高亮带下划线+序号标记**,右侧 Drawer 列出该段所有注解(作者、时间、内容、未解决/已解决状态)。
- 点击右侧注解项 → 文档滚动定位到对应段落并高亮闪烁。
- 支持回复串、@提及、状态流转。

**持久化机制**:
- 注解存储在与 .md 同级的 `.annotations.json` 文件中,结构:
```json
{
  "version": "v2",
  "items": [
    {
      "id": "anno-001",
      "anchorText": "用户输入手机号后",
      "anchorOffset": 128,
      "author": "zhangsan",
      "createdAt": "2026-07-31T10:00:00Z",
      "status": "open",
      "replies": [{ "author": "lisi", "content": "确认加 86 区号", "createdAt": "..." }]
    }
  ]
}
```
- 通过 `/api/anno` 读写,git 提交即沉淀,评审者 clone 后即可看到全部历史讨论。
- **锚点稳定性**:`anchorText` 记录被选中原文 + `anchorOffset` 字符偏移;若文档被改导致原文找不到,前端做模糊匹配(编辑距离 < 阈值),仍命中;若彻底删除则标注"原文已变更"提示作者复核。

### 4. 方案对比与更新日志
- **方案对比**:顶栏 Select 切换 `_versions/v1` ↔ `v2`,切换时原型、PRD 文件、注解三同步切换。
- **更新日志**:顶栏"日志"按钮 → 右侧 Drawer Timeline。Timeline 项接 `git log`(commit hash、作者、时间、message),可点击跳转 GitHub commit 详情。

### 5. 链接分享与导出
- **分享链接**:`/crm/login?v=v2` 可直达某方案,评审邀约零摩擦(本地启动后通过 `localhost:port/crm/login?v=v2` 分享给同机或同网段同事)。
- **PDF 导出**:页面右上角"导出"按钮,react-to-print 调浏览器原生打印,把"当前原型截图 + PRD 全文 + 注解列表"导出为 A4 PDF,供不进系统的客户/领导查阅。

### 6. 协作流程
> 无需站内通知系统。注解写入 `.annotations.json` 后,评审者自行 `git pull` 拉取最新讨论,流程与代码评审一致。需要即时通知时,外部群发分享链接即可。

## 六、 权限模型

> 无独立鉴权系统。访问控制通过两层保障:
> 1. **Git 仓库可见性**:私有仓库只有授权成员能 clone,天然隔离外部人员。
> 2. **分支隔离**:内部评审用 `main` 分支,客户演示用 `demo` 分支(导出 PDF 或临时切分支),避免内部注解泄露给客户。

## 七、 落地执行 SOP(分阶段 Roadmap)

### 🚀 阶段一:搭建"基座" + Skill 规范(MVP 核心)
**任务**:
1. Trae 中初始化 Vite + React + Tailwind + Shadcn。

3. 构建 `host/layout`(Sidebar + TopBar + Tabs)与 `host/router`(扫描 `meta.json` 自动注册路由)。

5. 在 Trae 中加载该 Skill,生成首批页面(Figma 转码 + Markdown),跑通本地预览。

**验收标准**:
- ✅ Skill 加载后,任意输入(Figma 链接/PRD/截图)产出的代码均含合规 `meta.json` 与默认导出。
- ✅ 丢入 Skill 产出的目录,刷新后导航自动出现入口,Tab 双视窗正常切换,无需改任何基座代码。

**回滚预案**:路由扫描失败时降级为静态路由表 `host/router/fallback.ts`,手动维护;Skill 产出不合规时,CI 加一道 lint 校验 `meta.json` 完整性,失败即阻断合并。

### 🚀 阶段二:本地后端 + 编辑器 + Word 注解
**任务**:
1. 开发 `server/index.js`(Express + fs),实现 `/api/md` 读写、`/api/anno` 读写。

4. 开发 `host/annotation` Word 式注解:选中文字挂评论、右侧 Drawer 列表、高亮 + 序号、回复串、状态流转。

**验收标准**:
- ✅ 评审者 `git clone` 后执行 `./prototype.sh start`,一行命令自动开浏览器可用。
- ✅ 在 PRD Tab 编辑文字并保存,刷新页面后改动仍在(写回本地 .md)。
- ✅ 选中一段文字添加注解,右侧 Drawer 出现该注解;修改原文后,注解仍能通过模糊匹配命中。

**验收标准**:

- ✅ 导出的 PDF 包含原型截图、PRD 全文、注解列表三部分。
- ✅ 顶栏"日志"按钮展示 Git commit Timeline,可跳转 GitHub。
- ✅ 新同事按 README 操作,5 分钟内完成环境就绪并打开平台。

**回滚预案**:搜索索引构建失败时降级为仅搜索标题;PDF 导出失败时降级为浏览器原生 Ctrl+P 打印。

## 八、 日常新增功能 SOP(基座就位后的标准工作流)

> 基座(`prototype.sh` + `server/` + `src/host/`)一次性安装就位后,日常每新增一个功能设计,只需以下 4 步,无需改任何基座代码。

### 前提:基座已就位(一次性)
```
project-root/          # 已 git clone,执行过一次 ./prototype.sh start
├── prototype.sh       # ✅ 已就位
├── server/            # ✅ 已就位(Express + fs)
├── src/host/          # ✅ 已就位(基座:layout/router/editor/annotation/search)
├── src/pages/         # 业务页面区(增量添加)
└── package.json
```

### 新增一个功能(示例:CRM 客户列表页)

**第 1 步:在 AI 工具中加载 Skill**
- Trae / Cursor / v0 中加载 `prototype-page-generator.skill`
- Skill 已内置目录约定、默认导出、Tailwind+Shadcn、`meta.json` 自动生成等规则
- 建议在 Trae 中设为常驻规则,每次开新对话无需重复加载

**第 2 步:喂输入给 AI,生成代码**
输入可以是任意形式:
- Figma 设计稿链接
- 一份 PRD 文档(.md / .docx)
- 一张截图
- 一段口头描述("做一个 CRM 客户列表,左侧筛选,右侧表格分页")

AI 按 Skill 规范产出:
```
src/pages/CRM/CustomerList/
  ├── index.tsx      # 默认导出 React 组件
  ├── prd.md         # PRD 文档(从输入提炼或留模板)
  └── meta.json      # { "title":"客户列表", "module":"CRM", ... }
```

**第 3 步:把目录丢进 `src/pages/`**
- 直接放到对应业务域下:`src/pages/CRM/CustomerList/`
- 无需手动注册路由、无需改基座

**第 4 步:刷新浏览器**
- 基座 `host/router` 自动扫描 `src/pages/**/meta.json`
- 左侧导航"CRM"分组下自动出现"客户列表"入口
- 点击进入 → Tab 切换原型 / PRD → 可编辑 PRD、添加 Word 注解

### 用户感知的完整流程

```bash
# 一次性(已做过):
git clone xxx && ./prototype.sh start

# 日常新增功能(每次):
# 1. AI 工具加载 Skill → 输入需求 → 生成代码
# 2. 把生成的目录拖进 src/pages/<业务域>/
# 3. 回到浏览器刷新 → 新功能自动出现
```

### 常见场景变体

| 场景 | 操作差异 |
|---|---|
| 新建一个业务域(如 ERP) | 直接建 `src/pages/ERP/`,导航自动出现"ERP"分组 |
| 一个页面要做 A/B 方案 | 让 AI 生成 `_versions/v1.tsx` + `_versions/v2.tsx` + `prd_v1.md` + `prd_v2.md`,meta.json 填 `versions:["v1","v2"]` |
| 改已有页面 | 直接改 `index.tsx`,或在浏览器里用 Milkdown 编辑器改 `prd.md`,保存即生效 |
| 删除页面 | 删掉对应目录,刷新后导航入口自动消失 |
| 评审讨论 | 选中 PRD 段落添加 Word 注解 → 写入 `.annotations.json` → git commit/push → 同事 pull 后看到 |

## 九、 总体里程碑与风险登记

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| AI 生成的代码不符合接入契约 | 页面无法加载 | Skill 在生成时强制合规 + CI lint 双重校验 |
| 不同 AI 工具产出样式割裂 | 视觉不统一 | Skill 强制 Tailwind + Shadcn + 设计 token 引用 |
| 评审者本机无 Node 环境 | 无法启动 | README 明确前置依赖;后续可考虑用 `pkg` 打包为单文件可执行 |
| 文档编辑冲突(两人同改一段) | 一方改动丢失 | MVP 不处理,靠 git pull/push 流程规避;冲突时 `.md` 走 git merge,`.annotations.json` 走数组合并(不同 id 不冲突) |
| 注解锚点因文档改写失效 | 历史注解错位 | `anchorText` + 模糊匹配(编辑距离);彻底删除时标注"原文已变更"提示 |
| 内部敏感信息泄露客户 | 商务事故 | 私有仓库 + main/demo 分支隔离 |
| 文档与代码不同步 | "看错版本"老问题 | 同级目录强绑定 + Git commit 关联 Timeline |
