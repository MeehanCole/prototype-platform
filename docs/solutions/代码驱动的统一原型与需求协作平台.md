# 🚀 代码驱动的统一原型与需求协作平台 (V4.0)

## 一、 平台定位与核心价值

> **核心定位:平台是唯一输出基线,Figma / Axure 只是输入源。**
> Figma、Axure 产出的原型只是"中间创作态/素材",进入开发、测试、验收、迭代阶段,必须以平台内的原生 React 代码 + PRD + Git 版本为最终交付物。iframe 嵌入仅用于快速预览,不作为交付基线。

- **一站式闭环**:彻底取代 Axure 和离线文档。将 AI 生成的真实前端代码与 Markdown 需求文档深度绑定。
- **输入源解耦**:Figma / Axure 只是输入源(素材),支持任意输入形式(设计稿/截图/PRD/口头描述),统一转换为平台原生代码。
- **纯静态架构**:彻底移除 Express 后端,PRD 通过 Vite `?raw` 内嵌到原型代码,零后端依赖,可直接部署到 Cloudflare Pages 等静态托管平台。
- **基座架构 (Host)**:平台基础设施(路由、PRD 渲染、版本切换、缩放、设计系统切换)只开发一次。后续新需求只需"像插 U 盘一样"丢入页面组件和文档。
- **同源强绑定**:需求文档与原型代码在同一个 Git 目录下,同生共死,版本永远一致。
- **PRD 内嵌展示**:点击原型上的功能点"说明"按钮,右侧弹出 DocPanel 展示该功能点的完整 PRD 业务描述(正向、边界、验收),无需跳转页面。
- **AI 来源解耦**:平台只认"接入契约",不关心代码是 Figma 转的还是 AI 写的。换工具不影响资产沉淀。

## 二、 技术栈全景选型

| 模块 | 技术选型 | 核心作用与优势 |
|---|---|---|
| 基础框架 | Vite + React + Tailwind CSS | 现代前端标配,构建极速 |
| UI 组件库 | Shadcn UI | 源码级组件,支持深度定制 |
| **PRD 内嵌** | **Vite `?raw` + ReactMarkdown + remark-gfm** | **PRD .md 文件在构建时内嵌到 JS bundle,零后端依赖,纯静态部署友好** |
| **Mermaid 渲染** | **mermaid 库 + 自定义 `pre` 组件** | **PRD 交互流程章节的 Mermaid 流程图渲染为 SVG,PRD 视图和 DocPanel 均支持** |
| **功能点标注** | **FEATURE_LABELS + FEATURE_DOCS + DocPanel** | **胶囊形"说明"按钮 → 点击弹出右侧面板展示完整 PRD 段落** |
| **Portal 定位** | **React `createPortal`** | **DocPanel 渲染到 `document.body`,绕过 zoom `transform` 容器,修复 fixed 定位失效问题** |
| **设计系统切换** | **CSS 变量 + localStorage** | **5 套预设(Prototype Default / Element Plus / Ant Design / Arco / Naive UI),运行时一键切换** |
| **品牌标识** | **侧边栏左上角「P」色块 + "原型协作台"** | **中文品牌名,增强产品定位清晰度** |
| 自动路由 | 扫描 `meta.json` 注册路由 | 丢文件即接入,无需手动注册 |
| 部署与版本 | Git + Cloudflare Pages | push 即构建部署,国内访问快,免费 |

## 三、 AI 代码接入契约 + Skill 规范

### 契约 1:目录约定(强约束)
```
src/pages/<业务域>/<页面>/
  ├── index.tsx          # 默认入口(必须 default export)
  ├── prd.md             # 专属 PRD 文档
  ├── meta.json          # 页面元数据
  └── _versions/         # 多版本目录
      ├── v1.tsx
      └── v2.tsx
```

### 契约 2:组件默认导出(强约束)
入口文件**必须** `export default function XxxPage()`。

### 契约 3:meta.json 元数据(由 Skill 自动生成)
```json
{
  "title": "登录页",
  "module": "CRM",
  "defaultVersion": "v2",
  "versions": ["v1", "v2"],
  "tags": ["登录", "鉴权"]
}
```

### 契约 4:样式系统统一(强约束)
- **必须**使用 Tailwind CSS + Shadcn UI,禁止 antd、inline-style。
- **必须**使用平台设计 token(`bg-background`、`text-foreground`、`bg-primary` 等)。

### 契约 5:PRD 段落标记(Mode C 多版本必做)
PRD 中每个功能需求必须用 `**FR-X` 标记段落起始,支持程序精确提取:
```markdown
**FR-1 视角切换（Restructure, 顶层 Tab 必做）**
| 项目 | 说明 |
|---|---|
| 描述 | 页面最顶部显示「个人视角」/「团队视角」切换 Tab |
| 业务规则 | 1) 普通员工=只显示个人视角 |

**FR-2 团队视角：部门/成员筛选（Modify）**
...
```

### 契约 6:PRD 内嵌代码(Mode C 多版本必做)
版本文件必须包含:
```tsx
import prdV2Raw from '../prd_v2.md?raw'

function extractSection(raw: string, startFr: string): string { ... }

const FEATURE_DOCS: Record<string, string> = {
  'A.01': extractSection(prdV2Raw, 'FR-1'),
  'B.01': extractSection(prdV2Raw, 'FR-3'),
  // ... key 必须与 FEATURE_LABELS 1:1 对应
}
```

### Skill 规范定义(给 AI 的生成规则)

平台的 AI 生成规则采用 **项目级 `.skills/` 目录**管理,与 IDE 无关:

| 文件 | 用途 |
|---|---|
| `.skills/README.md` | 规则索引与跨 IDE 使用说明 |
| `.skills/page-generator.md` | 代码生成完整契约(目录/导出/样式/PRD 内嵌/DocPanel/反模式/Checklist) |
| `.skills/design-workflow.md` | 三种设计工作流完整流程(模式 A/B/C、版本管理、产物目录) |
| `.skills/templates.md` | 可复制的代码模板(meta.json/PRD/Changelog/extractSection/DocPanel/NewTag) |

**`.trae/skills/`** 是 Trae IDE 的 Skill 适配器,内容为 `.skills/` 的摘要和引用,不维护独立规则。

**跨 IDE 使用方式**:
- **Trae IDE**:Skill 自动加载,直接使用
- **Cursor / Copilot / 其他 Agent**:在对话中引用 `.skills/` 下的文件,例如:"请先阅读 `.skills/page-generator.md` 中的代码生成规范,然后为我生成 OA 审批中心页面"
- **纯手工**:打开 `.skills/` 下对应的 `.md` 文件,按规范编写代码

| 规则 | 强制级别 | 说明 |
|---|---|---|
| 输出目录结构符合契约 1 | 强制 | 缺一不可 |
| 入口 `export default` | 强制 | 否则基座无法懒加载 |
| 使用 Tailwind + Shadcn | 强制 | 禁用其他 UI 库与 inline-style |
| 引用平台设计 token | 强制 | 颜色/圆角/间距走 theme |
| 生成 `meta.json` | 强制 | 含 title/module/versions/tags |
| 生成 `prd.md` | 推荐 | 10 节标准结构,中文标题 |
| PRD 加 `**FR-X` 标记 | Mode C 强制 | 支持 `extractSection` 提取 |
| 版本文件含 `?raw` 导入 | Mode C 强制 | PRD 内嵌,零后端依赖 |
| FEATURE_DOCS 与 FEATURE_LABELS 1:1 | Mode C 强制 | 点击说明按钮正确展示对应 PRD |
| DocPanel 用 `createPortal` | Mode C 强制 | 绕过 zoom transform 容器,560px 宽度 |
| Mermaid 渲染 | 强制 | PRD 视图 + DocPanel 均需支持 `mermaid` 库渲染 |
| Figma 布局适配 | 强制 | `min-h-screen`(非 `h-screen`)、Sidebar 通顶、移除 `overflow-hidden` |
| 宽表格横向滚动 | 强制 | 外层 `overflow-hidden` + 三层 `min-w-0` + `overflow-x-auto` |
| `pages-imports` 排除 | 强制 | tsconfig.app.json 排除 Figma 参考代码目录 |

## 四、 核心功能模块设计

### 1. 混合式左侧导航 (Hybrid Sidebar)
- 💻 **业务原型区**:按 `meta.json.module` 自动分组(如 CRM、ERP、OA)。
- 侧边栏可折叠,默认 `w-44`,折叠为 `w-12`(仅显示首字母)。
- 折叠/展开有 200ms 过渡动画,模块名全大写 + tracking-wider。

### 2. 需研一体化双视窗 (Tab View)
右侧主内容区顶部固定分段控件:
- 🎨 **原型**:渲染 `index.tsx` 或 `_versions/<v>.tsx`,可直接点击操作。
- 📝 **PRD**:只读渲染同级 `prd.md`(或 `prd_v1.md` / `prd_v2.md`),使用 `ReactMarkdown` + `remarkGfm` + Mermaid 流程图渲染。

**多版本绑定规则**:
- `meta.json.versions` 仅 1 项 → 单一 `prd.md`
- 多版本 → 强制拆分 `prd_v1.md` / `prd_v2.md`

### 3. 功能点标注系统 (Feature Annotation)

**交互流程**:
1. Header 右侧「显示新增功能点」toggle 开关(按路由+版本存 localStorage)
2. 打开开关后,页面上每个功能点旁出现胶囊形「说明」按钮
3. 蓝色按钮 = 有 PRD 详情,可点击 → 弹出右侧 DocPanel
4. 灰色按钮 = 无 PRD 详情,仅 hover 显示简短 tooltip
5. 开关关闭 → 所有按钮瞬间消失,零占位零位移,原型恢复纯净演示态

**DocPanel(右侧滑出面板)**:
- `createPortal` 渲染到 `document.body`(绕过 zoom `transform` 容器)
- 560px 宽度（`max-w-[92vw]`）,从右侧滑出 + 半透明遮罩 + backdrop-blur
- 头部:编号 + 类型标签 + 标题 + 关闭按钮
- 内容区:`ReactMarkdown` + `remarkGfm` + Mermaid 渲染该功能点对应的 PRD 完整段落(含流程图)
- 支持 Esc 键 + 遮罩点击关闭
- 单例模式(只有一个 `code` state,不堆叠)

**Hover Tooltip**:
- `createPortal` 渲染到 `document.body`,`position:fixed` 定位
- 显示:编号 + 标题 + 简短描述
- 有 PRD 详情时附加"点击查看完整 PRD"提示
- 自动避让视口边缘(上方空间不足时显示在下方,左右越界时对齐边缘)

### 4. 版本对比与缩放
- 顶栏版本下拉:切换 `_versions/v1` ↔ `v2`,版本切换时 React 强制 remount,状态不跨版本污染
- 缩放控件:-/100%/+ 按钮,50-150% 范围,10% 步长,200ms 过渡
- 内容区最大化:`fixed inset-0 z-50` 覆盖侧边栏和顶栏,Esc 退出

### 5. 设计系统切换
- 顶栏 `DesignSystemSwitcher` 下拉,5 套预设(Prototype Default / Element Plus / Ant Design / Arco / Naive UI)
- 选择后通过 CSS 变量动态注入,localStorage 持久化
- 每套预设包含:主色、圆角、字号、组件视觉规范

## 六、 部署方案:Cloudflare Pages

**为什么选 Cloudflare Pages**:
- 免费,国内访问快
- 支持 GitHub push 自动构建部署
- 纯静态托管,零运维
- 完美适配移除后端后的架构

**部署步骤**:
1. 推代码到 GitHub
2. Cloudflare Pages 连接仓库
3. Build command:`npm run build`
4. Output directory:`dist`
5. 环境变量无需配置(零后端依赖)

## 七、 日常新增功能 SOP

### 前提:基座已就位(一次性)

### 新增一个功能(示例:CRM 客户列表页)

**第 1 步:在 AI 工具中加载 Skill**
- 加载 `prototype-page-generator` Skill
- Skill 已内置目录约定、默认导出、Tailwind+Shadcn、`meta.json` 自动生成、PRD 内嵌、DocPanel 等规则

**第 2 步:喂输入给 AI,生成代码**
输入可以是任意形式:
- Figma 设计稿链接（通过 MCP 工具 `get_figma_data` + `download_figma_images` 直接读取设计稿节点数据 + 下载页面截图，无需手动导出代码；也可仅生成 PRD 不生成代码）
- Figma 插件导出的代码工程（zip/目录，放入 `01-raw/` 走适配管线）
- 一份 PRD 文档
- 一张截图
- 一段口头描述

AI 按 Skill 规范产出:
```
src/pages/CRM/CustomerList/
  ├── index.tsx      # 默认导出 React 组件
  ├── prd.md         # PRD 文档
  └── meta.json      # { "title":"客户列表", "module":"CRM", ... }
```

**第 3 步:把目录丢进 `src/pages/`**

**第 4 步:刷新浏览器**
- 基座自动扫描 `meta.json`,导航自动出现入口

### Mode C 多版本改造 SOP

**第 1 步:C1 基线建立**
- 快照现有版本为 `_versions/v1.tsx`
- 生成 `prd_v1.md`(基线简版 PRD)
- `meta.json` 添加 `"v1"` 到 versions

**第 2 步:C2-C3 需求分析 + 改造方案**
- 分析新需求,设计改造方案
- 分类:Restructure / Add / Modify / Remove

**第 3 步:C4 原型改造**
- 复制 `v1.tsx` → `v2.tsx`
- 在 `v2.tsx` 中:
  1. `import prdV2Raw from '../prd_v2.md?raw'`
  2. 添加 `extractSection` 函数
  3. 添加 `FEATURE_DOCS` 映射表(key 与 `FEATURE_LABELS` 1:1)
  4. 添加 `DocContext` + `DocPanel` 组件
  5. 改造功能点标注为胶囊形「说明」按钮
- `meta.json` 添加 `"v2"` 到 versions

**第 4 步:C5 PRD + Changelog**
- 生成 `prd_v2.md`(含 `**FR-X` 标记)
- 生成 `c5_v1_vs_v2_changelog.md`(6 节测试验收文档)
- 编号对齐:Changelog 编号 = FEATURE_LABELS key = 原型按钮编号

**第 5 步:C5.1 验收**
- 打开 V2 → 开「显示新增功能点」→ 逐个点击「说明」按钮 → 对照 Changelog 验收
- 切回 V1 → 验证不回归
