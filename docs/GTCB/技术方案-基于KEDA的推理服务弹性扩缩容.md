## 1. 背景与问题

现有推理服务只能按固定副本运行，或依赖 Ray Serve 自带的「按请求数」弹性。存在两个缺口：

| 缺口 | 具体表现 |
|---|---|
| **扩缩容依据太窄** | Ray Serve 只看请求队列，HPA 只看 CPU / 内存。**GPU 利用率、显存占用、SM 活跃度这些真正决定推理性能的指标，无法参与扩缩容决策** |
| **GPU 闲置成本高** | 推理服务常出现「卡被占着但算力空闲」（batch 打满、长尾请求少），按 CPU/请求数都缩不下来 |

**需求目的**：用 KEDA 把 **Prometheus 中的 GPU 指标**接入扩缩容判定，**扩展推理服务的扩缩容依据范围**（不止 CPU/内存/请求数），并让用户可在页面上配置指标、阈值与副本范围。

---

## 2. 目标与非目标

**目标**

1. 推理服务支持三种弹性模式：常规（固定副本）、Serverless（按请求）、指标（按 GPU 指标）
2. 指标模式支持两种来源：**内置指标**（多厂商、多条件组合）与 **自定义 PromQL**
3. 指标、阈值、副本范围、检测窗口可在创建 / 编辑页配置，并在详情页完整回显
4. 扩缩容动作可解释：用户能看懂「为什么扩、为什么缩」

**非目标（本期不做）**

- 不做 GPU 卡级的排队 / 抢占调度（属于资源调度域）
- 不做跨集群、跨资源池的弹性
- 不做自定义指标的历史趋势分析与告警（告警由平台告警模块负责）

## 3. 技术方案

### 3.1 三层协作（关键设计）

```
Prometheus（DCGM / 厂商 exporter）
      │  指标
      ▼
   KEDA（prometheus scaler，30s 轮询）
      │  判定条件 → 调整「副本范围」
      ▼
SkyLLMServing.spec.scale.minReplicas / maxReplicas   ← 有 /scale 子资源，可被 KEDA 写入
      │  operator 下发
      ▼
Ray Serve autoscaler（在 [min,max] 内按请求扩缩）
      │  副本数换算 worker
      ▼
RayCluster.workerGroupSpecs[].replicas               ← 无 /scale，只能由 operator 改
```

| 角色 | 职责 | 不能做什么 |
|---|---|---|
| **KEDA** | 从 Prometheus 取指标、比较阈值、**调整副本范围的上下限** | 不能直接扩 RayCluster（CRD 无 `/scale` 子资源），不能替代 Serve autoscaler |
| **Ray Serve autoscaler** | 在 `[min, max]` 区间内按请求量扩缩副本 | 不能读 Prometheus 指标 |
| **KubeRay operator** | 把副本数换算成 worker 数下发到 RayCluster | 不做指标判定 |

> 一句话概括分工：**KEDA 决定「允许扩到多大」，Ray 决定「当前扩到几个」，operator 负责「换算成几张卡」。**

### 3.2 副本数与 worker 的换算

```
worker replicas = ceil(模型副本数 × TP × PP × DP ÷ 单 Pod 卡数)
```

因此页面上只需要配置**模型副本数**，worker 数由系统推导，不再单独暴露。

### 3.3 弹性模式能力矩阵

| 模式 | 判定依据 | 谁执行 | KTransformer |
|---|---|---|---|
| **常规模式** | 无（固定副本） | — | ✅ 支持 |
| **Serverless 模式** | 每副本处理中的请求数 | Ray Serve autoscaler | ❌ 不支持 |
| **指标模式** | Prometheus 中的 GPU 指标（内置 / 自定义 PromQL） | KEDA 调范围 + Serve 执行 | ❌ 不支持 |

> **KTransformer 只支持常规模式**：它走的是边缘 ReplicaSet 路径，没有 Serve 层的 autoscaler，也没有 `scale` 相关字段，配置了也不会生效，因此在创建 / 编辑页直接置灰。

### 3.4 关键约束（必须知道）

| 约束 | 影响 | 处理方式 |
|---|---|---|
| KEDA 单个 ScaledObject 只有 **一个 threshold** | 标准的「扩容阈值 / 缩容阈值」双阈值滞回无法直接表达 | 采用「**条件满足 → 放开上限；条件持续不满足 → 收窄上限**」的单条件模型，滞回由检测窗口承担 |
| 指标表达式必须返回 **单个数值** | 多 series 会导致取值错误 | 保存前做预检（FR-6.1），多 series 直接拦截 |
| 指标查询 30s 轮询一次 | 过重的 PromQL 会拖垮 Prometheus | 预检限制查询耗时，推荐用 `rate` + 聚合 |
| ScaledObject 与目标必须同命名空间 | 跨命名空间无法直接引用 | 由平台统一在同一 ns 内创建 |

## 4. 指标供给

### 4.1 指标来源

| 来源 | 适用场景 | 页面交互 |
|---|---|---|
| **内置指标** | 90% 常规场景，按算力型号过滤，带推荐阈值 | 指标下拉 + 阈值 + 多条件组合 |
| **自定义 PromQL** | 多厂商 / 自定义 exporter / 业务指标 | 手写完整判断条件（含比较），支持指标名联想 |

### 4.2 内置指标目录（多厂商）

| 算力型号 | 指标数 | 指标 |
|---|---|---|
| 英伟达 H100（DCGM） | 7 | GPU 利用率、显存使用率、SM 活跃度、Tensor Core 活跃度、显存带宽利用率、功耗、温度 |
| 华为昇腾 910B | 2 | AI Core 利用率、显存使用率 |
| Metax C500 | 2 | GPU 利用率、显存使用率 |
| 寒武纪 MLU370-X8 | 2 | MLU 利用率、显存使用率 |
| 海光 DCU Z100 | 2 | DCU 利用率、显存使用率 |
| 天数智芯 BI-V150 | 2 | GPU 利用率、显存使用率 |

> 非 NVIDIA 厂商只保留「算力利用率 + 显存使用率」两项，因为这两项是各家 exporter 都暴露、且口径可比的指标；SM 活跃度 / Tensor Core 活跃度属于 NVIDIA 专有概念（昇腾对应 AI Core / Cube），字段不通用。
> **指标名与 PromQL 需按现场 exporter 实际暴露核实后再上线**（原型中为占位）。

#### 5.3.4 弹性伸缩

分区说明：**弹性伸缩最小单元是一个模型副本，通过调整模型副本数实现扩缩容。**

**① 常规模式**

说明「一般用于稳定负载，无需频繁扩缩容场景」。仅展示：模型副本数（必填）。

**② Serverless 模式**

说明「一般用于负载变化较大场景，根据请求情况自动扩缩容，无需人工干预」。

| 字段 | 说明 |
|---|---|
| 最小模型副本 / 最大模型副本 | 副本区间 |
| 缩容检测窗口 | 秒，默认 600，对应 Serve `downscale_delay_s` |
| 目标请求数 | 默认 10.0，每副本同时处理请求数的目标值 |
| 最大请求数 | 默认 20.0，每副本最多处理的请求数 |

**③ 指标模式（核心能力）**

页面结构与 Serverless 同构，取消「缩容条件」，由**伸缩条件 + 缩容检测窗口**共同表达扩缩语义。

**指标来源：内置指标（默认）**

| 字段 | 规则 |
|---|---|
| 算力型号 | 只读标签，值取自「算力规格」选中行 |
| 伸缩条件 | 条件列表，默认 1 条、最多 3 条。每条 =「指标 + ≥ + 阈值」；行尾为垃圾桶图标按钮（hover 红底红边，title「删除该条件」，2 条及以上才显示） |
| 条件关系 | 2 条及以上时出现，位于「+ 添加条件」下方，**必填**，选项为「且 / 或」 |
| 聚合方式 | **必填**，选项为 平均值 / 最大值 / 求和（不显示英文后缀），自定义下拉面板 |
| 最小模型副本数 | 必填，ⓘ「服务空闲时仍保留的最小副本数，确保始终有实例可用，避免请求到达时等待冷启动」；**校验不得为 0**（红字「最小模型副本数不能为 0（算力资源冷启动需数分钟，至少保留 1 个副本）」） |
| 最大模型副本数 | 必填，三种动态提示：默认「负载高峰时允许扩展到的最多副本数，用于应对流量尖峰，同时限制算力占用上限」；最小 = 最大时「最大与最小相等：副本数固定，等同于常规模式（无弹性）」；最小 > 最大时红字「最大模型副本数不能小于最小模型副本数」 |
| 缩容检测窗口 | 必填，秒，ⓘ「指标回落后继续观察的时长，确认负载确实下降而非短暂波动后再缩容，避免频繁伸缩」 |

伸缩条件提示文案（场景化，随关系变化）：
- 且：**同时满足上述条件时，允许服务扩展到最大副本数以应对高峰；条件长时间不满足时，回落至最小副本数并释放算力资源**
- 或：**满足任一条上述条件时，允许服务扩展到最大副本数以应对高峰；条件长时间不满足时，回落至最小副本数并释放算力资源**

**指标来源：自定义 PromQL**

| 字段 | 规则 |
|---|---|
| 指标表达式 | 必填，单行输入 + 指标名联想（下拉左侧指标名、右侧含义，按输入尾串过滤）+ 清空按钮 |
| 语义 | 用户写**完整判断条件（含比较）**，返回 1 表示触发扩容、0 表示不触发；**因此自定义模式下不显示扩容 / 缩容阈值** |
| 提示 | 「例如：显存占用超过 85% 时扩容 —— `avg(gpu.memory.used{namespace="$namespace"}) / avg(gpu.memory.total{namespace="$namespace"}) > 0.85`」 |
| 其余字段 | 最小 / 最大模型副本数、缩容检测窗口（同内置模式） |

**模式限制**

- 推理框架 = KTransformer 时，Serverless 与指标模式**置灰不可点**，说明改为「KTransformer 暂不支持 Serverless 与指标模式，仅支持常规模式（固定副本）」；由 vLLM 切换到 KTransformer 时自动回落到常规模式

| 操作 | 规则 |
|---|---|
| 启动 / 停止 | 运行中显示「停止」，已关机显示「启动」；切换后卡片状态徽标与容器副本联动（停止 → 已关机 + `0/0`；启动 → 运行中 + 回落到最小副本数） |
| 删除 | 弹出居中确认弹窗：遮罩 `rgba(0,0,0,0.45)`、面板 600px；标题「删除」+ 右上 ×；正文橙色圆形感叹号 + 「是否确定删除内部推理服务 **服务名称(服务ID)** ？」（名称与 ID 为蓝色）；底部「取 消」/「确 定」。确认后从列表移除并清理弹性配置 |

## 6. 校验规则汇总

| # | 场景 | 规则 | 提示 |
|---|---|---|---|
| 1 | 服务名称 | 非空 | 红框 + 「请输入服务名称」 |
| 2 | 算力规格 | 指标模式下必选 | 「指标模式需先选择算力规格」 |
| 3 | 最小模型副本数 | ≥ 1 | 「最小模型副本数不能为 0（算力资源冷启动需数分钟，至少保留 1 个副本）」 |
| 4 | 副本区间 | 最小 ≤ 最大（**允许相等**，等于固定副本） | 相等时灰色提示「等同于常规模式（无弹性）」；倒置时红字「最大模型副本数不能小于最小模型副本数」 |
| 5 | 伸缩条件 | 至少 1 条，最多 3 条 | 超过 3 条隐藏「+ 添加条件」 |
| 6 | 条件关系 | 2 条及以上时必填 | 下拉默认「且」 |
| 7 | 聚合方式 | 必填 | 默认「平均值」 |
| 8 | 自定义表达式 | 必须返回单个数值 | 后端预检（见 6.1）；前端仅做非空约束 |
| 9 | 框架限制 | KTransformer 仅常规模式 | 置灰 + title 提示 |

**6.1 指标表达式预检（后端能力，页面不展示「试算」）**

| 项目 | 说明 |
|---|---|
| 背景 | 手写 PromQL 易出现多 series / 语法错误 / 查询过重，若等 KEDA 轮询才暴露，扩缩容会长时间失效 |
| 方案 | 保存前由后端调 Prometheus 预检，**不在创建流程暴露调试按钮** |
| 预检项 | ① `/api/v1/query` 可执行 ② `result.length === 1` ③ 返回值可转数值 ④ 查询耗时低于阈值 |
| 失败处理 | 拦截保存并说明原因（如「返回 3 个序列，请用 sum()/avg() 聚合」），不写入 CR |
| 联想数据源 | `/api/v1/label/__name__/values` + `/api/v1/metadata`，后端缓存 5 分钟；Prometheus 不可达时降级为纯手写 |

## 7. 状态流转与数据闭环

```
创建（填表 → 校验 → 提交）
   ↓
列表卡片（运行中 · 容器副本 1/1 · 弹性模式 · 模型副本 1–4）
   ↓ 点卡片
详情（弹性伸缩：伸缩条件 · 且/或 · 聚合方式 · 最小/最大副本 · 缩容检测窗口）
   ↓ 编辑
编辑（预填；框架 / 模型 / 服务模型名称锁定）
   ↓ 确定 → 回到详情（数据已更新）
列表卡片同步（名称 · 弹性模式 · 模型副本）
   ↑
启停 / 删除 → 卡片状态实时变化，详情跟随
```

| 流转 | 数据变化 |
|---|---|
| 创建提交 | 新增服务记录 + 弹性配置；卡片状态「运行中」，副本 `min/min` |
| 编辑提交 | 更新服务字段与弹性配置，列表与详情同步 |
| 停止 | 状态「已关机」，容器副本 `0/0` |
| 启动 | 状态「运行中」，容器副本回落到最小副本数 |
| 删除 | 移除服务与弹性配置；若删除全部服务，进详情有兜底守卫 |

## 8. 异常与边界

| 场景 | 处理 |
|---|---|
| 未选算力规格就选指标模式 | 指标下拉显示「暂无内置指标」，提交拦截 |
| 编辑历史数据的模型不在下拉选项内 | 保持原模型值，避免保存时被改写 |
| KTransformer + 历史弹性配置 | 创建/编辑页强制常规模式 |
| Prometheus 不可达 | 指标联想降级为纯手写；KEDA 侧走 fallback 副本数 |
| 自定义表达式返回多 series | 预检拦截，不写入 CR |
| 列表为空 | 展示「暂无数据」；进详情有守卫不崩溃 |

## 附录 B：PromQL 示例

```promql
# 单指标：GPU 利用率 > 80%
avg(DCGM_FI_DEV_GPU_UTIL{namespace="$namespace"}) > 80

# 显存占用率
avg(DCGM_FI_DEV_FB_USED{namespace="$namespace"})
  / avg(DCGM_FI_DEV_FB_TOTAL{namespace="$namespace"}) > 0.85

# 组合：利用率高 且 排队多
(avg(DCGM_FI_DEV_GPU_UTIL{namespace="$namespace"}) > 80)
  and (sum(ray_serve_deployment_queued_queries{namespace="$namespace"}) > 10)

# 多厂商（昇腾）
avg(npu_chip_info_utilization{namespace="$namespace"}) > 80
```

## 附录 C：术语

| 术语 | 说明 |
|---|---|
| 模型副本 | 一个可独立处理请求的服务实例，弹性伸缩的最小单元 |
| 伸缩条件 | 指标 + 比较 + 阈值，满足时放开副本上限 |
| 缩容检测窗口 | 条件持续不满足多久后，才收窄副本上限 |
| 副本范围 | `[最小模型副本数, 最大模型副本数]`，KEDA 调整的对象 |
| 聚合方式 | 对指标序列取平均 / 最大 / 求和，使表达式收敛为单值 |
