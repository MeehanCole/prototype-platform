# Agent / Subagent 架构调研（智能诊断参考）

> 状态：**待确认**（调研完成，供评审）
> 背景：确定智能诊断平台后台 Agent 架构——subagent 采用「动态创建」还是「预置分派」，参考 DeerFlow / 蚂蚁系框架 / Claude Code 等业界实践
> 关联：告警诊断 + 常驻对话共用统一入口 Agent 的架构决策

## 1. 调研范围与结论摘要

| 框架/产品 | 归属 | Subagent 模式 | 关键机制 |
|-----------|------|--------------|---------|
| **DeerFlow 2.0** | 字节开源 | **动态创建** | 主 Agent 通过内置 `task_tool` **即时生成** subagent：每个独立上下文窗口 + 工具集 + 终止条件，后台线程池**并行执行**，结果汇总回主 Agent 合成输出 |
| **Claude Code Subagents** | Anthropic | **预置 + 自动分派** | 创建一系列拥有特定"专长"的子代理（预置定义），Claude 遇到任务时**自动或按指令分派**给最合适的子代理；子代理只能向主 Agent 汇报，不直接互相通信 |
| **LangGraph** | LangChain | **两者皆可** | 基于图结构的状态化编排：主流是"预置节点 + 状态流转"；也支持 `create_agent` 工厂**动态创建** agent/子图实例 |
| **AutoGen** | Microsoft | **预置角色 + 对话** | GroupChat 中 agent 是预定义角色集合（UserProxy/Assistant），类可动态实例化，agent 间对话协作 |
| **CrewAI** | CrewAI | **预置团队** | Crew（团队）预定义 agent 角色/目标/工具，流程编排（顺序/层级），模拟团队协作 |
| **MetaGPT** | 国内开源 | **预置 SOP 角色** | 产品经理/架构师/工程师等预定义角色，标准作业程序（SOP）流水线 |
| **蚂蚁 AIEvo** | 蚂蚁开源 | **多智能体协作** | 基于大规模**线上告警问题诊断**与专家经验平台化实践，专注告警诊断场景的多智能体协作 |
| **蚂蚁 muAgent / agentUniverse** | 蚂蚁开源 | **SOP 编排** | 简化多 Agent 标准操作程序编排 / 多智能体协作编排组件 |

> 注：用户提到的 **PiAgent** 未检索到权威资料（可能为较小众或名称差异）；蚂蚁系多智能体框架已调研替代，其中 **AIEvo 与告警诊断场景直接相关**。

## 2. 模式本质分析

### 2.1 两派对比

| 维度 | 动态创建派（DeerFlow 式） | 预置分派派（Claude Code 式） |
|------|--------------------------|------------------------------|
| Subagent 来源 | 主 Agent 计划里**定义并生成**实例 | **提前定义**注册，主 Agent **挑选分派** |
| 能力边界 | 主 Agent 即时规划（依赖 prompt 质量） | 预置定义清晰（可控、可审计） |
| 灵活性 | 高——任务多样开放时自适应 | 中——仅覆盖预置专长 |
| 稳定性 | 低——能力取决于主 Agent 规划 | 高——行为可预期 |
| 适合场景 | 开放/研究类任务（如 DeerFlow 研究助手） | 边界清晰的垂直任务（代码巡检、告警诊断） |
| 上下文 | 每个 subagent 独立窗口，主上下文不被中间过程塞满 | 同左（两派都隔离上下文） |

### 2.2 共识点（两派一致）

- **上下文隔离**：subagent 独立上下文窗口，主 Agent 上下文不被中间探索过程塞满
- **结果压缩**：subagent 只回传结构化摘要/结论，不回流原始过程
- **并行执行**：多个 subagent 可并行运行，提升效率
- **单向汇报**：subagent 向主 Agent 汇报，多级通信增加复杂度（Claude Code 明确限制子代理间不直接通信）

## 3. 对智能诊断平台的架构建议

### 3.1 场景拆解（两个入口，一个 Agent）

| 入口 | 任务形态 | 适合模式 |
|------|---------|---------|
| 告警诊断 | **边界清晰**：日志/指标/APM/根因，流程固定 | **预置专长 subagent + 主 Agent 自动分派**（Claude Code 式） |
| 常驻对话 | **开放**：任意问题，意图未知 | **动态创建 subagent**（DeerFlow 式），按意图即兴编排 |

### 3.2 推荐方案（已确认）：Skill 为能力 + Subagent 为执行载体

**预置的是 Skill（能力定义），不是固定 Subagent；Subagent 由主 Agent 动态派发执行。**

```
用户 → 主 Agent（统一入口，意图识别 / 制定计划 / 选择 skill / 汇总）
   │ 为每个任务动态派发 subagent（执行载体，临时创建）
   ├─▶ subagent 执行「日志分析 skill」（调日志工具）
   ├─▶ subagent 执行「指标分析 skill」（调指标工具）
   ├─▶ subagent 执行「APM 链路分析 skill」（调 SkyWalking）
   ├─▶ subagent 执行「根因推理 skill」
   └─▶ subagent 执行「处置执行 skill」（受执行授权控制）
   │ 各 subagent 回报结构化结果
   ▼ 主 Agent 汇总 → 根因 → 处置建议
```

- **Skill = 能力定义**：日志分析 / 指标分析 / APM 链路 / 根因推理 / 处置执行均为预置 Skill（SKILL.md 文件，不绑定模型，文件存在即生效，与平台既有 Skill 体系一致）
- **Subagent = 执行载体**：主 Agent 按诊断计划动态派发，持有对应 skill + 工具去执行，独立上下文、结果压缩回报；不预置固定 subagent 角色
- **主 Agent = 编排者**：意图识别 → 制定计划 → 选择 skill → 派发 subagent → 汇总结论
- **Skill 可复用**：诊断 / 巡检 / 常驻对话均可按需调用同一批 skill，避免重复实现

> 该方案与平台既有约束一致：技能不绑定模型、无触发方式/来源/状态标签；Agent 绑定 skill 与工具。

### 3.3 对当前原型的影响

- 无代码改动：诊断面板的「诊断计划 → 工具卡片 → 思考 → 根因 → 建议」即为主 Agent 编排 subagent 的可视化
- 工具卡片（日志/指标/APM/告警关联）对应主 Agent 派发的 skill 执行任务

## 4. 决策记录（已确认）

- [x] **架构**：主 Agent（统一入口，不区分场景）＋ 预置 Skill（能力）＋ 动态派发 Subagent（执行载体）
- [x] **预置 Skill 名单**：日志分析 / 指标分析 / APM 链路 / 根因推理 / 处置执行（5 类能力）
- [x] **Subagent 不预置**：由主 Agent 按计划临时派发执行，回报后回收
