# 智能诊断平台 - 需求清单

## 1. 项目背景

现有 Electron 桌面端客户端 + Python+LangGraph 服务端实现的智能诊断系统，需要迁移到 Web 平台，并与容器云平台（类似于KubeSphere（而不是kubesphere）、算力加速平台（这个只是使用的技术-Hami+Ray+Queue）和底座（OIDC）深度集成。

## 2. 目标用户

| 角色 | 职责 | 核心诉求 |
|------|------|----------|
| 运维人员 | K8s 集群、数据库、网络等基础设施的日常运维和故障排查 | 快速诊断问题、查看告警、执行巡检 |
| 平台管理员 | 系统配置、用户权限管理、资源调度 | 全局管理、审计、资源配额 |

## 3. 核心目标

将 Electron 桌面端诊断功能迁移到 Web 平台，实现：
- 统一 Web 入口，无需安装客户端
- 与容器云进行集成，实现容器云相关资源的智能化
- 与 底座OIDC 集成（统一用户权限认证和资源隔离）
- 与算力加速平台集成，实现算力资源的智能化处理
- 多角色、多租户支持

## 5. 非功能需求

### 5.1 技术约束
- 前端：Vite + Tailwind v4 + Shadcn UI
- 认证： OIDC 统一认证
- 后端：Python + LangGraph（现有服务容器化部署）
- 平台已经是拥有产品，相关功能已就位

### 5.2 性能要求
- 页面加载时间 < 2s
- 对话响应流式展示，首字延迟 < 500ms
- 支持并发 50+ 用户同时对话

### 5.3 安全要求
- OIDC 统一认证
- 角色权限控制（RBAC）
- 操作审计日志

## 6. 平台集成架构

### 6.1 集成原则

平台（容器云、算力加速平台、底座）已具备完整的功能（告警、巡检、资源监控、认证权限等），**智能诊断助手不重复实现这些功能**，而是通过 AI 对话与现有平台能力进行智能化联动。

### 6.2 集成方式

| 平台能力 | 现有功能（已就位） | 诊断助手联动方式 |
|----------|------------------|----------------|
| 容器云平台 | 资源管理、集群管理、租户管理 | 通过 MCP 工具查询资源状态、诊断故障 |
| 告警中心 | 事件告警、指标告警、日志告警 | 对话式查询告警、AI 分析根因定位 |
| 平台巡检 | 巡检计划、规则、结果 | 对话式触发巡检、AI 解读巡检结果 |
| 算力加速平台 | Hami+Ray+Queue 异构算力调度 | 查询 GPU 资源状态、AI 推荐算力分配 |
| 底座 OIDC | 统一认证、权限管理 | 继承用户身份和权限，资源隔离 |

### 6.3 数据流

```
用户触发方式：
  ├─ 对话触发（用户在智能对话中发起）
  ├─ 定时触发（周期性自动执行巡检等）
  └─ 事件触发（告警事件自动触发对应诊断 Skill）

数据流：
用户 → 智能对话/Auto-trigger → Skill → MCP 工具 → 平台现有 API
                                                    ↓
                                         容器云/告警/巡检/算力平台
```
