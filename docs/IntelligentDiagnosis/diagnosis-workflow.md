# 智能诊断交互规范（Diagnosis Workflow）

> 约束「告警 / 故障智能诊断」交互的实现流程。任何智能诊断场景（告警中心诊断面板、巡检异常、对话式诊断）均按本规范执行。
> 依据：业界 AIOps 智能告警诊断实践（Datadog / Dynatrace / Moogsoft / 腾讯云智维 / 多智能体协作等）调研结论。
> 核心原则：**结论先行 + 证据可追溯；关联信息自动聚合；可追问可迭代；可处置闭环**。

## 1. 五阶段诊断流程（强约束）

```
触发：告警/故障入口（如告警行「智能诊断」）→ 打开诊断面板，预填上下文（策略/级别/目标/时间/消息）
   │
   ▼ ① 上下文确认 + 诊断计划（秒级）
AI 复述已获取的上下文，标记「已获取告警上下文」；
同时展示「诊断计划」清单（Agent 式，执行前可见）：
   1. 查询相关日志与指标
   2. 分析服务调用链路（APM）
   3. 关联相似告警，收敛故障事件
   4. 定位根因并给出处置建议
   │
   ▼ ② 工具查询（模拟 1~2s，逐条出现）
按计划依次执行工具调用，每个工具展示为「工具卡片」：
   - 工具名 + 查询参数（时间窗/目标范围）
   - 结果**汇总**（如"命中 ERROR 42 条"、"内存 87%→92% 上升"）
   - 点击**展开查看原始内容**（日志片段/指标数据，可追溯）
   - **执行载体链**：主 Agent 动态派发 Subagent → 调用 Skill（见 §2.1 工具卡片规范）
   │
   ▼ ③ 诊断结论（先思考，后结论）
先折叠展示「AI 思考过程」（CoT，点击展开，灰色块，不打断主流程）；
再给出「诊断结论」+ 置信度（高/中/低）+ 推理依据证据链
   │
   ▼ ④ 处置建议
按优先级列出修复步骤（1/2/3）+ 操作按钮（见 §3 处置区规范）
   │
   ▼ ⑤ 对话追问（可迭代）
用户可继续提问（"最近有变更吗？""影响范围多大？"），AI 基于上下文继续回答
```

- 阶段按顺序推进，**每条阶段结果逐条流式出现**（不可一次性全量渲染）
- 任一阶段失败 → 进入失败态，提供「重新诊断」（见 §4 状态机）

## 2. 面板 UI 结构规范

| 区域 | 内容 |
|------|------|
| 头部 | 诊断对象摘要（策略 + 级别 + 目标 + 时间）+ 诊断状态徽标（诊断中 / 完成 / 失败）+ 历史对话入口 |
| 主体 | **对话消息流**（与智能对话一致）：用户请求气泡（人像图标）→ AI 消息序列（Bot 图标），每条 AI 消息为一个气泡：AI 思考（折叠）→ 诊断计划 → 工具调用 → AI 思考（折叠）→ 诊断结论 → 处理建议 |
| 消息内容 | 思考=灰色折叠块（CoT）；计划=编号清单；工具=工具卡片（名称+参数+汇总+可展开原始）；结论=诊断结论+置信度+证据链；建议=步骤（可执行项带「执行」按钮） |
| 处置区 | 处置步骤 + 按钮（见 §3） |
| 输入区 | 追问输入框（Enter 发送），底部固定 |
| 宽度 | 默认 560px，支持左边缘拖动调整（400~720px） |

### 2.1 工具卡片规范（Subagent 执行载体链）

每个工具卡片须体现「执行载体 + 能力定义」，与后台架构（主 Agent + 预置 Skill + 动态派发 Subagent）一致：

- 卡片头部：工具名 + 查询参数 + 结果汇总 + **执行状态**（`执行中` → `完成`，模拟耗时 0.6s 内切换，加载动画 + 勾选反馈）
- 卡片主体（常驻一行）：**执行载体链** `[subagent 图标] 派发的 Subagent → [skill 图标] 调用的 Skill`
  - 示例：`日志分析 Subagent → log-analysis skill`；`指标分析 Subagent → metric-analysis skill`
  - Skill 命名统一英文短横线（log-analysis / metric-analysis / apm-trace / alert-correlation），与平台 Skill 体系一致
- 点击展开：原始查询结果（日志片段/指标数据），可追溯
- 工具卡片可内嵌**可视化图表**（内联 SVG 手绘，不引第三方图表库）：
  - `指标监控` → 指标趋势折线图（面积 + 折线 + 85% 阈值虚线，末点标红）
  - `SkyWalking APM` → 调用链路拓扑图（节点 + 连线 + 箭头，异常链路标红 + 耗时标注）
  - `性能剖析` → CPU 火焰图（多层栈，宽度 = 采样占比，hover title 显示函数名 + 占比）
- 工具调用区标题下方为 **AI 输出交互语言**（非架构说明），示例：`我将调用多个 Subagent 并行进行深度诊断（日志分析 / 指标分析 / APM 链路 / 告警关联），请稍候...`
- 工具卡片映射（预置 Skill 名单见 Agent架构调研 §3.2）：日志查询→日志分析 Subagent；指标监控→指标分析 Subagent；SkyWalking APM→APM 链路 Subagent；告警关联→根因推理 Subagent

### 2.2 AI 思考文案（Subagent 回报聚合）

二次「AI 思考」折叠块内容须体现**回收 Subagent 结构化回报**的聚合过程，格式：

```
已回收各 Subagent 的结构化回报：
1. 日志分析 Subagent（log-analysis skill）：<日志结论>
2. 指标分析 Subagent（metric-analysis skill）：<指标结论>
3. APM 链路 Subagent（apm-trace skill）：<链路结论>
4. 根因推理 Subagent（alert-correlation skill）：<关联结论>
综合判断：<根因倾向>
```

## 3. 处置区规范

- 架构前提：**主 Agent（统一入口，不区分场景）+ 预置 Skill（能力）+ 动态派发 Subagent（执行载体）**
  - 日志分析 / 指标分析 / APM 链路 / 根因推理 / 处置执行均为**预置 Skill**（SKILL.md，不绑定模型）
  - 主 Agent 按诊断计划**动态派发 subagent** 执行对应 skill，subagent 独立上下文、结果压缩回报，不预置固定 subagent 角色
- 「**执行**」按钮：**仅当后台 Agent 具备执行能力时展示**（可执行项才有）。点击后展示模拟反馈「已提交执行」
- **无可执行 Agent 时**：不展示执行按钮，展示提示条「**当前无可执行智能体，请联系平台管理员**」（黄色警示样式）
- 「**重新诊断**」：**必选**（失败重试 / 重新分析）。点击后重置步骤重新执行完整流程
- 「**创建工单 / 一键处置 / 自动执行**」：**默认不放**。按产品实际能力决定：
  - 产品无工单/处置体系时**不提供**（原型当前如此）
  - 有工单能力时仅提供「创建工单」并展示模拟反馈，不真实提交
  - 一键执行类操作真实平台高危，禁止在原型中误导展示；由真实流程承载
- 处置建议步骤 1/2/3 按优先级列出，来自根因结论，非泛化文案

## 3.1 双入口共享组件（强约束）

所有智能诊断场景统一复用 `DiagnosisDialog.tsx` 共享组件（右侧抽屉，样式/流程/历史/可视化一致），**禁止各入口各自实现**。

| 入口 | 模式 | 触发行为 |
|------|------|---------|
| **告警中心**（告警行「智能诊断」） | `alert`（预填模式） | 点击 → 注入告警上下文（DiagSubject）→ 直接进入五阶段诊断 |
| **常驻对话**（右下浮动按钮） | `scene`（场景模式） | 点击 → 空态展示**场景卡片**（6 个固定场景：容器故障/日志异常/性能剖析/数据库慢查询/网络排障/集群健康巡检）+ 手动输入 → 用户点击或输入后进入五阶段诊断 |

- **场景卡片**：固定 6 个（`DIAG_SCENES`），每个场景构造预置的 DiagSubject（含策略/目标/消息），点击即以该主题发起诊断；手动输入走「通用诊断」主题
- **智能巡检**：复用平台已创建的巡检计划，不重复实现定时调度。场景卡「集群健康巡检」→ 主 Agent 派发「巡检执行 Subagent」执行 `inspection-run skill`（运行巡检计划）+ `health-check skill`（健康状态采集）+ `report-analysis skill`（巡检结果分析），返回健康结论与异常解读
- **历史记录**：双入口共用同一 localStorage key（`aiops.diagHistory`，最近 20 条），可还原完成态
- **诊断主题抽象**：`DiagSubject`（no/policy/level/target/project/time/message）统一告警行、场景、手动输入三种来源，工具结果/思考/结论均基于它生成
- 场景模式下处理建议区提供「**换个场景**」按钮，可返回场景选择页

## 4. 状态机

```
诊断中（消息流推进：思考 → 计划 → 工具调用 → 思考 → 根因 → 建议，每条 AI 消息逐条流式出现）
   │
   ├─ 全部完成 → 完成态（全部消息齐全 + 可追问 + 可执行项按钮可用）
   ├─ 步骤失败（模拟可触发）→ 失败态（提示失败原因 + 「重新诊断」）
   └─ 用户追问 → 追加对话消息，不重置诊断状态
```

## 5. 实现要点

- 诊断面板为**右侧抽屉**（fixed right-0 全高），遮罩点击 / Esc / X 均可关闭，关闭不持久化状态
- 阶段推进用 `setTimeout` 序列模拟（每步 0.8~1.2s），`useEffect` 按 step 推进，卸载时清理定时器
- **工具查询两层展示**：卡片外层 = 工具名 + 参数 + 结果汇总；内层点击展开 = 原始内容（日志/指标/链路片段），默认折叠
- **思考过程（CoT）折叠**：点击展开灰色块展示，不占主视觉、不打断结论阅读
- **诊断计划**：诊断开始（①阶段）先展示计划清单，随后按计划执行工具调用
- 证据链必须**可展开**（指标 / 日志 / 关联告警），结论不得无依据
- 置信度三档：高 / 中 / 低（颜色区分：绿 / 橙 / 红）
- **历史导出**：历史列表每条提供「导出报告」，将单条诊断生成 Markdown（主题/时间/结论/证据链/处理建议）下载，供复盘 / 工单粘贴
- 常驻对话与告警中心**统一复用共享组件** `DiagnosisDialog.tsx`（见 §3.1），互不阻塞，各自独立开关
- 组件位置：`DiagnosisDialog.tsx`（共享）+ `AlertCenter/index.tsx`（告警中心页）+ `_shared.tsx`（常驻入口），不做全局单例
