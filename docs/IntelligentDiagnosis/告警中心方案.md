## 8. 智能诊断交互过程设计（调研自业界 AIOps 实践）

### 8.1 业界调研结论

业界 AIOps 智能告警诊断（Datadog / Dynatrace / Moogsoft / 腾讯云智维 / 多智能体协作系统等）的通用链路与共识：

1. **上下文采集**：单条告警触发诊断时，自动聚合关联数据（告警消息、时间窗口内指标、相关日志、拓扑、变更记录）
2. **告警关联 / 降噪**：相似告警聚类，同窗口告警收敛为「故障事件」，指出根源，降低认知负荷
3. **根因推理（RCA）**：基于服务拓扑 + 因果推断 / 大模型推理定位最根本原因，而非表面现象
4. **证据链呈现**：展示推理依据（指标曲线 / 日志片段 / 关联告警），结论可信、可追溯，不做黑盒
5. **处置建议 + 闭环**：给出修复步骤 / Runbook / 一键操作（创建工单、执行脚本），跟踪解决状态并沉淀复盘

> **"好的诊断过程"标准**：结论先行 + 证据可追溯；关联信息自动聚合（不要求用户跳转查日志/指标）；可追问可迭代；可处置闭环。

### 8.2 诊断交互过程（五阶段）

```
触发：告警行「智能诊断」→ 面板打开，预填告警上下文（策略/级别/目标/时间/消息）
   │
   ▼ ① 上下文确认（秒级）
AI 复述已获取的告警上下文（策略、级别、监控目标、激活时间、告警消息摘要），
并标记「已获取告警上下文」，确认输入完整后进入分析
   │
   ▼ ② 关联分析（模拟 1~2s）
自动拉取并展示分析依据来源：
   - 相关日志片段（近 30 分钟，命中关键词）
   - 指标趋势（监控目标近 1 小时 CPU/内存/连接数 简要）
   - 相似告警 / 关联告警（同目标或同策略最近触发）
   │
   ▼ ③ 根因定位
给出「最可能的根因」结论 + 置信度（高/中/低）+ 推理依据证据链：
   - 结论：如 "节点 node-10.10.60.62 内存压力导致 Pod 被驱逐"
   - 证据：指标超限曲线 / 日志报错片段 / 时间线对齐
   │
   ▼ ④ 处置建议
按优先级列出修复步骤（1/2/3），提供操作按钮：
   - 「创建工单」/「一键处置」（模拟） /「重新诊断」
   │
   ▼ ⑤ 对话追问（可迭代）
用户可继续提问（"最近有变更吗？""影响范围多大？"），AI 基于告警上下文继续回答
```

### 8.3 诊断面板 UI 结构

| 区域 | 内容 |
|------|------|
| 头部 | 告警摘要（策略 + 级别 + 目标 + 时间）+ 诊断状态徽标（诊断中 / 完成 / 失败） |
| 诊断进度 | 四步指示器：采集上下文 → 关联分析 → 根因定位 → 处置建议（当前步骤高亮） |
| 诊断结论卡 | 根因结论 + 置信度 + 证据链（点击展开指标/日志/关联告警） |
| 对话流 | 预填「诊断请求」用户消息 + AI 分阶段回复（结论/证据/建议）；用户追问消息 |
| 处置区 | 处置建议步骤 + 「创建工单」/「重新诊断」按钮 |
| 输入区 | 追问输入框（Enter 发送），底部固定 |

### 8.4 状态机

```
诊断中（阶段推进：上下文确认 → 关联分析 → 根因定位 → 处置建议，逐条流式出现）
   │
   ├─ 全部阶段完成 → 完成态（结论卡 + 证据 + 建议 + 可追问）
   └─ 失败（模拟可触发）→ 失败态（提示重试「重新诊断」按钮）
```
