# 智能诊断平台 - 方案设计文档

## 方案概述

### 定位
在现有容器云平台（KubeSphere + OIDC）基础上，增加一个 AI 智能诊断助手模块，通过对话方式联动现有平台能力（告警、巡检、资源监控、算力调度等）。

### 核心设计思想
- **不重复实现**现有平台功能，只做智能化联动
- 诊断助手作为**子应用**嵌入平台，保持平台导航一致性
- 管理面（模型/工具/技能）放在平台导航分类中
- 对话面提供**全局浮动入口**，随时可发起诊断

### 平台现有布局参考
- 平台使用 **Element Plus** 设计风格
- 全局导航左侧包含各功能模块分类
- 全局导航右侧有全局操作入口
- 智能诊断助手作为独立子应用嵌入

## 候选方案 1：全局导航分类 + 浮动对话入口（推荐）

### 架构

```
平台全局导航（左侧）：
├─ 智算服务
├─ 容器云
├─ CICD
├─ 运维中心
├─ 告警中心
├─ 交付中心
├─ 运营中心
├─ 多云管理
├─ 中间件
├─ 平台巡检
├─ AIOps（新分类）
│  ├─ 模型管理
│  ├─ 工具管理
│  ├─ 技能管理
│  └─ （对话统一走应用面常驻入口，管理面无独立对话页）

平台全局导航（右侧）：
├─ [🤖 智能诊断]（浮动按钮，快速唤起对话抽屉）

浮动对话面板（从右侧滑出，抽屉式）：
├─ 对话列表（左侧窄栏）
├─ 对话窗口（主区域）
│  ├─ 消息流
│  ├─ 模型信息（顶部只读，展示默认模型）
│  └─ 输入区（底部，支持附件/截图/语音）
├─ 工具调用可视化（消息内嵌）
```

### 交互流程

```
场景：用户发现集群告警

1. 用户点击右侧浮动按钮「🤖 智能诊断」
2. 对话面板从右侧滑出（覆盖在内容区上方，类似抽屉）
3. 用户输入："查看最近1小时的告警"
4. 助手调用 MCP 工具 → 查询告警中心 API → 返回告警列表
5. 用户继续："分析根因"
6. 助手调用诊断 Skill → 分析日志/指标 → 输出根因分析结果
7. 用户如需调整配置 → 点击面板中的「模型管理」链接 → 跳转到管理页面（导航切换）
8. 对话面板保持状态，用户调整完配置后可继续对话
```

### 页面路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/intelligentdiagnosis/modelmanagement` | 模型管理 | 管理面，含默认模型设置 |
| `/intelligentdiagnosis/toolmanagement` | 工具管理 | 管理面，MCP 工具注册与配置 |
| `/intelligentdiagnosis/skillmanagement` | 技能管理 | 管理面，诊断 Skill 编排与配置 |

> 对话面板（浮动抽屉）是全局组件，通过右侧浮动按钮触发，是应用面唯一的对话入口（管理面无独立对话页）

### 特点

| 维度 | 说明 |
|------|------|
| **用户体验** | 对话不打断当前操作，随时可发起诊断；管理面在导航中统一管理 |
| **平台一致性** | 管理面以分类形式融入平台导航，符合平台现有布局习惯 |
| **开发成本** | 中等，需要开发浮动对话面板组件（类似抽屉） |
| **风险** | 对话面板状态管理需注意（切换页面时保持对话状态） |
| **扩展性** | 新增管理功能直接加导航项；新增诊断场景通过 Skill 扩展 |

## 候选方案 2：独立子应用页面（对话 + 管理统一入口）

### 架构

```
平台全局导航（左侧）：
├─ 首页
├─ 资源管理
├─ 监控告警
├─ 平台巡检
├─ 算力调度
├─ 智能诊断（新一级模块，子应用入口）
│  ├─ 模型管理
│  ├─ 工具管理
│  └─ 技能管理
```

### 交互流程

```
场景：用户发现集群告警

1. 用户点击右侧浮动按钮「🤖 智能诊断」
2. 对话面板从右侧滑出（覆盖在内容区上方，类似抽屉）
3. 用户输入："查看集群健康状态"
4. 助手调用巡检 Skill → 运行已创建的巡检计划 → 返回健康状态
5. 用户继续："分析根因"
6. 助手调用诊断 Skill → 分析日志/指标 → 输出根因分析结果
7. 用户如需调整配置 → 切换到「模型管理」等管理子页面
8. 配置完成后 → 再次点击浮动按钮继续对话
```

### 页面路由

| 路由 | 页面 | 说明 |
|------|------|------|
| `/intelligentdiagnosis/modelmanagement` | 模型管理（默认入口） | 管理面，含默认模型设置 |
| `/intelligentdiagnosis/toolmanagement` | 工具管理 | 管理面 |
| `/intelligentdiagnosis/skillmanagement` | 技能管理 | 管理面 |

### 特点

| 维度 | 说明 |
|------|------|
| **用户体验** | 对话区域大，适合深度诊断场景；管理面切换页面 |
| **平台一致性** | 以一级模块融入平台导航，符合现有导航习惯 |
| **开发成本** | 低，直接复用现有页面框架 |
| **风险** | 诊断过程中切换管理页面会丢失对话上下文 |
| **扩展性** | 线性扩展，新增功能直接加子导航项 |

## 方案对比

| 对比维度 | 方案 1（浮动对话入口） | 方案 2（独立子应用） |
|----------|----------------------|---------------------|
| **对话体验** | ⭐ 不打断当前操作，随时发起 | ⭐ 全屏对话，沉浸式体验 |
| **管理面入口** | ⭐ 导航分类「智能」统一管理 | ⭐ 导航一级模块「智能诊断」 |
| **平台融合度** | ⭐ 更好，管理面融入平台分类 | ⚠️ 作为一个独立模块 |
| **开发成本** | ⭐ 中等（浮动面板组件） | ⭐ 低（复用页面框架） |
| **对话状态保持** | ✅ 面板始终保留状态 | ⚠️ 页面切换可能丢失状态 |
| **适合场景** | 日常运维中随时诊断 | 专注诊断分析场景 |
| **推荐** | ✅ **推荐**（更符合"子应用 + 浮动入口"的定位） | 可选 |

## 设计风格说明

### 设计输入
- 平台使用 **Element Plus** 设计风格
- 本项目原型使用 React + Shadcn UI + Tailwind v4 技术栈

### 风格处理策略
由于原型平台使用 React 技术栈，而实际平台使用 Element Plus（Vue），**原型阶段建议**：

**选项 A：还原 Element Plus 视觉风格**
- 提取 Element Plus 的核心设计 token（主色 #409EFF、圆角 4px、字号体系等）
- 在 Tailwind 中通过 CSS 变量映射这些 token
- 原型看起来接近实际平台风格

**选项 B：使用平台内置预设**
- 从平台内置的 5 种预设中选择（Prototype Default、Element Plus、Ant Design 5.x、Arco Design、Naive UI）
- 快速出原型，风格统一

## 决策记录

### ✅ 已确认决策

| 决策项 | 选择 | 说明 |
|--------|------|------|
| **页面架构方案** | 方案 1 | 全局导航「AIOps」分类 + 右侧浮动对话入口 |
| **分类名称** | AIOps | 替代原「智能」分类名 |
| **AIOps 分类内容** | 模型管理、工具管理、技能管理 | 管理面不含独立对话页，对话统一走应用面常驻入口 |
| **设计风格** | 选项 A：还原 Element Plus | 提取 Element Plus 核心设计 token 映射到 Tailwind |
| **对话面板交互** | 抽屉式 | 从右侧滑出，覆盖内容区，可调整宽度 |

### 选择理由
- 管理面以 **AIOps** 分类融入平台现有导航，与「智算服务」「容器云」「运维中心」等平级
- 对话面提供**单一入口**：右侧浮动按钮（抽屉式对话），管理面仅承载模型/工具/技能配置
- 设计风格还原平台使用的 **Element Plus**，保持视觉一致性
